# 示例 03 · 复刻对照（骨架不变，皮肉全换）

**用途**：演示「骨架 100% 复现 + 皮肉必须原创」到底改什么、不改什么。两张 token 表分别是雷同版与原创版，可直接跑脚本看判据。

## 判据先说清

| | 骨架 | 皮肉 |
|---|---|---|
| 包含 | 信息架构、DOM 结构、状态机、协议、注入链、交互、a11y | 三色、字体、质感、插画、文案、动效风格 |
| 要求 | 100% 复现：少一个节点、字段、状态都算没复现 | 必须原创：三色/字体/质感/主视觉有一项与示例相同即雷同 |

## 跑一遍

```bash
# 雷同版：主色与字体照搬示例 A
node scripts/check-skin.mjs --tokens examples/03-remix/tokens-before.json \
     --examples assets/skin/example-palettes.json
# 预期：4 条 ERROR（颜色全同）+ 2 条字体 ERROR → 结论「皮肉不够原创」

# 原创版：只保留明度关系，色相/质感/圆角/动效全换
node scripts/check-skin.mjs --tokens examples/03-remix/tokens-after.json \
     --examples assets/skin/example-palettes.json
# 预期：通过；可能残留 1 条「主文字色距离偏近」的 WARN，人工再看一眼灰模同构、彩模异质
```

## 换皮流程（不改骨架）

1. 从成品卡抽出 `tokens.json`（颜色 / 字体 / 质感 / 圆角 / 动效），只留这一层；
2. 骨架 CSS 只引用 token，不写死颜色——写死一处，换皮就漏一处；
3. 换 token 前先跑 `check-skin`，确认目标配色与示例的距离；
4. 换完重跑 `validate` + `preview`，确认没有因为换色引入 `--chat-*` 写死或未知变量；
5. 交付时同时给「骨架清单（复现项）」与「皮肉差异（原创项）」，别只给截图。

## 常见错误

| 错误 | 后果 |
|---|---|
| 只换主色，字体与质感照搬 | 判据里仍算雷同 |
| 把骨架 CSS 里的颜色改成变量但保留原 hex 兜底 | 换皮后残留旧配色 |
| 为了「看起来不一样」改 DOM 层级 | 骨架没复现，交互与协议一起坏 |
| 用随机数生成配色 | 不可复现，验收时无法复核 |

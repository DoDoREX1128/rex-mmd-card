# examples · 案例库

## 这里放什么

不是「样板卡」，是**「一句话 → 卡」的推演记录**。每份案例回答同一个问题：

> 作者大人只说了这一句，我凭什么这么定？

## 来源

| 来源 | 定位 | 取用方式 |
|---|---|---|
| **MMD角色卡制作** | 最准 | 平台事实、人设标签格式、状态真值、SDK 边界 —— 一律照它 |
| **洛璃版MMD角色卡制作** | 最佳 | 文风条目、绝对零度、八股清单、开场三要素 —— 一律照它 |
| 市面上的成品同层卡 | 版式参考 | 只取结构与界面手法，不搬内容、不留痕迹 |

**冲突时：技术听 MMD，文字听洛璃版，版式照 [41-界面-基线](../references/41-界面-基线.md)。** 三者不打架，因为它们管的不是同一层。

## 后续怎么加

作者大人给了满意的成品卡之后，按**同一个格式**补一份：一句话 → brief → 关键决策表 → 哪里可以不同。**不要贴整份 JSON**——整份 JSON 学不到东西，决策表才学得到。

新案例进来后，回头检查 [11-流程-一句话补全](../references/11-流程-一句话补全.md) 的默认值表有没有该改的。案例的作用是**修正默认值**，不是当摆设。

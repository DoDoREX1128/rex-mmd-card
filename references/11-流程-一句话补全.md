# 11 · 一句话补全

> 目标：作者只给一句话，也能产出一张**不需要返工**的卡。
> 「不返工」不是猜得准，而是三件事：每个推断都有出处；各维度互相咬合；不确定处给最不坏的选择。

---

## 1. 输入：一句话里能抽出什么

任何一句题材描述都同时携带五个信号。**先抽，再补。**

| 信号 | 长什么样 | 决定了什么 |
|---|---|---|
| **时代** | 末世、星舰、民国、长安、当代都市 | 主题色、字体、器物名、称呼、禁用词 |
| **场景** | 渡口、书院、夜班、边关、公寓 | 地图节点、初始所在地、开场地点 |
| **关系** | 当家人、师徒、债主、同事、陌生人 | 玩家与主角色的起始关系 |
| **危险源** | 水比命贵、灵气有毒、会在夜里来 | 消耗项、失败后果、压力来源 |
| **欲求** | 权力、生存、占有、被需要 | 人物张力从哪来、内容尺度 |

抽到三个就足以开工，剩下按 §2 补，并把补的内容写进 `assumed`。

```json
// work/brief.json —— 之后所有模块从这里取词
{
  "era": "（时代 + 一句成因）",
  "place": "（主场景）",
  "relation": "（玩家与主角色）",
  "pressure": "（每轮要付的东西）",
  "desire": "（想要什么）",
  "tone": "（句子长短 / 形容词密度）",
  "signals": ["（原句里抽到的词）"],
  "assumed": ["（替作者定的第一处）", "（第二处）"]
}
```

`assumed` 是关键：它让作者一眼看出哪些是自己没说的。改这一栏比改整张卡便宜。

---

## 2. 补：按核心循环，不按固定表

「默认值」是**最不坏的选择**，不是唯一解；每一节都给了可替换方向。

### 2.1 玩法重心

| 一句话里出现 | 重心 | 加重的模块 |
|---|---|---|
| 生存、逃、活下去、荒野 | 生存 | 行囊、地图 |
| 权势、门派、朝堂、商号 | 经营 | 世界、人物 |
| 查、案、谜、失踪 | 解谜 | 见闻、地图 |
| 她/他、关系、同居、婚 | 关系 | 人物 |
| 打、杀、宗门、武道 | 成长 | 人物、世界 |

都没有 → 关系与生存各半。理由是这类卡多数时间花在「和谁、在哪里、缺什么」上。

### 2.2 主题 token

按时代取，见 [42-界面-视觉](42-界面-视觉.md) §1 的题材表。抽不到时代 → 暗底 + 单一暖色是最不容易出错的起点。

### 2.3 玩家维度

**不固定为 7 个。** 按 [44-界面-捏人协议](44-界面-捏人协议.md) §2 从核心循环推：身份类 / 能力类 / 处境类，各取 0–2 个，总数 3–6。

常见默认（可替换）：

| 维度 | 作用 | 什么时候可以省 |
|---|---|---|
| 姓名 | 称谓与代入 | 扮演固定角色时可省 |
| 性别 | 称谓与部分反应 | 世界无性别差异时可省 |
| 出身 | 立场与初始关系 | 所有玩家同一出身时可省 |
| 特长/能力 | 判定阈值与可用手段 | 无判定系统时可省 |
| 初始地点 | 开局场景 | 单场景卡可省 |
| 背景补充 | 玩家自定义过去 | 轻量卡可省 |

两条硬要求：

- **每个维度必须有代价或后果**，否则玩家一律选最优。
- **维度要和状态字段咬合**：选了「好手」，对应能力字段的初值要体现；否则捏人只是装饰。

### 2.4 状态字段

**不固定 hp / desire / intimacy。** 从 [字段库](fields/index.md) 选 4–8 个，覆盖三件事：

1. 每轮会变的（体力、时间、地点）；
2. 参与判定的（能力、资源）；
3. 玩家想随时看到的（2–4 个进气泡卡，其余进面板）。

示例（江湖卡，非模板）：`生命 / 体力 / 金钱 / 好感 / 地点 / 时间 / 标记 / 选项`。
换一张经营卡，可能是 `资金 / 库存 / 声望 / 日 / 天气 / 任务`。

超过 8 个就砍：先砍「阶段性才变」的，再砍「只影响文案」的。

### 2.5 NPC

一句话通常只给得出 1 个角色。补到 2–4 个的常用结构：

| 位 | 作用 | 关系初值参考 |
|---|---|---|
| **主** | 剧情发动机，玩家最先接触 | 陌生 / 眼熟 |
| **镜** | 与主角形成对照，折射主题另一面 | 熟识 |
| **刺** | 制造压力、背叛或道德困境 | 陌生偏冷 |

这是**功能位**，不是数量要求：只有主角一人也能成立，只要主线足够紧。

**不要为了凑数补 NPC**：每个 NPC 都要有可写的表层与至少一个可推进的动机；写不出来的，删掉比留空更好。

### 2.6 成人向子系统（可选）

只有当这张卡确实包含成人内容时才建：

- 部位键名以 [40-界面-卡架构](40-界面-卡架构.md) §6 的契约为准，**一个字都不能错**，否则热区点了打不开；
- 部位状态是受控词（干净 / 沾染 / 被外射 / 被内射 / 同时内外射），换词会让选图失效；
- 纯剧情卡不要为了「完整」硬加这一层，它会让每轮输出变长、出错面变大。

### 2.7 开场

三要素（默认）：

1. 一个动作或环境细节（正在发生的事，不是设定）；
2. 主角在场，但还没被点名（第二人称，不写名字）；
3. 一个钩子（没说完的话 / 正在靠近的人 / 缺的东西）。

长度按形态：

| 形态 | 参考长度 |
|---|---|
| 有封面 + 捏人的卡 | 120–300 字：玩家刚看完两屏，开场要快 |
| 直接开局的纯文字卡 | 300–800 字：开场就是全部第一印象 |

**不要在开场写世界史、数值或「你将扮演」**；那些属于 `world` 与 `codex`。

## 3. 咬合检查

一句话卡的失败多数不是文笔，是维度对不上。逐条查：

- [ ] 玩家维度的选项（如初始地点）= 地图节点名，一个不多一个不少
- [ ] 每个状态字段都能在 `world` 或规则里找到解释：玩家知道它为什么变
- [ ] 每个 NPC 的表层身份与动机不矛盾
- [ ] 若建了成人向子系统：键名符合性别契约，状态在受控词内
- [ ] `codex` 与 `world` 没有重复内容（重复 = 双份真值）
- [ ] 开场出现的专有名词，都能在 `codex` 或 `world` 里找到解释
- [ ] 限定色只出现在 3 个以内的语义位置（选中 / 危险 / 亲密）
- [ ] 捏人选了「能力强」，对应字段初值确实更高

有一条不过就改，不要带着裂缝交付。

---

## 4. 什么时候才允许问

默认不问。一句话就开工，把假设挂在 `assumed` 里。

只有三种情况必须先问，因为选错要重做整张卡：

| 情况 | 为什么必须问 | 怎么问 |
|---|---|---|
| 一句话里出现两个互斥的时代 | 主题色、器物、称呼全套冲突 | 二选一，给推荐 |
| 明确要求「照某个作品」但没说改哪里 | 抄与不抄的边界不清 | 问「要哪些、不要哪些」 |
| 玩家要扮演已有的具体角色 | 人设要写死该角色，捏人页可能要砍 | 确认是「扮演他」还是「与他互动」 |

除此之外，提问是消耗作者时间。

---

## 5. 交付时怎么写「我替你定的」

不要写「已完成」，要写清哪几处是推断：

```
我补的默认值：
- 时代成因：原文没给年代，锁在<某处>
- 主 NPC 的性别与身份（原文只写了身份）
- 专属资源用<某词>，归零触发<某后果>
- NPC 补到 3 人：主 / 镜 / 刺
```

这四行让作者在 10 秒内判断要不要返工。

---

## 6. 反例

| 症状 | 根因 | 修法 |
|---|---|---|
| 卡能跑，但玩两轮没内容 | 只有主 NPC，没有压力源 | 补一个制造冲突的角色或事件 |
| 状态栏有数值，玩家不知道在扣什么 | 字段没在规则里解释 | 加一句成本描述 |
| 捏人选完，进游戏数值没变 | 维度与字段没咬合 | 按 §2.3 重接 |
| 点开人物里层是空的 | 成人向子系统没写，或键名错 | 按 §2.6 补齐，或干脆不建 |
| 开场像设定集 | 把 `world` 写进了开场 | 按 §2.7 重写 |
| 换题材后还是原来的味 | 只换了颜色，没换器物名与称呼 | 重过 §2.1 / §2.2 |

## 1. 规则替换算法（逐字复刻，build 与 validate 都按这个来）

```
输入：全部 regex_scripts 按顺序执行，作用在「已被前面规则改写过的文本」上
单条：
  1. findRegex.trim() → 去掉首尾反引号
  2. 命中 /^\/(.+)\/([gimsuy]*)$/ → 当正则；缺 g 自动补 g
  3. 不命中 → 当字面量，replaceAll（元字符被转义，a.b 不匹配 axb）
  4. 写成 /…/ 但语法错 → 整条静默丢弃，不降级成字面量，页面无异常
  5. replaceString 支持 $1 $2 捕获、$名字（第一捕获组形如 血量::10;;金币::3）、{{random:甲::乙::丙}}
收尾：
  6. _stripAndCacheRoleSandboxScripts() 把全文 <script> 抽出缓存
  7. _runRoleSandboxScripts() 按出现顺序执行 → 「脚本被抽走也照样跑」
```

**推论**：链式注入成立。一条规则的产出可以是下一条的输入。注入标记用 `【rex-xxx】`，必须在链尾被消耗干净，否则页面上会露出来。

补充三条机制（`【源码】`，详见 [23](23-平台-事实表.md) §9）：

- 输出预算 `max(262144, 本条输入长度 × 4)`；超限时**整条规则回滚**，只在调试面板留一行告警。预算按条累计所有命中位置的输出之和。
- `scriptName` 以 `__` 开头时整条被丢弃，可用于临时停用。
- 规则按 `regexSort` 升序执行；字面量匹配式重复时，后一条永不命中。

`【实测】`（两份成品卡重放：100 条全点火无残留；68 条里 66 条点火，未命中 2 条各有其他入口）

## 2. 三个点火入口

| 入口 | 字段 | 上限 | 属性 |
|---|---|---|---|
| 开场 | `beginning` | 4000 字 | 玩家看见的第一句话；中文环境读 `beginningZh`，英文读 `beginning` `【实测】` |
| 功能栏 | `statusbar` | 200 字 | **也会过一遍正则**（`removeSpan()` 里先 `applyRegexList()`），挂在 `top:-99999px` 隐藏 div 上 `【实测】` |
| 模型输出 | AI 正文 | — | 状态块、选项块等，靠 `message:done` 的 `msg.content` 解析 |

`pageDepth` 固定 `2`；它只决定隐藏挂载点接在哪层容器，新页不实现该语义 `【实测】`。

**执行时机（头号坑）**：`<script>` 装卡即抽出并**立即执行**，而功能栏与消息 HTML 由 Vue 在**之后**才挂进 DOM。所以在脚本体顶层 `document.getElementById` 恒为 `null`，`appendChild` 静默无效。顶层只能做四件事：定义函数、挂 `window`、`sdk.on(...)` 订阅、准备数据。**任何 DOM 读写都必须放进事件回调。**

```html
<script>
// ✗ 顶层碰 DOM：恒为 null，整段脚本废掉
var box = document.getElementById('my-hud');
box.innerHTML = '…';

// ✓ 顶层只定义与订阅
function renderHud() {
  var box = document.getElementById('my-hud');
  if (!box || box.__inited) return;   // 幂等哨兵：预览会重跑
  box.__inited = 1;
  box.appendChild(document.createTextNode('就绪'));
}
sdk.on('message:mount', renderHud);   // 首屏靠这个，不是 ready
sdk.on('message:done', renderHud);
<\/script>
```

`chatVersion` **在新页运行时代码里完全不读**（`pages-chat-chat-sandbox.*.js` 中 0 次出现），只影响创卡页预览与分享链接 `【实测】`。但导入接口仍按它分流：**新版必须写 `1`，旧版同层卡必须写 `0`**。写错会静默落到另一条路线，页面不报错。

## 4. 选择器（能用的只有这些）

| 用途 | 选择器 | 备注 |
|---|---|---|
| 页面根 | `[data-chat="root"]` | 承诺不改名；带 `data-theme` / `data-composer` |
| 消息 | `[data-chat="message"]`、`[data-chat="message-body"]`、`[data-from="ai"\|"user"]` | 气泡另有 `data-state`、`data-msg-id`、生成中 `data-generating="1"` |
| 顶栏 / 输入 | `[data-chat="header"]`、`[data-chat="input"]`、`[data-chat="composer"]` | 输入白底绘制在 `input` 的直接父容器上 |
| 槽位 | `[data-slot="header-extra" \| "statusbar" \| "left" \| "right" \| "toolbar" \| "message-extra"]` | 共 6 个公开槽位 + 平台自用 `sdk-debug` |
| 宿主弹窗 | 卡内 CSS **打不到** | 宿主页面板（模型设置/对话设置/人设/总结等）改不动，详见 [47](47-界面-宿主与弹窗边界.md) |

槽位细节：

- `left` / `right` 是 root 的直接子节点，可安全挂浮层；**窄屏可能不存在**，只能作增强，不能当前提。
- `statusbar` 为空时整块不存在；`header-extra` 为 `:empty` 时 `display:none`；`composer` 在卡片关闭输入时整块不存在。
- 槽位默认 `flex-shrink:1`，内容多会被压扁，自己补 `flex-shrink:0`。

**`data-*` 的正确答案：只放进 `<script>` / `<style>`，别放进静态标记。**

实测两张真实成品卡（数据可复现）：

| 卡 | 规则数 | 总量 | 含 `data-*` 的规则 | 位置 |
|---|---|---|---|---|
| 成品卡 B | 68 | 629,728 字 | 2 条 | 都在 `<style>` 里做属性选择器（`[data-prose-font="lg"]`） |
| 成品卡 A | 100 | 1,873,259 字 | 6 条 | 都在 19000 字的 HUD 载荷 `<script>` 内（`data-chapter` / `data-realm` / `data-picture` / `data-art` / `data-material` / `data-direction`） |

**291 万字符、168 条规则里，没有一处 `data-*` 出现在平台直接解析的静态标记中。** 这不是巧合——两张卡的作者都走了同一条路：

- ✅ **运行时建 DOM 才用 `data-*`**：`el.innerHTML = '<button data-rex-tab="map">…'` 写在 `<script>` 的字符串里 → 这串字符平台从不解析，只有浏览器执行脚本时才变成标记，净化器碰不到。
- ⚠️ **真正危险的写法**：把 `<div data-x="1">` 直接写在 replaceString 的裸露标记里（不在 script/style 内）→ 平台插入消息 HTML 时可能整片剃掉，症状是「样式对、按钮全哑、无报错」。
- 所以本骨架的所有 `data-rex-*` / `data-f` / `data-node` 都在 JS 字符串中，零静态标记。校验器 `validate.mjs` 会先剥掉 `<script>` / `<style>` 再检查，只对裸标记报警。

**不能做**：抄页面上的哈希 class；裸父页面选择器（`.sandbox-host`、`.model-setting-scope`）；`window.parent.document`。

**配色只改 `var(--chat-*)`**：平台共 29 个（气泡与整页 10 + 底栏与白名单弹窗 18 + 别名 1），完整清单见 [23](23-平台-事实表.md) §5。三条纪律：

1. 覆盖写 `[data-chat="root"][data-theme="dark|light"]`（特异性 0,2,0），可跟随深浅色切换；平台令牌本身是 0,1,0。
2. 只改 `--chat-bg` / `--chat-text` / `--chat-accent` 带不动底栏与弹窗——那 18 个是独立变量。
3. 别名（`--chat-bubble-user-bg` / `--chat-bubble-ai-bg` / `--chat-bubble-text` / `--chat-more-item-bg`）保持 `var()` 引用，写死即切断传导链。

**z-index**：平台 header / composer / messages 实测 `z-index:auto` + `position:static`；舞台 `content` 2000、`full` 3000；平台临时浮层 8000–10090。作者页面级浮层取 **3500–7999**，气泡内装饰取 1–999。详见 [23](23-平台-事实表.md) §6。

## 5. SDK 能力清单（拼错就永远不生效）

**30 个能力**

```
input.get  input.set  input.add  input.insert  input.clear  input.focus  input.blur
input.getCursor  input.setCursor
composer.show  composer.hide  composer.visible
message.send  message.edit
cache.get  cache.set  cache.remove
save.get  save.set  save.remove  save.keys
stage.open  stage.close  stage.el  stage.visible
role.get  user.get  on  debug.log  version
```

**12 个事件**

```
ready  message:new  message:done  message:stream  message:mount  message:unmount
input:change  conversation:switch  theme:change  back  stage:close  dispose
```

`【契约】`（contract.json 会校验这些名字，validate.mjs 拿它做交叉核对）

**关键语义**

- `sdk.role.get()` → `{ name, avatarUrl }`；`sdk.user.get()` → `{ nickname, avatarUrl }`。**读不到人设、世界书、开场白、正则**，不要编造 `role.personality` 之类字段。
- `sdk.save`：服务端持久化，跨设备，**上限由宿主动态下发**（不写死 10 key），有频率限制；只能恢复游戏快照，**不能删改宿主聊天历史**。
- `sdk.cache`：会话内，刷新即失。
- `sdk.stage.open('content'|'full')` + `sdk.stage.el()`：**长期存在的面板/画布只能挂这里**。气泡滚出屏幕就销毁。
- `sdk.message.send()` 未结束时重复调用立即返回 `BUSY`，不排队。

**六个必记的实现细节**（逐能力签名见 [25](25-平台-SDK速查.md)）：

| 项 | 事实 |
|---|---|
| `sdk.version` | **是值不是函数**，恒为 `'1'`；写 `sdk.version()` 抛错 |
| `sdk.save.remove` | 真机坏死：就绪态也稳定抛 `NETWORK`，重试无效；删档用 `save.set(key, null)` |
| `sdk.save.get` / `save.keys` | **同步抛 `SdkError`**，不是返回错误码；不 `try/catch` 整段脚本失效 |
| `sdk.stage.el()` | 关闭时也返回 DIV，不是 `null`；判断开关只能用 `stage.visible()` |
| `sdk.message.edit` | `serverId === null` 时不可编辑（开场白、未落库） |
| `sdk.role.get()` / `user.get()` | 读不到人设、世界书、开场白、正则；返回空值时给中文降级 |

**平台状态变量**（`sdk.vars.get/set` / `vars:change` / `<abc_vars>`）：**已确认存在，不是不存在**。仅新页可开、最多 6 层 80 键、快照随消息按楼层回溯、`{{var}}` 只替换本轮新组装内容、分享页与瘦预览可读不可写。但官方 `contract.json` 未给参数、返回值与导入字段——可以讲行为边界，不能编造签名，也不能说"平台不支持"。

三条红线：① 不编造 `sdk.vars.get()` 的参数与返回结构；② 不把 `varSchema` / `varInit` 这类推测字段塞进 6 键正则包；③ 不用正则去 hide 或改写 `<abc_vars>`（平台已把它从正文拆出去，正文本来就是干净的）。

现阶段状态一律走「AI 正文吐 `[rex-status]` → 前端解析 → `sdk.save`」。等契约公布，再把 [33](33-内容-存档与续档.md) 的手写存档替换成平台变量。

## 6. 事件用法（已验证的陷阱）

| 需求 | 用哪个 |
|---|---|
| 读 AI 最终正文 | `message:done` 的 `msg.content`。**不要**读 `[data-chat="message-body"]`——空气泡一挂上那里是「消息生成中」 |
| 跟字、打字机 | `message:stream` 的 `msg.content` |
| 每条气泡出现时绑按钮 | `message:mount`，在 `unmount` 里解绑。**`sdk.on` 写脚本体，不要写进 mount 回调** |
| 切会话 | `conversation:switch`：清 `cache`，重读 `save` |
| 跟随深浅色 | `theme:change` |

三条回调细节：

- **只传 1 个实参**（payload）。契约写的第二参 `bubbleRoot` 不是 SDK 提供的，不要依赖。
- **`msg.id` 跨重载会变**（`l1` → `h9512`）。持久化、定位、计数一律用 `msg.serverId`（等于气泡上的 `data-msg-id`）。开场白 `id` 为 `'greeting'`、`serverId` 为 `null`。
- **`ready` 最后到且不补发**。首屏挂 `message:mount` / `message:done`；`ready` 只当诊断信号。

## 7. 内容禁令与渲染细节

- `findRegex` 别含 HTML 标签或 `html` / `head` / `body` / `css` 这类保留字。
- `replaceString` 别写 `*{}` / `html{}` / `body{}` 全局 CSS。
- 替换内容会过一遍 Markdown：**HTML 不要缩进四个空格**，会变代码块原样显示。
- 白名单外标签会被删：`iframe` `link` `meta` `form` `object` `embed`。
- JSON 字符串里的 `</script>` 必须写 `<\/script>`，否则宿主页面提前截断。
- 中文引号、全角标点在 JSON 里安全；**双引号必须转义**，换行必须 `\n`。

两条渲染时机（`【源码】`，只适用新版）：

- **`statusbar` 字段只在装载时渲染一次**。渲染函数没有重渲染路径，它的正则输入是 `statusbar` 字段自身、不是消息内容——AI 每轮输出新状态，功能栏不会跟着变。动态数值只能靠作者 JS 在 `message:done` 里改 DOM。
- **作者内容落在 `[data-chat="message-body"]` 里**，它带 `opacity:.9`（颜色透 10%，且创建层叠上下文把 z-index 囚禁在气泡内）与 `white-space:pre-line`（标签间换行显形）。见 [42](42-界面-视觉.md) §4 与 facts 的 `runtimeBehavior`。

> 旧版不适用：旧版状态栏逐消息渲染，每条消息各自点火，机制与新版完全不同。

## 8. 导入三步（每次交付都要写给用户）

1. **新建卡**——`chatVersion` 只在新建卡导入时被读取，给已存在的卡导入会被忽略，且**无法把老卡升级成新页**。
2. **首次保存前**把「新版聊天页」选成「使用新版」——人工步骤，整卡路线最容易漏。选错无回头路，只能重开。漏掉的症状：规则装上但 `sdk.*` / `[data-chat]` / 舞台全不在，按钮不响应、样式对一半，**页面无任何报错**。
3. 导入正则 → 人设贴「角色人设」→ 世界书单独导入 → 回聊天页看效果（创卡页预览是瘦环境，能力矩阵见下节）。

## 9. 两类标记，不要混

| | 注入标记 | 内容协议标记 |
|---|---|---|
| 形态 | `【rex-boot】`、`【rex-hud】` | `[rex-status]{…}[/rex-status]` |
| 出现在 | `beginning` / `statusbar` / `findRegex` | 模型正文、解析脚本、开场白基准块 |
| 作用 | 把规则挂到正文上，一次消耗 | 承载状态数据，每轮解析 |
| 约束 | 不用尖括号：创卡页对 `findRegex` 有 HTML 标签文案禁令；方括号也不受正则转义影响 | **必须被一条规则消耗**：`findRegex: /\[rex-status\][\s\S]*?\[\/rex-status\]/`，渲染成紧凑卡或空串。协议本身用方括号，不用尖括号——中文尖括号会被剥壳整段删掉，连字符尖括号会以未知元素留在气泡里 |

## 10. 瘦预览能力矩阵（创卡页）

| 行为 | 能力 |
|---|---|
| 同步抛 `SdkError` | `save.get`、`save.keys` |
| 返回 `undefined` | `cache.get` |
| 返回 `NOT_SUPPORTED` | `input.set/add/insert/clear/focus/blur/setCursor`、`composer.show/hide`、`message.send/edit`、`save.set/remove` |
| 仍可用 | `cache.set/remove`、`on`、`debug.log`、`version`、`role.get`、`user.get`、`stage.*`、`composer.visible` |
| 固定返回 | `composer.visible()` → `true`；`input.get()` → `""`；`input.getCursor()` → `0`；`stage.el()` → `DIV`（关着也返回） |

结论：写类能力在瘦预览不可用是**预期行为**，不要据此判断卡坏了；`save.get` 必须包 `try/catch`，否则整段脚本失效且页面无提示。

## 11. 静默失败清单（逐条都无报错）

1. `chatVersion` 写 0 或漏写：`sdk.*`、`[data-chat]`、舞台全不在。
2. `findRegex` 写成 `/…/` 但语法错：整条丢弃。
3. 字面量匹配式重复：后一条永不命中。
4. 可见 HTML 的标记没接进 `beginning` / `statusbar` / 前序替换：界面永不出现。
5. 能力名或事件名拼错：永不生效、永不触发。
6. 自写 `data-*` 被净化：后续 `querySelector` 全查不到。
7. z-index 落在 1000–3499：被舞台压住。
8. 替换产物超输出预算：整条规则回滚，仅调试面板可见。
9. `sdk.on` 写进 `message:mount` 回调：每挂一条气泡多订一份。
10. 在 `message:mount` 里读 `message-body` 当正文：读到「消息生成中」占位。

完整表由 `facts.json` 的 `silentFailures` 维护，脚本 `validate` 会对可静态判定的项逐条拦截。

# 模块化场景与阅读布局

- ID：`sl-modular-scenes`；路线：旧版同层；架构：注册式场景 + mmd-sl/1 Host/Frame。
- 方向：角色创建、资料百科、长篇阅读、地图探索、音乐与进度管理。
- 布局：场景切换、桌面侧栏、消息状态、移动顶栏/单列。
- 实现与完整制作说明：[模块化场景完整模板](../../../assets/modular-scenes/README.md)。
- 成熟度与验证结果以 [机器目录](../catalog.json) 和其中的复测报告为准；目标站/实体设备不继承本地结果。

## 可直接克隆的完整工程

已提供十个场景的源码、两套自制题材/主题、原生适配、状态解析、存档与恢复、响应式 CSS、初始化/审阅同步/构建/回读和浏览器回归。构建不需要原始卡、外部素材或包外源码，也不需要 Python。随工程复制独立工具，skill 移位后仍可构建。

页面树、数据与模块接口、皮肉替换位置、完整命令和测试范围统一维护在资产说明，不再在本页复写另一套契约。

## 使用步骤

1. 选定内容和皮肤，执行 `node scripts/modular-scenes.mjs init <新项目> --name my-card --title 卡名`；另一套题材可加 `--variant orbit`。
2. 在新工程 `工程/src/content.json` 替换配色、标题、创建选项、人物、条目、地名和音景，不修改通用 frame/host。
3. 用户改交付区三份审阅稿，Agent 用 `modular-scenes.mjs status/sync/build` 核对、回写与构建；源码和审阅双改先处理冲突。
4. `verify` 回读发布包与源码快照；运行 `test-modular-scenes.mjs` 和实际工程的 `e2e-modular-scenes.mjs`，宽窄屏、失败和恢复分别留证。
5. 实际 MMD 入口和设备按 54 另验；交付清单见资产说明与55，不把本地宿主模拟当真站通过。

## 固定边界

保留场景模块注册、页面层级、返回/关闭、统一状态、生命周期与既有原生适配。常规换皮肉只改内容配置与创作稿；字段和平台适配必须显式核对。桥接方法、导航结构或存档语义改变属于派生方法。

本方法是独立的同层完整工程，不与最小基座的 rex-sl/2 消息混接；不要求第一句话包含模块标签。保留现有链式状态栏构建，不在本次更改启动器或实现其他入口策略。原生设置等直接让位到原生页面，不声称具有全部原生功能的独立自制面板。

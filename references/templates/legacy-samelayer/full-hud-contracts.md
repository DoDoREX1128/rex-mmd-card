# 旧版同层 · 完整 HUD 制作与验收契约

本页属于完整 HUD 方法，不是所有旧版同层方法的强制架构。

适用于旧聊天页中由 Host 接原生能力、Frame 承载完整界面的长篇卡。按本次范围选择封面、捏人、人物、系统、地图、阅读器；不是所有卡必须实现的功能清单。新版沙盒仍走 21/25，旧版原生仍走 24。

## 1. 三份产物共同定义一张卡

| 产物 | 职责 | 修改时核对 |
|---|---|---|
| persona.txt | 叙述身份、主题、核心关系、认知边界、开局、输出协议指针 | 保留已有正文与文风；不借修协议重写其文风 |
| worldbook.json | 常驻规则、按需设定、字段目录、可选创建参考 | 稳定 UID、关键词、优先级、启用状态与真实触发文本 |
| regex.json | 点火、协议隐藏、Host/Frame 载荷与启动失败反馈 | 旧版四键、id=-1、片长、总规则、消耗令牌、重入与销毁 |

字段说明以一处为准：世界书字段目录写类型、缺省、合并、清空和示例；人设指向它，解析器和测试使用同一契约。不要把整份字段表重复维护在人设、世界书和脚本三个地方。

实际工程起点是 [完整成品骨架](../../../assets/samelayer-complete/README.md)：保留完整 HUD、已补丁 Host、原生动作与压缩构建。默认复用整套实现，不用最小 Host/Frame 或教学小组件替换。先按完整骨架的文件表换题材内容，原生动作只在目标站发生变化时定向修补。

## 2. 原型进入 Frame

先定信息架构与一个完整返回链，再接真实数据。PC 可采用导航/摘要/详情，手机使用单列、分级详情与底部导航；栏数、导航项数和断点由内容密度决定。封面、创建、正文、原生面板各自有返回路径，返回创建上一步保留草稿。

- 需要复用完整封面原型时，可在 Frame 内用 Shadow DOM 隔离其全局 CSS；调整 `:root→:host`、默认查询根和动效属性的承载节点。事件监听、动画和 observer 随组件销毁；不能只复制 CSS。
- 同层 Frame 的隔离与组件 Shadow DOM 是两层不同边界。Shadow DOM 不赋予访问父页面的权限；原生动作仍经 Host 白名单。
- 根容器属性与点击委托使用不同名字，避免 `closest('[data-nav]')` 截到整页容器。按钮不嵌套按钮；拖拽处理先排除按钮、输入框和链接。
- 介绍气泡打开时，下一次外部点击先关闭气泡，阻止该次点击落到下层选项。关闭/返回不受动作 busy 锁阻塞。
- 采用简洁界面时，删掉解释实现的说明文字；保留空状态、失败原因、危险后果和必要的无障碍名称。不能为去说明而删掉操作反馈。
- 翻页可选 CSS 分栏，页码取真实布局位置；切模式按内容锚点恢复。不要让 `scrollIntoView` 同时拖动所有祖先；限制到阅读容器。
- 布局只从原始数据计算，避免反复读回自己改过的尺寸。收藏、锁定、选中、主题等都纳入重绘依赖；编辑中不重建输入节点。

宽屏、窄屏均验证横向溢出、遮挡、返回、键盘与 reduced-motion。Canvas 可按设备限制 DPR、粒子和刷新率；具体阈值通过该作品实测确定。

## 3. 增量状态与历史重建

本节是换卡和扩展时的验收契约。内置回放仍使用按 turn 排序与补偿实现；更严格的编辑/删除重建要求仍要以对应行为回归为准。

模型生成使用 `[status]{JSON}[/status]`。历史兼容可以同时读取旧标签，开闭标签一起归一；不能要求新卡继续生成旧标记。

1. 解析取原始内容或 DOM 的 `textContent`，显示取已剥离协议的文本。`innerText` 会忽略隐藏节点，不能作为唯一协议源。
2. 按宿主确认的消息顺序重放所有有效 assistant 状态块。用户引用的示例 JSON 不参与状态；role 无法确定时先修正 Host 映射，不能无条件把用户消息当模型输出。
3. 缺键继承、对象按键合并、列表整组替换；空列表可清空。装备等实体集合如需增量更新，声明稳定 ID、删除和重命名语义，不能按显示名合并。
4. `turn` 是模型数据，不是消息唯一 ID。重复 turn 的新消息仍要处理；同一消息重复快照不得重复追加。优先从完整历史重建，或以消息 ID+内容版本维护缓存。
5. 编辑、删除、回溯、重置和切会话后重建，撤销已经消失的状态；仅“跳过旧 turn”无法处理这些操作。保存快照若只带部分历史，需另定义基线与游标，不能当完整回放。
6. 坏 JSON 留住上一有效状态并报告具体消息；生成中半截块不展示在正文，也不提前应用。裸 JSON 修复仅在明确的历史兼容通道中开启，需界定边界与类型白名单。

隐藏协议与保存原文是两件事。长块用 `$1` 搬入隐藏容器可能受平台替换长度限制；可选“只替换开/闭标签”的路线，但必须实测净化器是否保留闭合结构、是否吞掉后文。不能仅因一张卡能用，就把任意隐藏策略宣布为平台通用事实。

## 4. 世界书与创建参考

新稿每条content用唯一一组同名首尾标签包裹，内部普通分节，按[31](../../31-内容-世界书.md)校验；创建参考同样适用。标题的分类符号与正文外层标签是不同字段，不能互相替代。

常驻判据：这条不在上下文，本轮是否容易写错？人物志、图鉴和长背景按需触发。创建参考与正文分组维护；可用稳定源 ID/元数据分类，导出目标不支持分类字段时再映射到标题约定，不要求所有作品用同一种括号。

- `order` 越大越优先，不能拿数组位置或 UID 代替；项目可设分组区间与步长方便插入。具体区间不是平台限制。
- 精简标题时保留已有关键词，增加新短名；用创建提交块的实际文本回放触发，检查漏触发和关键词误抢。
- 创建提交只传名称/稳定 ID，介绍按需注入，前提是目标站确实能用这些词触发参考；目录存在不证明会注入。
- 文本总表作为唯一文案源时，使用稳定条目 ID 回填，检测漏项/重复，再生成审阅稿；不要手工维护两套内容。
- 地图使用唯一地名注册表，地区 ID、地区名、视图标题分开；未知原文保留并提示，不能强制切到默认地区。地点与人物位置共用别名表。

## 5. 原生适配与完成信号

| 风险 | 实施与验收 |
|---|---|
| 图标不是可见 img | 图标可能在 background-image 中；定位、可操作性与可见性分别判断，目标站复查 |
| 输入框可见但只读 | 找实际可写输入并校验写后值；不要盲删 readonly 或绕过平台限制 |
| 面板常驻隐藏 DOM | 是否打开需检查布局盒与样式，不只检查节点存在 |
| 菜单 revision 频繁变化 | 动作前观察并重新定位，不能仅靠旧 revision，也不能取消全部过期保护 |
| 确认接口是 toggle | 已打开就处理当前确认；按整段文案和对象核对，二次确认沿用原操作授权 |
| bridge 读错返回结构 | 对照当前处理器验证 `{ok,data}` 等实际契约；缺字段立即报错，不能无限等 |
| busy 永久不复位 | 动作本身用 finally 解锁，不依赖下一次快照解锁；保留关闭入口 |
| 生图/保存显示假成功 | 区分填入、提交、服务端确认和结果完成；费用由平台处理，不能代扣或用 toast 冒充落库 |

选项写草稿，已有输入按用户约定追加/替换，不自动发送。长任务设超时，失败保留草稿；涉及提交、删除、重置时沿用本次明确授权，不因为测试功能存在就执行。

## 6. 大载荷与可复现构建

先判断默认 `pack-samelayer` 是否够用。完整应用需要压缩时，可以采用确定性压缩→base64→分片→校验→启动，旧 WebView 的解压器不依赖缺失的浏览器压缩 API。完整成品骨架的 complete-samelayer.py 已保留这条 LZ77 路线；最小 pack-samelayer 则仍是另一种打包器，不要混用。

构建必须回读交付 JSON，而不是只检查源代码：

- 旧版四键、规则 id=-1、statusbar/开场/单条替换长度及总规则数均合规。
- 分片索引连续、逐片哈希与解码后的完整载荷哈希一致；恢复的 Frame 与构建源逐字节一致。
- 规则总数包含隐藏、分片、启动等；不能把片数当规则数。压缩不含时间戳与随机内容，重复构建可比对。
- 独立规则与累积替换两种语义分别仿真；链式仅在累积语义成立，不能声称同一链式入口在独立语义下也通过。令牌全部消耗，断片和失败可见。
- Markdown/净化器可能改写内联代码。采用编码或转义并检查最终输出；特定 launcher 的字符禁用集合不适用于所有业务 JS。
- 模块合并使用显式清单和缺文件断言；同步基座前记录补丁，避免上游重铺覆盖定制。产物计数、哈希、manifest 与交付说明一起更新。

正式导入后验证点火、状态和一个原生动作；同 hash 导航可能不刷新，先核对加载构建，必要时真实刷新。宿主 iframe 与内部 Frame 要分别定位。CSP 放行哪些来源以目标部署为准。

## 7. 完整运行时的复现与验证

完整骨架包含Host、原生DOM适配、功能动作、模型动作、原生基础落点、Frame交互、封面创建、地图/档案组件、CSS和构建链。以实际文件与动作目录为准，不用历史动作数量替代实现清单。

运行 `check-complete-actions.mjs` 校验81项动作目录及33份运行时文件；再对新工程执行完整构建与 `e2e-complete-samelayer.mjs`。动作名、参数契约、桥接白名单、处理器、HUD事件、结果回读及关闭/返回必须连续，不能只验其中一层。

对支持的目标页面，验收目标是复现全部现有HUD动作。源码/本地回归、目标站非破坏性操作、已授权的真实写入及实体设备分别记录。模拟夹具通过说明变体处理正确，不能据此认定当前平台恰好采用同一DOM。

## 8. 改卡与工程协作

保留已有稿件与选定风格，按需求分组逐项完成；复用结构和交互后再替换题材与视觉。已委托代选时自行决策，仅请求方案时先交方案。短反馈先复现，定位根因后修复；明确的全局变化检查所有适用位置。

交付/工程分离，内容总表作为唯一维护位置；不要让同步脚本重铺掉已修好的原生适配。导航数、创建步数、配色与帧率按作品调整；输入保护、关闭可用、失败可见和动作结果回读作为工程不变量。开发中的常见故障与优化方法直接使用下列检查表，不重演旧方案：

# 完整 HUD 与多面板应用

- ID：`sl-full-hud`；路线：旧版同层；架构：Host/Frame。
- 方向：长篇阅读、角色创建、世界探索、多面板管理。
- 布局：全屏应用、分级导航、移动单列、桌面分区。
- 成熟度：`buildable`。实现随包提供；不自动继承新作品的本地/目标站/设备通过结论。

## 结构与适用边界

页面树：封面→创建/续档→正文主界面→人物/地图/设置/原生面板；子页可关闭或返回，创建返回保留草稿，正文操作失败保留输入。可选模块按需求启用，不强迫每张卡具有全部题材功能。

Host 适配原生页面，Frame 管页面、阅读与交互。数据经既有桥接和快照进入 Frame；状态权威、历史重建、生命周期与动作结果按 [完整制作契约](full-hud-contracts.md)执行，不因换肤重写。

适合需要完整独立界面和原生适配的旧版卡；纯文字、气泡换肤或新版舞台不要套用。

## 固定骨架与替换位置

文件表、命令和实现见 [完整骨架](../../../assets/samelayer-complete/README.md)。

| 层 | 位置 | 改造边界 |
|---|---|---|
| 固定骨架 | kit 的 Host/动作/模型/原生处理器、frame 构建链 | 保留契约、白名单、确认、回读和失败反馈；平台实测失败才定向适配 |
| 页面交互 | frame-main、frame-creation、frame-panels 等 | 保留导航、返回、草稿和清理；重做导航属于派生方法 |
| 皮肤 | frame.css、frame.html、局部组件样式 | 换 token/字体/素材；保留响应式、触控区和可读性 |
| 内容 | 新工程 persona/worldbook/opening、创建数据、地图/人物数据 | 换世界、人设、选项、地名与文案，不继承参考题材 |
| 字段 | frame-main 的解析/渲染、地图/人物/创建绑定 | 三份产物与解析器同一契约，不能只改显示标签 |
| 作用域 | template 配置与各存储键 | 按作品/账号/角色/会话隔离，不能只改 appId |

现有基础资产含演示领域内容，“已克隆”不等于“去痕换题材完成”。发布新作品前按 [29](../../29-平台-模板分类与融合规范.md)逐项替换、扫描及验证。

## 完整制作路径

1. 确定内容、字段、选用模块和皮肤；按 02 建交付/工程目录。从零内容由 Agent 准备，不要求用户写代码。
2. 用完整骨架的 `complete-samelayer.py init` 复制成套实现，不以最小演示覆盖完整工程。
3. 按上表换皮肉与字段，保留原生动作链；按制作契约接状态、世界书与创建参考。
4. `status/sync` 核对用户审阅稿，`build/verify` 构建并回读交付包；具体参数见资产 README。
5. 跑动作目录、完整构建测试及实际新工程浏览器回归；查主流程、返回/关闭、输入、状态和存档。
6. 按 54 单独验证目标站/设备，按 55 交付，只报告实际证据，不把模拟当真实写入成功。

## 验收与证据

资产可用 `node scripts/check-complete-actions.mjs` 查动作与运行时完整性，`python scripts/test-complete-samelayer.py` 查构建等行为；实际项目跑 `e2e-complete-samelayer.mjs`。完整要求和错题入口见 [制作契约](full-hud-contracts.md)。

成熟度仅说明实现随包提供；换题材、目标部署与设备结论在新工程记录，不在此虚构统一通过状态。

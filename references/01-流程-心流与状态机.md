# 01 · 心流与状态机

> 目的：把「每次对话从哪里开始、下一步做什么、什么算过关」固定下来，避免三种常见偏移——没定位就动手、边做边改方案、把本地预览当成实机结论。

---

## 1. 开场 30 秒定位

任何请求先跑这段，不要直接写代码。

| 序 | 判定 | 依据 | 判定不了的处置 |
|---|---|---|---|
| 1 | 版本：新版 `1` / 旧版 `0` | 用户要「新版聊天页 / 沙盒 / SDK / 舞台」→ 新版；要「保留原生聊天 / 删消息 / 回溯 / iframe HUD」→ 旧版 | 问一次，并把答案写进方案 |
| 2 | 路线：A 原生增强 / B 同层 / C 沙盒 | 需要原生动作 → B（旧版）；需要长期面板/跨设备 → C（新版）；只要换肤 + 自建场景 → A（旧版） | 用能力需求反推，不用风格偏好反推 |
| 3 | 交付形态：分离式 / 整卡 PNG / 整卡 JSON | 玩家要「一张图导入」→ PNG；要可维护 → 分离式 | 默认分离式，交付前问一次 |
| 4 | 档位：全托管 / 半托管 / 全精修 | 用户是否愿意逐项确认 | 默认半托管 |

输出一句书面结论，例：

> 版本：新版（chatVersion 1）。路线：C 沙盒卡。形态：分离式 6 键包 + 人设。档位：半托管。不做：原生动作、跨源弹窗换肤。

这句话同时是 S0 的产物，后续所有判断以它为准；用户改主意时更新这一句，不靠记忆。

## 2. 三档托管与提问预算

| 档位 | 适用 | 提问量 | 用户参与点 | 主要风险 |
|---|---|---|---|---|
| **全托管** | 想法完整、明确要全自动、无歧义 | 只问定位 4 项 + 3 个关键假设 | 交付时看结果 | 方向可能不符预期 |
| **半托管**（默认） | 想法完整但有歧义 | 只问关键分歧：平台 / 字段 / 视觉方向 | 改 2–3 处 | 低 |
| **全精修** | 用户要当导演 | 按方案模板逐项确认 | 全程 | 慢，但可控 |

提问规范：

1. 每次 2–4 个选项，每个选项写「是什么 / 得到什么 / 付什么代价 / 适合谁」；
2. 给推荐项与理由；
3. 一次最多 3 问；
4. 不问开放式问题（「你想要什么风格」），给具体方案让用户选。

档位只决定「方案怎么来」，下游构建、校验、交付完全一致；可随时升降档。

## 3. 六个状态

### S0 · 定位

- **入口**：用户提出需求。
- **动作**：跑第 1 节的 4 项判定；已有项目追加体检（平台 / 路线 / 当前阶段 / 可复用资产）。
- **产物**：一句书面结论（版本 / 路线 / 形态 / 档位 / 不做什么）。
- **出口**：用户确认，或明确授权代选。
- **回退**：用户说不清需求时，给 2–3 个具体方案（含能力与代价）让其选择，而不是继续追问细节。

### S1 · 方案

- **入口**：S0 已定。
- **动作**：按 [10-流程-三问与方案](10-流程-三问与方案.md) 填一页方案：定位、信息架构、字段与协议、视觉、交互、风险、验收；画一张首屏线框。
- **产物**：`brief.json` + 线框 + 风险清单。
- **出口**：通过「评审 7 问」——路线理由、导航项数与手机容纳、每轮字段数与削减方案、哪些字段每轮都变、首屏第一眼看到什么、手机最常用三个动作、哪一条从未验证过。
- **回退**：7 问有一问答不上，回 S0 重新判定路线或补信息。

### S2 · 原型

- **入口**：S1 通过。
- **动作**：只做三件事——首屏、主界面结构（导航 + 一个详情）、一次完整交互；假数据、不接宿主、不接协议。读 [43 封面与捏人](43-界面-封面与捏人.md)、[44 捏人协议](44-界面-捏人协议.md)、[41 基线](41-界面-基线.md)。
- **产物**：可点的原型页。
- **出口**：用户确认视觉方向与基础交互。
- **回退**：方向被否，回 S1 改视觉与 IA，不在原型上反复打磨细节。
- **限时**：原型阶段不追求完整，细节属于 S3 之后。

### S3 · 模拟

- **入口**：S2 确认。
- **动作**：读 [40 卡架构](40-界面-卡架构.md) 与 [30 状态与字段](30-内容-状态与字段.md)。
  1. 骨架就位：`init.mjs` → 改 `content.json` 与 `persona.txt`；
  2. 构建：`build.mjs` → 6 键包 + 人设 + 世界书 + v2 整卡；
  3. 门禁：`validate.mjs`（结构 / 限额 / 正则 / 标记 / SDK / CSS / 人设 / 世界书）+ `replay.mjs`（点火与残留）；
  4. 模拟：`preview.mjs` 跑双端与窄屏，用 `?profile=thin` 验瘦预览降级、`?preset=badjson|missing|empty` 验坏输出兜底；
  5. 回归：`e2e.mjs`。
- **产物**：构建包 + 校验输出 + 模拟截图。
- **出口**：`validate` 0 error；关键路径可点通；坏输出不清空上一份有效状态。
- **回退**：校验暴露结构问题（字段、协议、路线），回 S1；只暴露实现问题，在 S3 内修。

### S4 · 真站

- **入口**：用户提供**目标卡的测试链接**。没有链接不进入本阶段。
- **动作**：只经界面操作取证；`evaluate` 仅用于只读指标；必测首屏 / 导航 / 面板开关 / 消息编辑删除回溯 / 会话 / 人设 / 补充设定 / 指令 / 设置 / 输入发送 / 二次进入 / 窄屏。
- **产物**：截图、控制台记录、用例结果表。
- **出口**：上述用例全部通过，或逐项记录失败现象。
- **回退**：真站与模拟不一致时，先记录差异，再判断是平台事实缺失（补 facts）还是实现缺陷（回 S3）。

### S5 · 实机

- **入口**：S4 通过。
- **动作**：真机 / 真平台导入，玩三轮。
- **产物**：设备、浏览器、失败点、截图。
- **出口**：无阻断问题。
- **诚实边界**：没跑就写 `NOT RUN`，不推定。

## 4. 三条旅程

### 4.1 新卡

```
S0 定位 → S1 方案 → S2 原型 → S3 模拟（build/validate/preview/e2e）→ S4 真站 → S5 实机
```

### 4.2 改已有项目

```
S0 定位 + 体检 → S1 出 2–3 个改造方案 → S2' 只改受影响的界面 → S3 全量校验 → S4/S5
```

- 体检清单：读 `main.md` / `plan.md` / 清单文件；读入口、点火方式、协议、字段；跑一次现有产物定位「不渲染 / 样式错 / 按钮哑」；列出用户资产（HUD、文案、美术）与可替换零件。
- 分级：**文案 < 皮肤 < 模块 < 工程骨架**。跨级改先确认；重做工程骨架等于让用户重做十几轮，放在最后。

### 4.3 复刻

```
S0 定位 → analyze 拆解 → S1 复现清单 → S2 工程骨架复现 → S3 换创作皮肉 + check-skin + validate → S4/S5
```

- 拆解产出：架构判定、规则表、分片还原、标记链、原生动作命中、协议嗅探。
- 复现清单逐项打勾，缺一个节点/字段/状态即未复现。
- 换皮只动 token 层，不动结构；`check-skin` 报雷同则改配色/字体/质感，不改判据。

## 5. 断点续作

项目目录约定：

```
main.md      实时索引：版本 / 路线 / 各文件用途与状态
plan.md      任务清单与决策记录（完成一步立即打勾）
资料/        用户素材与被否方案
工作/        中间文件（草稿、分析产物）
output/      最终交付物
```

新会话恢复顺序：读 `main.md` → 读 `plan.md` → 核对当前文件 → 从「已授权未完成项」接续。跳过读取直接动工，是本 skill 最常见的返工原因。

## 6. 偏移与纠正

| 偏移 | 表现 | 纠正 |
|---|---|---|
| 跳阶段 | 没方案就开始写界面 | 回 S1，先把 7 问答完 |
| 边做边改方案 | 字段改了三次，每次都重写解析器 | 冻结字段名，改名前先改解析器，变更记一行 |
| 把预览当实机 | 本地跑通就写「已完成」 | 按证据等级标注：S3 通过 ≠ S4 通过 |
| 用风格反推路线 | 「我想要沉浸感」→ 选同层卡 | 用能力需求反推；风格在 S1 解决 |
| 过度提问 | 一次抛 9 个问题 | 收敛到 3 问，其余用默认值并标 `assumed` |
| 过度自动化 | 用户没确认方向就生成整卡 | 半托管档位下，S1 必须停下来确认 |

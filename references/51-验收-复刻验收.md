## 1. 从平台原始数据到可导入 JSON

平台的原始数据是接口给的（`role` + `regexp`），字段名和导出格式不一样。转换有四条硬规则：

| 规则 | 原因 |
|---|---|
| 按 `regexSort` **升序**排 | 平台 `loadRoleRegex()` 里会 `reverse()` 后执行；导出要还原成执行顺序 |
| id按路线归一：新版负整数，旧版固定-1 | 不用新版id规则改变旧版包 |
| `beginning` 优先取 `beginningZh` | `beginning` 常是占位（"第一句话"），中文环境实际读 `beginningZh` |
| 环境归一后再按包格式输出 | 新版写chatVersion=1，旧版独立包不带chatVersion |

```bash
node scripts/export-raw.mjs --role role.json --regexp regexp.json --out card.json
```

产出：旧版恰好四键/id=-1，或新版五必填键加可选personality。personality是留档，不因正则导入就进入人设栏；旧版需要留档时另用--persona-out指定文本路径。

## 2. 逆向分析任意一张卡

```bash
node scripts/analyze.mjs card.json --out work/analysis
```

输出：

```
analysis/
├── analysis.md      规则表 / 架构判定 / 分片统计 / 动作命中 / 字段嗅探
├── analysis.json    机器可读
└── chunks/          （A 型）还原出的 host.js / frame.js
```

判定逻辑：

| 特征 | 判定 |
|---|---|
| 规则里出现 `s.h=(s.h??'')+"` / 通用 `+="` 累积 | 分片链（A 型） |
| `beginning` 里有一串 `<tag>`，规则 `findRegex` 正好是 `/<tag>/` | 标签模块（B 型） |
| 只有 1~3 条大规则 | 单体（谨慎：可能是压缩产物） |

分析报告会给出：规则数、总字数、单条最大、标记链是否连续、是否有残留标记、`chatVersion`、原生动作命中数。

**用途**：拿到任何一张"好卡"，先用它拆结构，再决定学哪一部分。

## 3. 点火重放（交付前必跑）

平台的替换算法必须逐字复刻，否则你以为点火了，实际没有：

```js
// 1. findRegex.trim()，去掉首尾反引号
// 2. 命中 /^\/(.+)\/([gimsuy]*)$/ → 正则；缺 g 自动补
// 3. 不命中 → 字面量 replaceAll
// 4. /…/ 语法错 → 整条静默丢弃（不降级）
// 5. replaceString 支持 $1、$名字、{{random:甲::乙::丙}}
```

```bash
node scripts/replay.mjs card.json --from auto
```

报告四项：

- 点火数 / 总数
- 未命中列表（**必须为空**，除非该规则靠 AI 输出触发）
- 残留标记（`【…】` / `<tag>`）
- 产物长度与 `<script>` 块数

退出码非 0 = 有残留或关键规则没点火。

## 4. 打包旧版同层卡

```bash
node scripts/pack-samelayer.mjs \
  --host work/src/host.js \
  --frame work/src/frame.html \
  --out work/out --name my-card --theme mytheme
```

它会：

1. 转义（`<`→`\u003c`、`$`→`\x24`、`\`、`"`、换行）
2. 按原串转义成本安全切片（默认载荷预算19000）
3. 生成 init + h 片 + f 片 + launcher
4. 输出旧版四键/id=-1 JSON + manifest

打包后**立刻跑 replay**，链尾有残留就是切片或转义错了。

## 5. 测试层次与工具适配

S0–S5是工作阶段，E1–E5是证据。文件生成(E1)、静态(E2)、本地行为(E3)、目标站(E4)、实体设备(E5)分别报告。现有授权与可用环境决定能做哪些；未运行写NOT RUN，不为了凑阶段停住已能完成的交付。

新版用preview/e2e；旧版同层用preview-samelayer与正式包重放；旧版原生针对KV/气泡/主题入口测试。真实目标站使用当前可用浏览器工具，不要求安装某个固定bsk CLI。读取工具文档后，按54的“观察→操作→观察→截图”执行。

每个复现项列原卡表现、本项目表现、证据与限制；只测试声明支持的动作。编辑/删除/回溯在自带同层基座未实现，不列成必过动作来迫使AI伪造能力。能否调用、可见结果、服务端保存分别核对。



## 6. 约定复现项的验收清单

### 格式层

- [ ] 环境正确；新版独立包写1，旧版包无该键
- [ ] 旧版恰好四键 / 新版五必填加可选personality，无跨格式字段
- [ ] 每规则四键；旧版id=-1，新版负整数
- [ ] 名称/正则/替换长度在限内
- [ ] 无 BOM、无裸换行、JSON 合法

### 点火层

- [ ] 起点字段（`statusbar` 或 `beginning`）里有第一个标记
- [ ] 标记链连续，无跳号
- [ ] 链尾无残留
- [ ] 每条规则都点火（除 AI 输出触发）
- [ ] launcher 校验载荷完整

### 结构层

- [ ] 分片没切在转义序列中间
- [ ] `$` 已转义（没被当捕获组）
- [ ] `<` 已转义（没提前闭合 `</script>`）
- [ ] 单例 / 版本守卫 / 幂等
- [ ] 卸载清理干净

### 体验层

- [ ] 首屏不空（有封面或首条内容）
- [ ] 每个按钮有反馈；连点 10 次不变形
- [ ] 浮层四态可收（移开/滚动/点别处/切页）
- [ ] 手机无横向滚动，底栏不遮输入
- [ ] 状态解析失败不清零

### 证据层

- [ ] 已执行的S阶段与E证据分别标注
- [ ] 截图留档（PC 1440 / 手机 390）
- [ ] 未验证项写明原因

## 7. 常见"假通过"

| 假通过 | 真相 |
|---|---|
| 本地 `file://` 打开正常 | 平台是 https 注入，跨源与 CSP 全不同 |
| 无头浏览器截图正常 | 字体回退、模糊、层级可能不同 |
| 控制台无报错 | 静默丢弃的规则不会报错 |
| 规则都"跑了" | 跑了不等于命中；命中不等于渲染 |
| 手机上"能看" | 能看不等于能点；触摸热区可能被遮 |
| 用户说"可以" | 他只看了首屏，没玩第三轮 |

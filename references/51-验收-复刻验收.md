## 1. 从平台原始数据到可导入 JSON

平台的原始数据是接口给的（`role` + `regexp`），字段名和导出格式不一样。转换有四条硬规则：

| 规则 | 原因 |
|---|---|
| 按 `regexSort` **升序**排 | 平台 `loadRoleRegex()` 里会 `reverse()` 后执行；导出要还原成执行顺序 |
| `id` 重编号为 `-1,-2,…` | 导入时平台会再编号，重复 id 会乱序 |
| `beginning` 优先取 `beginningZh` | `beginning` 常是占位（"第一句话"），中文环境实际读 `beginningZh` |
| `chatVersion` 归一成 `0` 或 `1` | `Number(x) >= 1 ? 1 : 0`，不要原样透传 |

```bash
node scripts/export-raw.mjs --role role.json --regexp regexp.json --out card.json
```

产出：`card.json`（旧版 4 键必填，带 `personality` 时 5 键）或 6 键（若原始 `chatVersion=1`，仍建议手动确认）。

## 2. 逆向分析任意一张卡

```bash
node scripts/analyze.mjs card.json --out work/analysis
```

输出：

```
analysis/
├── analysis.md      规则表 / 架构判定 / 分片统计 / 动作命中 / 字段嗅探
├── analysis.json    机器可读
└── chunks/          （A 型）还原出的 host.js / frame.js
```

判定逻辑：

| 特征 | 判定 |
|---|---|
| 规则里出现 `s.h=(s.h??'')+"` / 通用 `+="` 累积 | 分片链（A 型） |
| `beginning` 里有一串 `<tag>`，规则 `findRegex` 正好是 `/<tag>/` | 标签模块（B 型） |
| 只有 1~3 条大规则 | 单体（谨慎：可能是压缩产物） |

分析报告会给出：规则数、总字数、单条最大、标记链是否连续、是否有残留标记、`chatVersion`、原生动作命中数。

**用途**：拿到任何一张"好卡"，先用它拆结构，再决定学哪一部分。

## 3. 点火重放（交付前必跑）

平台的替换算法必须逐字复刻，否则你以为点火了，实际没有：

```js
// 1. findRegex.trim()，去掉首尾反引号
// 2. 命中 /^\/(.+)\/([gimsuy]*)$/ → 正则；缺 g 自动补
// 3. 不命中 → 字面量 replaceAll
// 4. /…/ 语法错 → 整条静默丢弃（不降级）
// 5. replaceString 支持 $1、$名字、{{random:甲::乙::丙}}
```

```bash
node scripts/replay.mjs card.json --from auto
```

报告四项：

- 点火数 / 总数
- 未命中列表（**必须为空**，除非该规则靠 AI 输出触发）
- 残留标记（`【…】` / `<tag>`）
- 产物长度与 `<script>` 块数

退出码非 0 = 有残留或关键规则没点火。

## 4. 打包旧版同层卡

```bash
node scripts/pack-samelayer.mjs \
  --host work/src/host.js \
  --frame work/src/frame.js \
  --out work/out --name my-card --theme mytheme
```

它会：

1. 转义（`<`→`\u003c`、`$`→`\x24`、`\`、`"`、换行）
2. 按 19000 字安全切片（避开转义序列）
3. 生成 init + h 片 + f 片 + launcher
4. 输出 4 键必填 JSON（可带 `chatVersion:0`）+ manifest

打包后**立刻跑 replay**，链尾有残留就是切片或转义错了。

## 5. 测试阶梯（按顺序，不得跳）

| 级 | 做什么 | 通过标准 | 能证明什么 |
|---|---|---|---|
| **S1 方案** | 一页方案 + 线框 | 用户确认 | 方向对 |
| **S2 原型** | 独立 HTML，假数据，无宿主 | 浏览器打开能走完主流程 | 布局/交互成立 |
| **S3 模拟** | `preview.mjs` 仿平台壳（宿主 mock） | 全分区可点、双端断点正常 | 逻辑接得上 |
| **S4 真浏览器** | 用户提供测试链接 + bsk 黑盒测试 | 真实渲染、真实滚动、真实触摸、原生动作可见生效 | 不是"本地看起来对" |
| **S5 真机/真平台** | 导入 MMD，玩三轮 | 无白屏、无静默失效 | 可交付 |

### S4 用 BrowserSkill 怎么做

**先要链接**：用户必须提供可访问的测试链接（平台卡预览页 / 已发布页 / 用户起好的服务）。没有链接不测。

完整命令（session/navigate/observe/screenshot/emulate/evaluate/console/stop）、黑盒用例表与证据模板见
[54-验收-真实平台测试](54-验收-真实平台测试.md)。最小流程：

```
1. 向用户要测试链接，确认打开的是目标卡
2. bsk session start --json → 记 session_id
3. bsk navigate "<用户链接>" --session <id> → bsk observe
4. bsk screenshot（PC）→ bsk emulate --device iphone-14 → screenshot（手机）
5. 黑盒走查：导航/面板/消息编辑删除回溯/会话/人设/指令/设置/输入发送/二次进入
6. bsk evaluate 只读指标（scrollWidth / elementFromPoint / fonts）→ bsk console
7. bsk session stop <id>
```

**黑盒纪律**：只点界面、只看可见结果；不读内部变量、不调内部方法、不用 localStorage 制造通过。

**S4 的意义**：无头浏览器和真实 Chromium 在字体、滚动、`backdrop-filter`、`position:fixed` 上会不一样。示例卡的视觉全靠这些细节，S3 过了不算过。

### 不得跳的原因

- S2 过 → 只证明"静态布局对"
- S3 过 → 只证明"假宿主下逻辑对"
- S4 过 → 只证明"真浏览器渲染对"
- S5 过 → 才证明"平台注入与原生桥接对"

**把 S3 写成 S5 是本 skill 最严重的话术错误。**

## 6. 100% 复现的判据（逐条打勾）

### 格式层

- [ ] `chatVersion` 正确（旧 0 / 新 1）
- [ ] 旧版 4 键必填 / 新版 6 键，无多余键
- [ ] 每规则 4 键，`id` 唯一负数
- [ ] 名称/正则/替换长度在限内
- [ ] 无 BOM、无裸换行、JSON 合法

### 点火层

- [ ] 起点字段（`statusbar` 或 `beginning`）里有第一个标记
- [ ] 标记链连续，无跳号
- [ ] 链尾无残留
- [ ] 每条规则都点火（除 AI 输出触发）
- [ ] launcher 校验载荷完整

### 结构层

- [ ] 分片没切在转义序列中间
- [ ] `$` 已转义（没被当捕获组）
- [ ] `<` 已转义（没提前闭合 `</script>`）
- [ ] 单例 / 版本守卫 / 幂等
- [ ] 卸载清理干净

### 体验层

- [ ] 首屏不空（有封面或首条内容）
- [ ] 每个按钮有反馈；连点 10 次不变形
- [ ] 浮层四态可收（移开/滚动/点别处/切页）
- [ ] 手机无横向滚动，底栏不遮输入
- [ ] 状态解析失败不清零

### 证据层

- [ ] S2–S5 分别标注
- [ ] 截图留档（PC 1440 / 手机 390）
- [ ] 未验证项写明原因

## 7. 常见"假通过"

| 假通过 | 真相 |
|---|---|
| 本地 `file://` 打开正常 | 平台是 https 注入，跨源与 CSP 全不同 |
| 无头浏览器截图正常 | 字体回退、模糊、层级可能不同 |
| 控制台无报错 | 静默丢弃的规则不会报错 |
| 规则都"跑了" | 跑了不等于命中；命中不等于渲染 |
| 手机上"能看" | 能看不等于能点；触摸热区可能被遮 |
| 用户说"可以" | 他只看了首屏，没玩第三轮 |

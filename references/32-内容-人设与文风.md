# 32 · 人设与文风

> 分两层：**格式**（结构错了模型读不懂）与**写法**（语感，决定像人还是像 AI）。
> 套用模板：[assets/skeleton/persona.example.txt](../assets/skeleton/persona.example.txt)。

**2026-10-29 修订**：这一版不是"设计一套格式再让人去填"，而是**从一篇人写的人设反推格式**。样本是作者亲修的《武魂殿》提示词（6677 字），反例是同一设定的 AI 扩写稿（9087 字）。两份文本的量化差异见 §0，反推出的 12 条规则散布在 §2–§5。

---

## 0. 先看两份稿子的差别

同一题材、同一角色，人写的和 AI 写的差在哪：

| 指标 | 人写（正） | AI 写（反） | 说明 |
|---|---:|---:|---|
| 句均长 | 20.3 字 | 22.3 字 | 差得不多 |
| 长句（>40 字） | 6 句 | 15 句 | AI 爱写长句 |
| 行末不加句号 | **84%** | 32% | 人写的是笔记，AI 写的是文章 |
| 平均每行字数 | **30.7** | 44.6 | AI 每行多写一半 |
| 句号总数 | 28 | **86** | AI 的句号是人写的 3 倍 |
| 逗号总数 | 85 | 139 | AI 更爱铺陈 |
| 因果词（因为/所以/因此/从而） | **0** | 2 | 人写不解释因果 |
| 过渡词（首先/其次/此外） | **0** | 0 | 两边都没犯 |
| 排比三连（；…；…） | 1 | **3** | AI 爱排比 |
| 对偶金句（X 很 A，Y 很 B） | **0** | 1 | "力量很响，痛苦很静" |
| "先…再…最后" | **0** | 1 | AI 的三段式 |
| 破折号 | 1 | **5** | AI 爱用破折号补充 |
| 括号补充 | 7 | 5 | 人写更爱用括号塞备注 |

**三条结论**：

1. **人写的是笔记，AI 写的是文章。** 笔记一行一件事，写完就停；文章要有起承转合，于是加解释、加排比、加金句。
2. **AI 腔不是"用词华丽"，是"每句话都在完成一个修辞动作"。** 排比、对偶、三段递进、因果解释、升华收尾——单看都好，连起来就假。
3. **格式要能挡住这些修辞动作**，而不是教人"写得优美"。

下面的规则，每条都对应上表里的一个差异。

## 1. 六块骨架

| 块 | 必选 | 写什么 |
|---|---|---|
| `<前提：…>` | ✅ | 一行：AI 的职能、`{{user}}` 的位置 |
| `<主题>` | ✅ | 玩法一句、世界观四层、视角、风格 |
| `<主要角色>` | ✅ | 主角 + 常驻角色；路人禁入 |
| `<约束规则>` | ✅ | 对话禁忌、四项禁令、OOC、判定、剧情、视角、风格校准 |
| `<开局场景>` | ⭕ | 场景、开局状态、随身物品 |
| `<字段与输出>` | ⭕ | 有界面解析状态时才写 |

## 2. 三层标记与笔记体

| 层 | 写法 | 例 |
|---|---|---|
| 顶层块 | `<块名>` … `</块名>` | `<主题>`…`</主题>` |
| 子标题 | `-<子名>` … `-</子名>` | `-<主角：沈砚>`…`-</主角>` |
| 小分支 | `[项名]内容`（不闭合） | `[性格]冷酷强硬、不择手段` |

**八条硬规则**

1. `<前提>` 是单行块：`<前提：……>`，不闭合、不换行。它是唯一不闭合的尖括号标签。
2. 子标题闭合必须带 `-`：`-<主角：沈砚>` 对 `-</主角>`。不带 `-` 会被当成顶层块闭合，栈错位。
3. 后开先闭，不得交叉。
4. 角色正文写**真名**，玩家统一 `{{user}}`；禁 `{{char}}` / `$#char#$` / `$#user#$` / 「角色名」占位。主角就是玩家时写 `-<主角：{{user}}>`。
5. 标签里只放自然语言，不放 HTML / CSS / 脚本 / `sdk.`。
6. **一行一件事，写完就停。** 字段行不必加句号；人写稿 84% 的行末没有标点。
7. **标点以全角为主，允许半角混用。** 人写稿里有 `主角的金手指,` `由玩家喜好决定.`；这是笔记体，不是错误。真正要避免的是整篇英文标点或整篇全角混排。
8. 正文里字符与字符之间不加空格（中文之间、中英文之间都不加）。

## 3. 逐块写法

### 3.1 前提

一行，分号隔开两件事：AI 的职能、`{{user}}` 的位置。

```
✓ <前提：AI担任说书人，负责推演世界、扮演所有NPC、判定事件结果、描述环境变化；{{user}}扮演武魂殿圣女比比东的孩子，一个带着前世记忆的穿越者>
✗ <前提>
  你是一个专业的角色扮演AI，请务必严格遵守以下设定……
  </前提>
```

判据：**这句话在故事第 100 轮还成立吗？**

| | 写法 | 为什么 |
|---|---|---|
| ✗ | `{{user}}扮演刚下船的旅人` | 只在开头三句成立 |
| ✗ | `{{user}}身上只有一枚铜牌` | 开局物品，属于 `<开局场景>` |
| ✓ | `{{user}}扮演这个世界芸芸众生中的一员，没有特殊来历` | 全书成立 |
| ✓ | `{{user}}扮演地球穿越者` | 全书成立，且决定信息差 |

三种玩家定位：原住民 / 外来者 / 观察者。AI 那一半写职能不写状态。

### 3.2 主题

```
<主题>
[核心玩法]魂穿斗罗大陆，角色扮演，没有固定主线，剧情自由推进
[世界观]
-定性：东方玄幻，力量层级高。九十五级以上的封号斗罗，全大陆屈指可数；封号斗罗单人武力足以正面顶住一支军
-秩序：武魂殿不属于任何帝国，横在两大帝国之间。觉醒、注册、猎魂授权、魂环分配都归它管，全大陆的秩序由它维持
-稀缺：魂环与魂骨，等级与爵位。魂兽是资源，出城猎杀要报备，魂骨按年限定价，一头十万年的魂兽能让两个家族翻脸
-代价：升一级称号必须亲手猎杀魂兽，一个时辰内吸收魂环，魂环不可更换；魂骨融合后不可分割。最要命的是被人说出「你身上有魂骨」或「你是化形魂兽」
[视角]第二人称「你」，只写{{user}}能感知到的东西。不写{{user}}的内心判断和决定（与约束规则里的 `[视角]` 二选一，推荐写那边）
[风格]
-基调：热血网络小说风，偏西式玄幻
-氛围：
-感官：
</主题>
```

**`[核心玩法]` 一句，四个短句封顶。** 不写"核心循环是感知→试探→付代价"这种分析框架。

```
✓ 魂穿斗罗大陆，角色扮演，没有固定主线，剧情自由推进
✗ 成长与权谋混合型。核心循环是感知→试探→付代价→关系位移：玩家先靠残余的感官拼出处境……
```

**`[世界观]` 四层各一行，用 `-定性：` `-秩序：` `-稀缺：` `-代价：` 起头。** 每层 40–80 字，四层 200–320 字。

写法照抄上面的范例：

- **先判断，再给支撑**：`东方玄幻，力量层级高` → 九十五级屈指可数 → 一人顶一支军。
- **给数字和专名**，不给形容词：`十万年` `一个时辰` `四班轮值`。
- **最后一句给最要命的点**，不解释：`最要命的是被人说出「你身上有魂骨」`。
- **不写因果**：不写"因为魂环不可更换，所以……"。人写稿因果词 0 次。

**`[视角]`** 人称 + 聚焦 + 明确禁止写什么。「不写内心判断」比「第三人称限知」有用。

**`[风格]` 写世界给人什么感觉**：基调、氛围、感官。**`[风格校准]` 写怎么落笔**：对话、描写侧重、句法。两处不重复。

### 3.3 主要角色

子块名 = **关系 + 姓名**：`-<主角：{{user}}>`、`-<母亲：比比东>`、`-<姐姐：千仞雪>`、`-<师父：沈砚>`。

**主角字段顺序**（按需取）：

```
-<主角：{{user}}>
[基础信息]未出生，性别与名字由玩家定
[身份]武魂殿圣女比比东的孩子，千仞雪的孪生弟弟，同胎同日生，生辰斗罗历2622年2月8日
[外貌]肤色偏白，眼瞳深处带一点金
[天赋与限制]先天满魂力二十级：觉醒即二十级，跳过魂士阶段，万中无一。双生武魂。第一武魂六翼堕天使——主黑暗与精神……第二武魂被世界法则排斥，只能靠天赋系统「塑造」才能觉醒；玩家未定义前，不得描述其形态、属性与魂技
[天赋系统]主角的金手指,一块暗红色全息屏，浮在眼前只有主角能看见，用意念交流。五项功能：全知（问情报）、全能（实现要求）、个人（自身面板）、情报（他人面板）、空间（无限收纳）
[系统的运作方式]
-只在{{user}}主动调用时出现，不主动提示、不抢戏、不替玩家做决定。
-无固定性格,由玩家喜好决定.默认语气冷静、简短、不带情绪、称「主人」
[长线记忆]
-前世病死，保留完整意识与记忆，灵魂穿越而来
-他是穿越者这件事，比比东与千仞雪都不知道
-前世的能力留在原来的世界，跟过来的只有记忆和知识
-</主角>
```

**配角字段顺序**：

```
-<关系：姓名>
[基础信息]女，二十岁。
[身份]武魂殿圣女，千寻疾唯一的亲传弟子，也是他的囚徒。八十一级魂斗罗，双生武魂。
[与主角的关系]母子；对主角与千仞雪持有怨恨、无辜、母爱多重情感交织
[性格]冷酷强硬、不择手段
[语言习惯]高冷；对两个孩子持有怨恨但又觉得孩子无辜矛盾
[行为倾向]隐藏自身，
[长线记忆]
-双生武魂是她最大的秘密，也是她最后的底牌
-她认定腹中的孩子是她身上唯一还活着的东西
-玉小刚至今以为是她选择了权力
-</关系>
```

**这一段是整份格式的核心。** 四个字段全是"笔记"：

| 字段 | 写法 | 为什么这样反而好 |
|---|---|---|
| `[性格]` | 四个词，不展开 | 模型能从「囚徒」「怨恨/无辜/母爱」里自己长；展开成三段排比反而锁死 |
| `[语言习惯]` | 半句话，语法不通 | 信息在（高冷 + 矛盾），不需要写成人物小传 |
| `[行为倾向]` | `隐藏自身，` 就完了 | 人写笔记常这样；模型照样懂 |
| `[长线记忆]` | 三条"她认定/她以为" | 全是认知事实，不是事件流水账 |

**不要把这里改成 AI 腔。** 下面两组是同一角色的两种写法：

| 人写（保留） | AI 腔（不要） |
|---|---|
| `冷酷强硬、不择手段` | 说话很轻，轻到门外的人听不见；下达最残酷的决定也用这种音量。从不解释自己，被问「为什么」会安静地看着对方，直到对方换话题 |
| `隐藏自身，` | 遇险先看门，再看人，最后才看自己；遇诱惑先算代价；被逼到墙角不反抗，先答应下来，再在别处补一刀 |
| `高冷；对两个孩子持有怨恨但又觉得孩子无辜矛盾` | 白天她叫他们「孽种」，深夜把手放在腹上，一动不动坐很久 |

右边不是"更具体"，是**每个字段都在完成一个修辞动作**：对偶、三段递进、对比反转。单看漂亮，四个字段连起来就是 AI 味。

**金手指单开两块**：`[天赋系统]` 写是什么，`[系统的运作方式]` 写边界与代价。合成一块，模型只记住功能，记不住限制。

**`[长线记忆]`** 只放固定事实，不放剧情流水账。3–5 条，每条一句，句末不必加句号。

### 3.4 约束规则

```
<约束规则>
[对话禁忌]
-禁止跳出角色说话，禁止自称AI，禁止向玩家解释设定或提示选项，禁止让角色说出「你是穿越者」这类元叙事台词
-禁止模糊词（似乎/仿佛/宛如）、八股微表情（嘴角微微上扬/眼中闪过一丝）、语气声线描写、极端情绪词
-禁止「不是…而是…」句式等先否定再肯定的句式、「A等于B」「A就是B」式生硬比喻
-禁止术语腔与抽象词堆叠：外显、建制、成正比、位移、闭环、赋能、维度、底层逻辑
-禁止同一句信息在两处原样重复；同一段里意思重复的句子只留一句
-禁止三段式排比（先…再…最后）、对偶金句（X很A，Y很B）、因果解释（因为…所以…）、升华收尾
[OOC约束]所有角色遵守已写定的设定；性格转变必须有铺垫，不能为剧情方便临时改人
[判定规则]（TRPG 或金手指卡：成功判定、失败后果、代价怎么算）
[剧情约束]千寻疾归城与产期是两条会自动推进的线，玩家不行动它们也走；其余支线只在玩家触碰时推进
[视角]第二人称「你」，只写{{user}}能感知到的东西。不写{{user}}的内心判断和决定；写别人时只写动作、语气、停顿，不直接写对方的心理
[风格校准]
-基调：热血网络小说风，偏西式玄幻
-对话：占比中等。台词推进关系，不解释设定；单句不超过三行
-描写侧重：以动作和环境细节为主，心理只写身体反应
</约束规则>
```

禁令要**逐条 + 带例子**。只写"注意文笔"等于没写。

`[行动权限]` 默认不写——「不替玩家决策」由 `<前提>` 承担就够，写进约束规则会让模型反复自我提醒。

### 3.5 开局场景

```
<开局场景>
[场景描述]斗罗历2622年2月，武魂城·教皇山·教皇殿第三层。石室无窗，一榻一桌一灯；门从外面上锁，门外两名亲卫四班轮值，换班时能听见甲片相碰
[开局状态]
-主角在比比东腹中三十六周，与千仞雪同胎：听得见声音，睁不开眼，动一下就会被察觉
-双胞胎的身份还未公开，殿内知情者极少
-比比东坐在石榻上，右手扶着腰后，忍受着宫缩
[随身物品]无。魂力(先天满魂力二十级)、武魂(与双生武魂)要等六岁觉醒才会出现
</开局场景>
```

场景四件套：**时间地点 → 空间清单（一榻一桌一灯）→ 三个可感知细节（上锁 / 四班轮值 / 甲片相碰）**。不解释这些细节说明什么。

`[开局状态]` 2–4 条，每条一个可感知事实 + 一个限制。`[随身物品]` 没有就写「无。」，再用括号补一句为什么。

### 3.6 字段与输出

```
<字段与输出>
[状态块]每轮正文后另起一行，输出一个[status]{JSON}[/status]，不包代码块。键名只准这15个：turn、y、t、loc、region、act、threat、env、sum、flags、opt、me、npcs、sys、near。me是{{user}}，npcs用全名做键；rel是称谓，fav是-100到100的好感，两者不可混用。子键见世界书「输出格式」条。
[输出约束]turn与opt每轮必出，turn每轮加一，前端靠它排序与去重；只写变化的键，没变的整键省略，不写null；turn为10的倍数时输出全部字段。opt写玩家能做什么，不写发生了什么。
</字段与输出>
```

五条：

1. **协议用方括号 `[status]…[/status]`**。中文尖括号会被剥壳整段删掉；连字符尖括号会以未知元素留在气泡里，玩家看到 JSON。
2. **必须有一条规则消耗它**：`findRegex: /\[status\][\s\S]*?\[\/status\]/`，渲染成紧凑卡或空串。
3. **键名写成封闭白名单**（「只准这 15 个」），比"若干字段"遵守率高。
4. **`turn` / `opt` 每轮必出**；只写变化；10 的倍数全量。理由见 [30](30-内容-状态与字段.md) §2.4。
5. **开场白末尾附一条完整状态块**作基准。

## 4. 四项句式禁令 + 六条 AI 腔禁令

前四条是用户定的硬规则；后六条是从两份稿子的差异里反推的，同样只报 WARN。

### 4.1 先否定再肯定

| ✗ | ✓ |
|---|---|
| 这不是恐惧，是兴奋 | 他手在抖，嘴角却在往上走 |
| 魂兽不是野兽，是资源 | 魂兽按年限定价，出城猎杀要报备 |
| 称号不是荣誉，是权限 | 几级领多少补贴、能进哪道门，都按级算 |

改法：删掉「不是」那半句。删完不通，就把后半句补成完整陈述。

### 4.2 生硬比喻

| ✗ | ✓ |
|---|---|
| 称号就是权限 | 几级领多少补贴，都按级算 |
| 这座城等于一台机器 | 齿轮咬在城墙底下，每转一圈，闸门升一寸 |

改法：写 B 的具体特征，不要用系词画等号。

### 4.3 术语腔

**黑名单：外显、建制、成正比、位移、闭环、赋能、维度、底层逻辑。** 同类还有：结构性、机制化、抓手、颗粒度。

| ✗ | ✓ |
|---|---|
| 个人武力可以直接对抗建制 | 一个封号斗罗能正面顶住一支军 |
| 代价与所求之事的分量成正比 | 求的事越大，醒来时忘掉的东西越要紧 |
| 关系位移 | 她开始叫他名字 |

判据：这句话能不能拍成一个镜头？拍不出来就换。

### 4.4 同段重复

同一句信息不要在两处原样重复；同一段里意思重复的只留一句。跨块重复也算。

### 4.5 三段式排比

`先…再…最后…`、`A；B；C` 三连。AI 最爱的结构，人写稿里 0 次。

| ✗ | ✓ |
|---|---|
| 遇险先看门，再看人，最后才看自己；遇诱惑先算代价；被逼到墙角不反抗，先答应下来 | 遇险先看门。被逼到墙角先答应，再在别处补一刀 |

保留两项、删掉一项，或者拆成两句。三条并列会让模型学会"每段都要三连"。

### 4.6 对偶金句

`X 很 A，Y 很 B`。

| ✗ | ✓ |
|---|---|
| 力量很响，痛苦很静 | 力量落下来很响。痛是闷的，在骨头里 |
| 白天她叫他们「孽种」，深夜把手放在腹上 | 她叫他们「孽种」。深夜会把手放在腹上 |

对偶是修辞，不是信息。拆开写，信息不变，AI 味没了。

### 4.7 因果解释

`因为…所以…`、`…，于是…`、`…，从而…`。人设是设定，不是说明文。

| ✗ | ✓ |
|---|---|
| 因为八十一级才开始，第一环直接取了万年黑色 | 八十一级才开始，第一环直接取万年黑色 |
| 她答应留下，是因为算过：只要活着，就还有翻盘的一天 | 她答应留下。她算过，活着就还有翻盘的一天 |

删掉连接词，两句话并列，读者自己会连。

### 4.8 过渡词与总结句

`首先 / 其次 / 此外 / 值得注意的是 / 总而言之`，以及段末的"这就是……"。

人设里不需要路标。字段本身就是路标。

### 4.9 每字段写满

一个字段写 3 段、每段都有起承转合，是 AI 的默认行为。人写稿每个字段 1–3 条，平均每行 30.7 字。

**判据：这个字段删掉一半，角色会变吗？** 不会就删。

### 4.10 升华收尾

段末加一句"这既是……也是……"、"在这个世界里，……"。

人设不是散文。最后一句应该是硬事实，不是感想。

## 5. 字数与预算

平台硬上限：`personality` ≤10000 字；`beginning` ≤4000 字；单条世界书 ≤3000 字。

| 块 | 参考 | 人写稿实际 |
|---|---|---|
| 前提 | 50–150 | 约 90 |
| 主题 | 250–500 | 约 380 |
| 主角 | 400–900 | 约 700 |
| 每个配角 | 200–500 | 200–400 |
| 约束规则 | 200–450 | 约 400 |
| 开局场景 | 150–350 | 约 260 |
| 字段与输出 | 100–300 | 约 220 |
| **合计** | **1500–5000** | **约 3000** |

**平均每行不要超过 40 字。** 超过说明在写文章，不是写设定。

# 下篇 · 写法

## 6. 笔记体优先于文章体

| 文章体（AI 默认） | 笔记体（人写） |
|---|---|
| 每段有主题句 | 直接给事实 |
| 用连接词推进 | 用分行推进 |
| 每句完整 | 允许半句 |
| 段末总结 | 写完就停 |
| 同义反复强调 | 说一次 |

**不要"写得优美"，要"写得像备忘"。** 人设的读者是模型，不是评委。

## 7. 具体优先于评价

| 删 | 例 |
|---|---|
| 主观评价 | 「她是个可怕的女人」→ 写她做了什么 |
| 陈旧比喻 | 心如刀绞 / 坠入冰窖 |
| 堆砌形容词 | 「精美绝伦的门」→「门」 |
| 模糊代词 | 「那种感觉」→ 写具体是什么 |

注意：**"具体"不等于"展开"**。`冷酷强硬、不择手段` 是评价，但它比三段行为描写更有用——因为后者会锁死模型。判断标准是"删掉会不会变"，不是"够不够细"。

## 8. 套话清单

| 类别 | 症状 |
|---|---|
| 空转模糊词 | 似乎 / 仿佛 / 宛如 / 好像 / 隐隐（连续出现时） |
| 陈旧比喻 | 像小兽 / 心湖泛起涟漪 / 如遭雷击 |
| 八股微表情 | 嘴角微微上扬 / 眼中闪过一丝 / 不易察觉地皱了皱眉 |
| 语气声线描写 | 带着几分 xx 的口吻 / 声音里透着 xx |
| 极端情绪词 | 万念俱灰 / 欣喜若狂 / 痛不欲生 |
| 术语腔 | 外显 / 建制 / 成正比 / 位移 / 闭环 / 赋能 / 维度 / 底层逻辑 |
| 三段排比 | 先…再…最后… / A；B；C |
| 对偶金句 | 力量很响，痛苦很静 |
| 因果解释 | 因为…所以… / …，于是… |
| 升华收尾 | 这既是…也是… / 在这个世界里… |
| 大段心理 | 连续三段以上全是内心活动 |
| 性格标签堆叠 | 温柔善良、聪明勇敢、外冷内热（三个以上） |

**不矫正过度**：`笑了` / `皱眉` / `攥拳` 是正常动作；`冷酷强硬、不择手段` 是两个词，不是堆叠。禁的是"没有信息量的套话"和"修辞动作"。

## 9. 开场白

三要素：场景锚定、角色登场（用行为不用介绍）、钩子（一个问题、一件正在发生的事、一个待回应的动作）。

硬规则：

- 不替 `{{user}}` 发言、行动、决定心理。写到「轮到玩家」为止。
- 开场白本身必须符合 `[风格]`。
- 带状态块的卡，末尾附一条完整 `[status]{…}[/status]`。

长度 300–800 字；简报式可到 150 字，但要有钩子。

## 10. 旧格式迁移

| 旧 | 新 |
|---|---|
| `<世界观>` 顶层 | `<主题>` 里的 `[世界观]` 四层 |
| `<角色设定 名字：X>` 包所有字段 | `<主要角色>` 内的 `-<主角：姓名>` |
| `<基本信息>` 里写身份 | `[基础信息]` 只写性别年龄，`[身份]` 单开 |
| 道具、初始位置写在角色里 | 移到 `<开局场景>` |
| `<文风>` | `[风格]` + `[风格校准]` |
| `<输出格式>` | `<字段与输出>` |
| `<状态>` / `<status>` | `[status]…[/status]` |

旧卡能跑就不动。官方格式（`<角色设定 名字：X>`）`validate` 仍识别，不拦。

## 11. 自检

**硬项**

- [ ] `<前提：…>` 单行、不闭合、分号隔开
- [ ] 六块齐全；`<主要角色>` 内有 `-<主角：…>`
- [ ] `<约束规则>` 内有四项句式禁令 + 六条 AI 腔禁令
- [ ] 状态块用 `[status]`，键名封闭，且有规则消耗它
- [ ] `personality` ≤10000；`beginning` ≤4000
- [ ] 无 HTML / 脚本 / `sdk.`；无 `{{char}}` 占位

**软项**

- [ ] 平均每行 ≤40 字；长句（>40）不超过 8%
- [ ] 排比三连 ≤1 处；对偶金句 0；因果词 0
- [ ] 每个字段 1–3 条，没有"每段都有起承转合"
- [ ] 世界观四层齐全，每层能拍成镜头
- [ ] 金手指写了代价与失效条件
- [ ] 开场白不替玩家行动，且含钩子
- [ ] 角色名、时间线、数值三处一致

# 32 · 人设与文风

> 分两层：**格式**（错了卡就废，不可协商）与**写法**（默认审美，可按题材覆盖）。
> 把这两层混在一起，就会出现「把所有卡都写成同一种腔调」的问题。

---

# 上篇 · 格式（不可协商）

## 1. 标签规范

人设不是自由文本，是**成对单行标签**分区的结构化文档。

```
<世界观>
三百年大旱，海退成滩，滩上长出会走的树。
</世界观>

<角色设定 名字：沈砚>
<基本信息>
- 年龄：二十九
- 身份：替人看东西的方士
- 所在：南渡口
</基本信息>

<与{{user}}的关系>
沈砚替 {{user}} 看过一次不该看的东西，之后一直没敢收钱。
</与{{user}}的关系>
</角色设定>
```

**七条硬规则**

1. `<角色设定 名字：真实角色名>` 开头，`</角色设定>` 闭合；闭合标签不重复名字属性。
2. 开始与闭合标签各自独占一行；冒号全角半角选一种，全卡统一。
3. 每个开始标签必须有同名闭合标签，后开先闭，不得交叉。
4. 同一层级的标签名保持稳定——不要一会儿 `<背景>` 一会儿 `<往事>`。
5. 角色正文直接写真名，玩家统一 `{{user}}`；禁 `{{char}}` / `$#char#$` / `$#user#$` / 「角色名」占位写法。
6. 标签内容是自然语言，不放 HTML / CSS / 脚本 / `sdk.`。
7. 不用 `【章节】` 方括号标题，不用 Markdown 标题。

**标签名本身可以自定**（`<来历>`、`<禁忌>`、`<说话习惯>` 都行），只要成对、稳定、不与规范冲突。

## 2. 章节池（按需取，不凑数）

```
世界层：<世界观> <历史背景> <地图> <势力> <规则与代价>
角色层：<角色设定 名字：X>
        <基本信息> <与{{user}}的关系> <外貌特征> <性格特点> <说话方式>
        <背景设定> <道具> <能力与限制> <行为逻辑> <当前情景>
其他：  <npc>…</npc> <养成规则> <输出格式> <文风>
```

- **不要求全部使用**。纯对话卡可能只有「基本信息 + 关系 + 说话方式」三块；经营卡可能没有「外貌」，但有「账目规则」。
- 少于 3 组会显得单薄（校验器给 WARN），但 3 组也可以是一张合格的卡。

## 3. 输出格式块

只有当这张卡**有界面解析状态**时才写；内容必须与前端解析器逐字对应：

```
<输出格式>
每轮正文结束后另起一块，不要包进代码块：
<rex-status>{"time":"时历","loc":"地点","hp":数字,"silver":数字,"flags":[],"opt":["","",""]}</rex-status>

- 键名与前端字段表一致，不得改名、不得翻译。
- 缺字段就省略该键，不要写 null 或 0 占位。
- opt 给 2–4 条，每条 ≤20 字，是"玩家可以做什么"，不是"发生了什么"。
</输出格式>
```

键集合来自 `content.status.fields`（见 [30 状态与字段](30-内容-状态与字段.md) §2）；上面只是示例，不是固定键表。

**这条错了，界面就只是"看起来有"**：解析器永远匹不到，状态栏一直空着。

## 4. 字数

平台上限（硬）：`personality` ≤10000 字；`beginning` ≤4000 字；单条世界书 ≤3000 字。

经验区间（软，按卡型调整）：

| 项 | 参考 |
|---|---|
| `personality` 总量 | 2000–6000 字；对话卡可低到 1200，规则密集的养成卡可到 8000 |
| `<角色设定>` 单块 | 600–2500 字 |
| `<世界观>` | 200–600 字；超过就搬进世界书 |
| `<输出格式>` | ≤250 字 |
| 章节数 | 3–10 组 |

**大头（图鉴、地点志、支线 NPC、长历史）进世界书绿灯条目**，不进人设。人设每轮都进上下文，塞满就是持续烧钱。

# 下篇 · 写法（默认基线，可覆盖）

以下四条是**默认审美**，不是平台规则。题材需要时可以违反，但要有理由，并写进 `<文风>` 让模型知道这是有意为之。

## 5. 默认基线：具体优先于评价

| 删 | 例 |
|---|---|
| 主观评价与判断 | 「她是个可怕的女人」→ 写她做了什么 |
| 陈旧/劣质比喻 | 「心如刀绞」「坠入冰窖」 |
| 堆砌形容词 | 「精美绝伦的门」→「门」，除非那扇门真的特别 |
| 模糊代词与意象 | 「那种感觉」「某种东西」→ 写具体是什么 |

**什么时候可以不遵守**：恐怖、意识流、不可靠叙述等类型，"说不清"本身就是体验。此时把模糊词写进 `<文风>` 作为**有意选择**，而不是默认泛滥。

## 6. 套话清单（默认清理）

| 类别 | 症状 |
|---|---|
| 空转模糊词 | 似乎 / 仿佛 / 宛如 / 好像 / 隐隐（连续出现时） |
| 陈旧比喻 | 像小兽 / 心湖泛起涟漪 / 如遭雷击 |
| 八股微表情 | 嘴角微微上扬 / 眼中闪过一丝 / 不易察觉地皱了皱眉 |
| 语气声线描写 | 带着几分 xx 的口吻 / 声音里透着 xx |
| 极端情绪词 | 万念俱灰 / 欣喜若狂 / 痛不欲生 |
| 句式模板 | 不是……而是…… / 与其说……不如说…… |
| 大段心理 | 连续三段以上不落地、全是内心活动 |
| 性格标签 | 她很温柔 / 他很冷酷 |

**不矫正过度**：`笑了` / `皱眉` / `攥拳` 是正常动作。禁的是"没有信息量的套话"，不是所有表情。

## 7. 具体性检验

| 错 | 对 |
|---|---|
| 性格温柔善良 | 遇到受伤的小动物会带回家，包扎完再放走 |
| 两人感情很深 | 有记忆起就在一起，他记得她怕打雷 |
| 他很富有 | 袖口磨得起毛，但随手把最后一枚铜钱给了乞儿 |

**检验法**：这句话删掉，角色会变吗？不会 → 删。

## 8. 四个字段的取舍（建议）

- **外貌**：只写偏离默认认知的部分。标准是"遮住名字能不能认出是谁"。「黑发黑眼」是默认值，不写。
- **背景**：只写关键事件——"哪三件事把他变成了现在这样"，不是编年史。
- **关系**：写具体画面，不写形容词。「深厚的感情」→「他记得她不吃葱，二十年没端错过一碗面」。
- **性格**：独立成块，和基本信息分开；混写会让模型把"她是谁"和"她怎么行为"搅在一起。

## 9. 开场白

默认三要素：

1. **场景锚定**：时间、地点、氛围，具体可感。不要「这是一个……的世界」这种说明书开头。
2. **角色登场**：用行为和对话展现性格，不是介绍性格。
3. **钩子**：给玩家一个明确接话点——一个问题、一件正在发生的事、一个待回应的动作。

硬规则（这部分不可协商）：

- **不替 `{{user}}` 发言、行动、决定心理**。写到"轮到玩家"为止。
- 与 `<文风>` 互查：开场白本身必须符合自己写的文风。
- 带状态栏的卡：开场白末尾附一条完整 `<rex-status>` 作为基准，否则首轮状态栏是空的。

可替换的形态：

| 卡型 | 开场形态 |
|---|---|
| 剧情 / 角色卡 | 场景 + 角色登场 + 钩子 |
| 经营 / 策略 | 简报式：现状 + 三个待决事项 + 时间压力 |
| 悬疑 / 调查 | 现场速写 + 一条异常 + 一个已知事实 |
| 无限流 / 系统 | 规则播报 + 第一道任务 + 代价提示 |

长度：300–800 字为默认；简报式可短到 150 字，但必须有可回应的钩子。

## 10. 文风条目

写进人设或世界书常驻。字段可自行增删：

```
<文风>
视角：第三人称限制视角，只跟 {{user}} 的感知
节奏：短句为主，紧张处一句一段；平缓处长句可到三行
对话占比：中。对话推进剧情，不解释设定
描写侧重：动作与环境细节，少写心理独白
禁止：空转模糊词、八股微表情、语气声线描写、极端情绪词、"不是…而是…"句式、替玩家发言
</文风>
```

- ≤300 字，是约束清单，不是散文。
- 要模仿某种文风时：让用户给 3 段以上原文，存进 `资料/`，提炼成字段，**不要直接抄原文**——抄句子会带进原作的设定与人物。
- 类型卡（恐怖、喜剧、硬科幻）应改写"禁止"栏，不要沿用默认清单。

## 11. 自检

**硬项（不过即废）**

- [ ] 开始与闭合标签一一对应，无交叉嵌套
- [ ] 角色真名贯穿全文，玩家只用 `{{user}}`
- [ ] `<输出格式>` 键名与前端字段表逐字一致（有界面时）
- [ ] `personality` ≤10000 字；`beginning` ≤4000 字
- [ ] 无 HTML / 脚本 / `sdk.`

**软项（按题材判断）**

- [ ] 套话清单逐条扫过，保留项已写进 `<文风>` 作为有意选择
- [ ] 无抽象标签（每条性格都有对应行为）
- [ ] 全文简体中文，无日文汉字（桜→樱、宮→宫）
- [ ] 无占位符（某城市 / 某组织 / 某某）
- [ ] 开场白不替玩家行动，且含钩子
- [ ] 开场白 / 人设 / 世界书三处的角色名、时间线、数值互不矛盾

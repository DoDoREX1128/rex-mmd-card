# 32 · 人设由作品与作者决定

默认自由格式。用户已有正文、章节、标签和文风直接沿用；需要重构时解释理由和影响，不把任何固定模板当平台要求。

可选方式：自由短文适合关系与氛围；字段/笔记适合高密度设定；YAML适合配置式事实；成对标签适合分章节；混合方式适合大型世界。没有规定必须六块、必须以“前提”开头、必须把性格写成行为或禁止写成标签。

先确定本次需要的信息：角色身份、动机与矛盾、关系边界、语气、能力限制、长期事实、开局处境。只写有用部分，可增删合并章节。人物可以有细腻因果、修辞、较长句或完整段落。结构自由不等于内容含糊：关键事实应可辨认、互相一致。

角色名优先用真实名称，玩家占位用 {{user}}；旧平台占位符需要按当前入口转换。模型侧内容不要塞可执行脚本。正文不要为了显示格式而混入 HTML/CSS/SDK；自然语言讨论这些词不自动判危险代码。

笔记体是可选 preset：压缩重复、保留有辨识度的事实、少套话。用户选择它时，--style-lint 可提供句式与长度提示；行长、句号、因果词、修辞都不是硬指标，更不能由此识别“人写/AI写”。不强制把禁令清单放进每张人设或世界书。

有界面解析需求时才添加输出协议。统一 [status]；新版 JSON 字段声明要与解析器一致，旧版 KV 另写其编码约定。协议可以独立成条，也可放在用户自定义结构的某节，不必迁整个正文。

开场白遵循用户选择的视角与节奏，写到可回应处。玩家行动权限按角色扮演约定，不默认替玩家决定。长度由体验与平台上限共同决定，不强制300–800字。

示例只示范一种可能：

    守船人负责渡口，寡言，记得常客的习惯。
    他愿意冒险送人过河，但不会拿同行的性命赌输赢。
    {{user}} 的行动由玩家选择。

也可以改成诗性叙述、人物小传、列表或作者自己的格式。修改已有稿件时保留其意图，格式检查与内容质量分别讨论。

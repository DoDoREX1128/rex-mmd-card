# 24 · 旧版事实（chatVersion:0）

> 适用范围：旧版原生增强卡、旧版同层卡。新版（`1`）的事实见 [21](21-平台-新页事实.md)，两者的结论**不可互相套用**。
> 表格式数值以 [23-平台-事实表](23-平台-事实表.md) 与 `facts.json` 为准；本文只写机制、陷阱与边界。
> 证据标注：`【源码】` 源码确证 · `【实机】` 实机实测 · `【手册】` 官方文档 · `【待验证】`

---

## 1. 与新版的分界

| | 旧版 | 新版 |
|---|---|---|
| 脚本载体 | 逐消息可用 onerror；文档级初始化可用 script | `<script>` 装卡抽取、整卡一次 |
| 选择器 | 平台 class（会变） | `[data-chat]` / `[data-slot]`（承诺不改名） |
| 应用架构 | 自建层或 iframe 接管 | 官方 SDK + 舞台 |
| 存档 | 本地作用域 | `sdk.save` 服务端、跨设备 |
| 原生动作 | Host按目标逐项适配，不是默认61项 | 仅公开SDK能力 |

旧版没有新版SDK，调用可能报错或被封装吞掉，不能依赖；新版卡里写 `iframe` 会被白名单直接删除。

## 2. 导入结构

- 顶层**恰好四键**：`pageDepth` / `statusbar` / `beginning` / `regex_scripts`。
- **不要带 `chatVersion` 与 `personality`**：旧版独立正则 JSON 里出现这两个键，官方口径判 ERROR（洛璃 `validate.py` 实测："多出 chatVersion、personality"）。`chatVersion` 只在新建卡导入整卡时用于分流，不属于这份四键包。
- 每条规则恰好四字段：`id` **固定 `-1`**、`scriptName`、`findRegex`、`replaceString`。写 `-2` 会被判错（"id 必须为整数 -1"）。
- `pageDepth` 固定 `2`。

```json
{
  "pageDepth": 2,
  "statusbar": "【RexHUD 001】",
  "beginning": "雨还在下。",
  "regex_scripts": [
    { "id": -1, "scriptName": "init", "findRegex": "/【RexHUD 001】/", "replaceString": "<div class=\"hud\">…</div>" }
  ]
}
```

## 3. 点火：`img onerror`

### 3.1 位置

点火器必须位于**容器内部**、最外层容器的闭合标签**之前**。放在容器外时 `img.closest('.container')` 返回 `null`，整段脚本一行都不会执行，页面无提示。`【实机】`

### 3.2 引号与编码

HTML属性与属性内JavaScript是两层语法。外层单引号可配内部双引号；外层双引号可配内部单引号。同类裸引号会提前结束属性。生成HTML时对完整属性值做实体编码，不能仅靠换引号处理用户输入。

例如容器内部的固定代码：

```html
<div class="rex-native"><img src="data:," onerror='this.closest(".rex-native").setAttribute("data-ready","1");this.remove()'></div>
```

JSON.stringify的输出应按嵌入位置编码，HTML属性与内部JavaScript的引号分别转义。复杂引擎尽量用自给自足入口与动态事件绑定。



### 3.3 多行与语法

- 属性值可带换行，写成正常多行函数。`【实机】`
- ES6 在 `img onerror` 载体内可用：箭头函数、`let/const`、模板串、解构、展开、可选链均通过。`【实机】`
- 引号内的 `<`、`>`、`=>` 是纯文本，比较运算、`for` 循环、箭头函数都可正常使用。`【实机】`

### 3.4 `onclick` 净化

属性值只能是「干净的调用/引用表达式」：

| 放行 | 被净化 |
|---|---|
| `window.__fn&&__fn()` | `eval('…代码…')` |
| `eval(getElementById('FUNC').dataset.s)` | `this.x='y'` |

复杂逻辑改为动态绑定事件处理器。`【实机】`

## 4. 渲染

### 4.1 空白条

旧版气泡容器 `.content` 带 `white-space:pre-line`，注入 HTML 标签之间的换行会被当作真实换行，每个撑一行行高。实测：三段 `div` 之间带换行时高度 102px，子元素本身合计 51px。`【实机】`

两种有效修法：

1. 注入 HTML 标签之间不留换行；
2. 在自己容器上写 `white-space: normal`（推荐）。

无效的旧修法：`p:empty{display:none}`、`br{display:none}`（实测没有 `p:empty`，也没有 `br`）。Shadow DOM **不免疫**——`white-space` 是继承属性，需在 shadow 内写 `:host{white-space:normal}`。`【实机】`

### 4.2 元素 ID

同一父文档内重复实例中的 HTML 元素 ID 需有独立实例后缀，时间戳只是可选方案，命名 `类型_功能_时间戳`（如 `BUTTON_SAVE_1729584719271`）。同一模块内所有 ID 用同一时间戳；`data-s` 引用的 ID、`<label for>` 与目标 `input` 必须一致。重复 ID 是「第二次打开就失效」的根因。`【实机】`

独立 iframe 内可用局部 ID，不与父文档冲突。

### 4.3 Markdown

正则跑在 Markdown 渲染之前，替换产物会再过一遍 Markdown：

- HTML 不要缩进四空格；
- Markdown保留字符需按上下文转义；数学内容可运行时写入textContent，不为避Markdown改变运算含义；
- 反引号里的 HTML 会原样成文本。

## 5. 层级（z-index）

旧版没有统一安全带，按需压过谁：

| 节点 | z-index |
|---|---|
| 总结剧情面板 | 1000000000 |
| 长按菜单 `.msg-option-scope` | 99999 |
| 其余弹窗 | 10075 |
| 两侧容器 `.mm-left/right-side-container` | 9999 |
| `.chat-bottom` / `.scroll-view` | 999 |
| `.chat-scope-box` | 11 |
| `.modify-btn-scope` | 2 |

浮层要压过两侧容器取 10000 以上，压过弹窗需更高，但不得越过 99999 的长按菜单。数值来自实机样式表穷举，平台改版后需复测。`【实机】`

## 6. 同层卡边界

| 项 | 结论 |
|---|---|
| 形态 | 文档级单例建立隔离 iframe + 原生桥接；Host 读原生 DOM 并触发原生操作，Frame 不碰平台 DOM |
| 原生动作 | 参考上游包含61项，当前基座只实现基础动作；未实现的如实返回 `not-implemented`，不做假入口 |
| 注入链 | 默认**独立点火**：全部标记一次性写进 `beginning`，每条规则只认自己那一个。链式点火在「每条规则各自作用于原文」的语义下只有第一条命中 |
| 分片 | 单条 19000 字（预留 wrapper 与标记），按原串字符的转义成本切片后编码，不切断转义序列 |
| 存档 | 按作品 / 账号 / 角色 / 会话分区；不承诺跨设备同步 `【待验证】` |
| 禁止 | 混入新版字段或 `sdk.*`；用新版稳定选择器解释旧版 DOM |

构造与打包见 [22-平台-同层卡架构](22-平台-同层卡架构.md)；工具 `pack-samelayer.mjs`。

## 7. 旧版常见静默失败

1. `onerror` 放在容器外 → 整段脚本不执行；
2. 双引号包裹且内部有裸双引号 → 引擎不绑定；
3. 点火器位置正确但 `closest()` 选择器拼错 → 同上；
4. 重复实例ID冲突 → 后续定位或label关联可能错误；
5. 标签之间的换行没消除 → 每个换行多出一行高度；
6. `findRegex` 不带斜杠 → 控制台测试能过，聊天页不替换（旧版对形态更严格）；
7. 规则引用 `sdk.*` → 不报错、不生效；
8. 分片切在转义序列中间 → 整条语法错、静默丢弃。


## 8. 旧版原生最小工具与选型

assets/native 提供轻量KV状态卡与作用域CSS；init --route native，build --route native，validate --platform legacy。默认协议是[status]hp::数值;;loc::地点[/status]，与新版JSON外壳相同、编码不同；如改JSON须同步解析器、说明、转义和样例。

纯文字无需JS；KV卡仅显示数据；逐消息引擎需要各容器点火和清理；文档级主题/场景单例另处理。旧版原生卡也能按需求加存档，不以“原生”推定永远无需持久化。旧版同层Host的scope不能随便拿来给另一作品复用。

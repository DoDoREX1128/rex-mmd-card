## 1. 机器校验（`validate.mjs`）

校验项与阈值来自 `facts.json`，不是文档里手写的常量；改了 `facts.json` 后 `validate` 与 [23-平台-事实表](23-平台-事实表.md) 同时生效。

### ERROR（必须修，不修不算交付）

**结构**

- JSON 语法错（含 BOM）
- `chatVersion` 与 `--platform` 不符：旧版为 1、新版不为 1
- 顶层缺必填键；出现当前版本的禁用键（旧版混入 `entries` / `chatVersion` / `personality`，新版混入 `worldbook` 等）
- 规则不是数组、不是恰好 4 键、`id` 不是负数；旧版 `id` 不是固定 `-1`
- `scriptName` / `findRegex` / `replaceString` / 状态栏 / 开场白 / 人设越界；规则数 > 130

**匹配式与点火**

- 写成 `/…/` 但正则语法错（平台静默丢弃整条）
- 字面量匹配式重复（后一条永不命中）
- 可见 UI 的标记不在 `beginning` / `statusbar` 里（界面永不出现）
- 产物里有未被任何规则匹配的注入标记（会原样显示给玩家）
- 内容协议 `[rex-status]` 没有被任何规则消耗（模型每轮吐的 JSON 会原样显示）
- `findRegex` 里出现 `<script>` / `<style>`

**SDK 与 CSS**

- 能力名不在 30 项清单内；用了不存在的能力（`once` / `off` / `theme.set` / `memory`）
- `sdk.vars` / `vars:change` 不在此列：它们是契约未补齐，判 WARN，不判不存在
- 事件名不在 12 项清单内
- `<style>` 里出现全局选择器 `*` / `html` / `body` / `:root`

**人设与世界书**

- 人设出现 `<script` / `<style` / `sdk.`；用了 `{{char}}` / `$#char#$` / `$#user#$`
- 世界书 `entries` 是数组、`key` 不是 JSON 编码字符串、`uid` 重复、单条正文 > 3000

> 人设的**格式**问题（标签未闭合、交叉嵌套、缺骨架、缺 `[句式禁忌]`、命中四项禁令）自 2026-10-29 起全部降为 WARN，不阻断交付。格式由 Agent 按 [32](32-内容-人设与文风.md) 自查，门禁只管平台会坏的东西。

### WARN（逐条说明或修掉）

- 人设缺 `{{user}}`；成对标签 < 3 组；出现【章节】标题或 Markdown 标题
- 人设标签未闭合/交叉、缺骨架、缺 `[句式禁忌]`、命中四项禁令（先否定 / 生硬比喻 / 术语腔 / 同段重复）
- `sdk.vars` / `vars:change`：契约未补齐，可以讲边界，不能编造签名
- 人设首块既不是 `<前提>`（v2）也不是 `<角色设定>`（旧式）
- 人设里残留 ✅ / ⭕ 选型标记（模板标记不该进产出）
- 注入标记仍用尖括号 `<rex-…>`（建议改 `【rex-…】`）
- 字面量匹配式以 `/` 开头但形态不合法；或含元字符（走字面量分支会被转义）
- z-index 落在 1000–3499 空档，或越过 7999
- 出现未知 `--chat-*` 变量；别名变量被写死色值
- 静态标记里出现自写 `data-*`；四空格缩进的 HTML；白名单外标签
- `sdk.on` 写进 `message:mount` 回调；在 `message:mount` 里读 `message-body`
- 世界书 `comment` > 20 字；`probability` 写成数字
- 顶层出现导入页不认识的键

完整规则以 `validate.mjs` 与 `facts.json` 的 `silentFailures` 为准。

## 2. 点火重放（`replay.mjs`）

用平台的替换算法逐条实现，把 `beginning`（或 `statusbar`）当输入跑一遍全部规则：

- 期望：标记串按依赖顺序全部命中；脚本类规则即使不被正文命中也会装卡（它们的匹配式故意不被引用）
- 不得有残留：`【rex-xxx】` 出现在产物里 = 该条没命中
- 分片链（旧版同层卡）最后一条 launcher 未命中 = 断链，直接失败
- 产物里 `<script>` 数量应等于模块数（脚本被抽出是正常的）

## 3. 模拟台（E3）：能力精度与模型沙盒

`preview.mjs` 生成的是仿平台外壳，除布局外还模拟两类行为，用于在本地暴露「真机上才会出现」的问题。

### 3.1 能力精度三档

| 档 | 含义 | 进入方式 | 用法 |
|---|---|---|---|
| **exact** | 按已确证的平台行为模拟：事件顺序、载荷形状、`stage.el()` 返回 DIV、`save` 往返 | 默认 | 日常回归 |
| **conservative** | 只保证保守子集：瘦预览矩阵（`save.get` 同步抛错、`cache.get` 返回 undefined、写类能力 NOT_SUPPORTED） | `?profile=thin` | 交付前门禁 |
| **probe-needed** | 平台事实未确证（如 `sdk.vars`）：不模拟签名，不判不存在 | 见 [23](23-平台-事实表.md) 与 [25](25-平台-SDK速查.md) §6 | 写进风险清单；讲行为边界可以，编造参数不行 |

判断新卡是否会因降级而整段失效：带 `?profile=thin` 打开，若出现脚本整体不执行或白屏，说明能力调用没有兜底。

### 3.2 模型沙盒

`?preset=ok|badjson|missing|empty` 或开发条按钮，直接投一轮模型输出：

| 预设 | 内容 | 期望界面行为 |
|---|---|---|
| `ok` | 合法状态块 | 正常渲染 |
| `badjson` | 截断的 JSON | 保留上一份有效状态，不白屏、不清零 |
| `missing` | 只有部分字段 | 只更新出现的字段，其余保留 |
| `empty` | 空正文 | 不触发错误提示，不推进结算 |
| `stream` | `message:new → stream×N → done` | 流式更新，收尾只结算一次 |

事件顺序与载荷按 [23](23-平台-事实表.md) §3；`?cold=1` 可补发冷启动序列（`message:new → mount → done → ready`），用于验证「`ready` 最后到且不补发」的处理是否正确。

### 3.3 诊断面板

`?dev=1` 打开开发条，点「诊断」显示：当前 profile、已触发事件计数、最近调用的能力、模型预设记录、运行时错误。它回答的是「到底哪一步没跑」，不替代截图与人工判断。

## 4. 人工冒烟（E3，本地）

先跑机器版：`node scripts/e2e.mjs`（自动生成测试页、找 Chrome 无头跑、按 PASS/FAIL 打分，退出码非 0 即有失败）。当前覆盖 32 项：封面、捏人 7 字段、入局只写输入框不代发、手机抽屉贴边、里层热区气泡、残缺状态不清零、切宽屏并排。

机器跑不了的（观感、真机）再手点。**按开局形态取用**（形态定义见 [44](44-界面-捏人协议.md) §0），不要全表照跑：

**通用（所有卡）**

| # | 动作 | 通过标准 |
|---|---|---|
| 1 | 首次进入 | 不是空白/白屏，第一眼知道在哪、是谁 |
| 2 | 发送一轮 | 开场白出现，至少一位角色有反应 |
| 3 | 首轮状态 | 有状态呈现（气泡卡或状态栏），不是空的 |
| 4 | 逐个面板开合 | 能开能关，返回键逐层退 |
| 5 | 切到别的会话再切回 | 状态还在（未重置） |
| 6 | 手机 375px | 不横向滚动；底栏不遮内容 |
| 7 | 瘦预览（创卡页） | 写类能力不可用属预期；`save.get` 被 `try/catch` 包住，无整段失效 |
| 8 | 坏输出（`?preset=badjson`） | 保留上一份有效状态，不清零、不白屏 |

**形态 A · 封面 + 捏人**

| # | 动作 | 通过标准 |
|---|---|---|
| A1 | 封面进入 | 淡出后进捏人，不闪白 |
| A2 | 捏人逐项选择 | 每项有预览，选项带后果说明 |
| A3 | 入局 | 生成提交文本块，**没自动发送** |
| A4 | 必填未完成 | 按钮不可点，不是点了报错 |

**形态 B · 单屏轻捏人**

| # | 动作 | 通过标准 |
|---|---|---|
| B1 | 一屏内完成选择 | 无需翻页，选择有后果提示 |
| B2 | 修改已选项 | 能直接改，返回不丢 |

**形态 C · 直接开局**

| # | 动作 | 通过标准 |
|---|---|---|
| C1 | 首条即正文 | 没有空封面、没有空捏人页 |
| C2 | 身份揭示 | 若身份由剧情揭示，前三轮内有明确线索 |

**PC 宽屏（B/C 也适用）**

| # | 动作 | 通过标准 |
|---|---|---|
| 9 | 1440px | 布局不撑破；文本行长不超过 80 字符 |

## 5. 废卡症状对照（排查用）

现场速查用。**根因、处置、证据、版本在 [错题本](errors/index.md)**，本节不重复维护细节。

| 症状 | 最可能的原因 | 错题本 |
|---|---|---|
| 按钮全不响应、样式对一半、无报错 | 导入时没选「使用新版聊天页」 | — |
| 人设是空的 | `personality` 没另贴到「角色人设」——导入正则不读它 | E-008 |
| 状态栏第一轮有、后面不更新 | 人设里没写输出约定，模型不持续输出状态块 | — |
| 界面出现了但样式全无 | 标记没落在 `beginning` / `statusbar` 里，或匹配式里的尖括号被净化 | E-021 |
| 二次进入按钮点一次动两次 | 内核缺版本守卫 / 事件重复订阅 | E-030 |
| 存档被旧数据覆盖 | 用了闭包变量而不是 `window.__REX__` | E-015 |
| 某条规则永远不生效 | 字面量重复；或 `/…/` 语法错被静默丢弃；或超出 20000 字 | E-020 / E-022 |
| 浮层被舞台盖住 | z-index 落在 1000–3499 | E-017 |
| 手机上 HUD 挡住输入框 | `position: fixed` 没留 `padding-bottom`；或没避开 `--chat-viewport-height` | — |
| 换肤只变了气泡，底栏没变 | 只映射了 `bg/text/accent`，漏掉底栏与弹窗的 18 个变量 | E-019 |

排障顺序（按层，不按症状）见 [53](53-验收-真平台踩坑.md) §1。

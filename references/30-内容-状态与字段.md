# 30 · 状态与字段

> 本文管**「模型 → 前端」的数据通道**：块怎么定形、字段怎么设计、脏数据怎么裁、存档怎么版本化。
> 具体字段集合由卡的题材与核心循环决定，本文不规定你必须有哪些字段。

---

## 0. 先判断需不需要状态栏

不是每张卡都需要。

| 需要 | 不需要 |
|---|---|
| 存在会被反复读写、且会影响判定的数值（体力、金钱、好感、进度） | 纯文字互动，玩家自己记剧情 |
| 玩家要随时看到当前处境（地点、时间、状态标签） | 单场景短篇，一屏能读完 |
| 有跨会话的长期进度 | 一次性体验 |

不需要时，不要为了"看起来完整"硬加状态块——它会让模型每轮多输出一段 JSON，增加失败面。

---

## 1. 数据通道：三种承载方式

| 方式 | 做法 | 评价 |
|---|---|---|
| **正文块**（默认） | 模型在正文末尾输出一个结构化块，前端解析 | 唯一不依赖平台未公开能力的方案；本文按它写 |
| 平台状态变量 | `sdk.vars` / `vars:change` | **运行契约未公布**，不得据此写代码；只能写进风险清单 |
| 纯 DOM 推断 | 从正文里猜数值 | 不可靠，禁止用于会参与判定的数值 |

---

## 2. 块形状

### 2.1 不变量

1. **一个块、一次输出、正文末尾**；不散落在正文中间。
2. **块用固定标签包裹**，标签名全卡唯一（默认 `<rex-status>`，可换，但前端解析、人设声明、世界书三处必须一致）。
3. **块内是 JSON**：数组与嵌套结构用 KV 表达不了；代价是容错要求高（见 §4）。
4. **键名用英文**，显示名在 `content.status.fields[].label` 里配。中文键在模型输出里更容易被改写（`体力` ↔ `气血` ↔ `HP`）。
5. **键集合由字段表决定**，不是固定几个。下面这些是**可选保留键**，用了就遵守其语义：

| 保留键 | 类型 | 语义 | 是否必需 |
|---|---|---|---|
| `opt` | string[] | 玩家可选的行动（2–4 条） | 有选项 UI 时 |
| `loc` | string | 当前地点，须为地图节点名 | 有地图时 |
| `time` | string | 时历/时间 | 有世界时钟时 |
| `act` | string | 本轮动作摘要 | 有纪事/回顾时 |

除此之外的键全部来自 `content.status.fields`，例如体力、金钱、好感、怀疑度、进度。

### 2.2 字段设计：从核心循环倒推

按顺序问：

1. **每轮会变的量有几个？** 只保留每轮可能变的；不变的一次性写死进人设。
2. **哪些量会参与判定或分支？** 参与判定的必须有明确范围与阈值。
3. **玩家需要随时看到哪几个？** 这些进气泡卡；其余进舞台面板。

字段数量参考：

| 位置 | 建议数量 | 理由 |
|---|---|---|
| 气泡内状态卡 | 2–4 个 | 扫一眼能读完，多了等于没有 |
| 舞台完整面板 | 6–12 个 | 分组后一屏可读；超过 12 个考虑分页 |
| 每轮模型输出 | ≤8 个键 | 输出越长，格式出错率越高 |

字段类型只用四种，便于裁剪与渲染：

| 类型 | 用途 | 裁剪规则 |
|---|---|---|
| `bar` | 有上限的数值 | `clamp(0, max)`，取整 |
| `num` | 无上限计数（金钱、天数） | 取整，限制绝对值上限 |
| `tag` | 状态标签数组 | 最多 4–6 条，每条限长 |
| `text` | 短文本（地点、时间、称谓） | 截断到固定长度 |

### 2.3 字段库索引

同义字段漂移是长线卡最常见的隐性故障：`生命 / 血量 / HP` 同时存在，模型这轮改一个、下轮改另一个，玩家看到两个数字各说各话。

为此维护一个**不断生长的字段库**：`references/fields/`。

| 文件 | 作用 |
|---|---|
| [fields.json](fields/fields.json) | 唯一真源（118 条起） |
| [index.md](fields/index.md) | 按分类的索引表（生成，勿手改） |
| [README.md](fields/README.md) | 命名、分类、冲突组、生长与淘汰规则 |

**两层命名**（库里所有字段都遵守）：

- 语义名：**2–4 个汉字**，用于检索与显示（`体力`、`信任`、`名望`）；
- 运行时键：**2–4 个小写字母**，写进状态块 JSON（`sta`、`tru`、`rep`）。
- 超过 4 字的概念要压缩，去掉「值 / 度 / 当前 / 状态」这类后缀。

**用法**：

```bash
node scripts/field-add.mjs --find 体力        # 先查：有没有、近义是谁、属于哪个冲突组
node scripts/field-add.mjs --name 体力 --key sta --type bar --cat body --life 每轮      --range "0–100" --status core --alias 耐力,精力 --source luoli
```

查到就直接复用；查不到再登记。**一次只加一个**，批量加会绕过查重。

**十三个分类**：身份 / 生理 / 心理 / 欲情 / 关系 / 社会 / 资源 / 进度 / 战斗 / 空间 / 时间 / 物品 / 元。分类单选，按「这个字段主要被谁读取」归。

**冲突组**：生命组（生命/气血）、耐力组（体力/精力）、名望组（声望/名望/名誉）、货币组（金钱/货币）、受孕组（受孕/子宫）。同组只留一个主字段，其余写成别名。

**status 是证据强度，不是质量**：`core` 多份素材出现且是主干；`common` 出现但不常用；`niche` 特定题材；`supplement` 素材里没有、按常见玩法补的，用前先确认题材真需要。

**什么时候不要用库**：纯文字卡（没有状态栏）、一次性数值（只出现一轮）、平台已提供的字段（如 `sdk.user.get()` 的昵称）。库是候选池，不是必须填满的表。

## 3. 一个块的实际样子（示例）

```text
<rex-status>{"time":"第三日·酉时","loc":"南渡口","hp":62,"silver":18,"flags":["左臂受伤"],"opt":["去码头寻人","回客栈上药","留在原地观察"]}</rex-status>
```

这是某张江湖卡的字段集合；换一张经营卡，可能是 `{"day":12,"cash":320,"reputation":7,"stock":[...]}`。**形状不变，键可变。**

## 4. 解析：三级容错

```js
function parseStatus(raw, fields) {
  var s = String(raw || '').trim();

  // 一级：剥代码块、取最外层花括号
  s = s.replace(/^```[a-z]*\s*/i, '').replace(/```$/g, '');
  var a = s.indexOf('{'), b = s.lastIndexOf('}');
  if (a < 0 || b <= a) return null;
  s = s.slice(a, b + 1);
  try { return JSON.parse(s); } catch (e) {}

  // 二级：常见手滑修复
  var fixed = s
    .replace(/[“”]/g, '"')
    .replace(/[‘’]/g, "'")
    .replace(/，/g, ',')
    .replace(/：/g, ':')
    .replace(/,\s*([}\]])/g, '$1')
    .replace(/([{\[,]\s*)([A-Za-z_]\w*)(\s*:)/g, '$1"$2"$3');
  try { return JSON.parse(fixed); } catch (e) {}

  // 三级：只救 text 类字段（地点、时间等），宁缺勿错
  var out = {};
  (fields || []).forEach(function (f) {
    if (f.type !== 'text') return;
    var m = new RegExp('"' + f.key + '"\\s*:\\s*"([^"]{0,40})"').exec(s);
    if (m) out[f.key] = m[1];
  });
  return Object.keys(out).length ? out : null;
}
```

三级只救 `text` 类字段：数值类靠正则抠容易抠错，错误数值比缺失数值更危险。三级结果同样要过 §5 的白名单裁剪。

## 5. 白名单裁剪

模型返回的是**不可信数据**，只允许白名单字段进运行时：

```js
function clip(obj, fields) {
  if (!obj || typeof obj !== 'object') return {};
  var out = {};
  fields.forEach(function (f) {
    var v = obj[f.key];
    if (v === undefined || v === null) return;
    if (f.type === 'bar' || f.type === 'num') {
      var n = Number(v);
      if (!isFinite(n)) return;
      n = Math.round(n);
      out[f.key] = f.type === 'bar' ? Math.max(0, Math.min(f.max || 100, n)) : n;
    } else if (f.type === 'tag') {
      if (!Array.isArray(v)) return;
      out[f.key] = v.slice(0, 6).map(function (x) { return String(x).slice(0, 8); });
    } else {
      out[f.key] = String(v).slice(0, 40);
    }
  });
  if (Array.isArray(obj.opt)) out.opt = obj.opt.slice(0, 4).map(function (x) { return String(x).slice(0, 20); });
  return out;
}
```

**不允许 `Object.assign(data, obj)`。** 模型多吐一个 `__proto__` 或 `save` 键就能污染运行时；只过白名单。

---

## 6. 继承：缺字段不清零

```js
REX.data.status = Object.assign({}, REX.data.status, clipped);
```

`Object.assign` 的语义正好是「新的覆盖旧的、缺的保留」。**不要**先 `= {}` 再赋——模型漏一个字段时血条归零，玩家会以为被打死了。

漏字段时在面板上标一个淡色「继承」角标，让玩家知道这轮数据没给全，但不要弹错误。

---

## 7. 渲染：两处，同一份数据

| 位置 | 形态 | 更新时机 |
|---|---|---|
| 气泡内 | 紧凑卡（≤3 行，2–4 个核心值） | `message:done` 解析后立即替换 |
| 舞台面板 | 完整面板（分组 / 标签 / 地图入口） | 解析成功后更新；面板打开时增量刷新 |

- **气泡卡不要塞满**：只放玩家每轮都要看的。
- **不要每次 `innerHTML = ''` 重建**：走 `update(root, data)`，否则滚动位置与 tooltip 状态会丢。
- 数值变化用 300ms 过渡即可；不要做无限循环动画。

---

## 8. 自修复

| 故障 | 表现 | 处理 |
|---|---|---|
| 解析彻底失败 | 三级都返回 null | 气泡位置显示「本轮状态未读到」，**保留上一轮数值**；面板给「修正」入口 |
| 字段缺失 | 个别键没给 | 静默继承 + 淡色角标，不打断 |
| 值越界 | `hp: 9999` | `clamp` + `debug.log`，不弹窗 |

「修正」入口：左侧上一轮值、右侧本轮读到的值，玩家可逐字段手改或回滚；改完写进存档。

**不做**：自动猜玩家想要多少血。模型给错就让人改。

## 9. 存档：一个对象，版本化

```js
var SAVE_KEY = 'rex_save';
var SAVE_VER = 1;

function persist(immediate) {
  clearTimeout(REX._t);
  var write = function () {
    sdk.save.set(SAVE_KEY, { v: SAVE_VER, ts: Date.now(), data: REX.data })
      .catch(function (e) { sdk.debug.log('save fail', e && e.code); });
  };
  if (immediate) return write();
  REX._t = setTimeout(write, 300);
}
```

纪律：

- 存档键名由宿主动态下发，**不要写死数量**；一张卡只占一个名字，全进度塞进这个对象。
- 有频率限制：非关键变化防抖 300ms；**回合结算、玩家确认、离开面板立即写**。
- 读档校验 `v`：版本不一致走迁移；迁移不了给「新开」与「尽力读取」两个选择，**不要静默丢弃**。
- 只恢复白名单字段，不要直接把读到的对象当运行时状态。

## 10. 事件接线

```js
sdk.on('ready', function () { loadSave(); REX.goScene(hasSave() ? 'main' : 'cover'); });

sdk.on('message:done', function (msg) {
  var m = /<rex-status>([\s\S]*?)<\/rex-status>/.exec(msg.content || '');
  if (!m) return;
  var raw = parseStatus(m[1], CFG.status.fields);
  if (!raw) return showRepairHint();
  var clipped = clip(raw, CFG.status.fields);
  Object.assign(REX.data.status, clipped);
  if (clipped.opt) REX.data.opt = clipped.opt;
  renderBubbleCard(clipped);
  if (REX.panel() === 'status') updatePanel(clipped);
  persist(true);
});

sdk.on('conversation:switch', function () {
  sdk.cache.remove('rex_runtime');
  loadSave();
  REX.goScene(hasSave() ? 'main' : 'cover');
});

sdk.on('theme:change', function () { REX.applyTheme(); });
sdk.on('back', function () { return REX.back(); });
```

`ready` 最后到且不补发；`message:mount` / `message:done` 会补发历史。不要依赖 `ready` 做首屏渲染。

---

## 11. 静默陷阱

1. **在 `message:mount` 里读 `[data-chat="message-body"]` 当正文** → 读到「消息生成中」占位。正文用 `message:done` 的 `msg.content`。
2. **在 `message:done` 里无条件 `message.send`** → 自问自答死循环。要发必须由玩家手势触发。
3. **状态放在闭包里** → 界面显示新值、`sdk.save.set()` 写的还是旧副本。跨规则共享的状态放 `window.<命名空间>`。

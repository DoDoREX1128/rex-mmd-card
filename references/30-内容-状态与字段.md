# 30 · 状态与字段

> 本文管**「模型 → 前端」的数据通道**：块怎么定形、字段怎么设计、脏数据怎么裁、存档怎么版本化。
> 具体字段集合由卡的题材与核心循环决定，本文不规定你必须有哪些字段。

---

## 0. 先判断需不需要状态栏

不是每张卡都需要。

| 需要 | 不需要 |
|---|---|
| 存在会被反复读写、且会影响判定的数值（体力、金钱、好感、进度） | 纯文字互动，玩家自己记剧情 |
| 玩家要随时看到当前处境（地点、时间、状态标签） | 单场景短篇，一屏能读完 |
| 有跨会话的长期进度 | 一次性体验 |

不需要时，不要为了"看起来完整"硬加状态块——它会让模型每轮多输出一段 JSON，增加失败面。

---

## 1. 数据通道：三种承载方式

| 方式 | 做法 | 评价 |
|---|---|---|
| **正文块**（默认） | 模型在正文末尾输出一个结构化块，前端解析 | 唯一不依赖平台未公开能力的方案；本文按它写 |
| 平台状态变量 | `sdk.vars.get/set` / `vars:change` | 已确认存在（仅新页、6 层 80 键、按楼层回溯），但契约未公布参数与返回值；讲边界可以，编造签名不行 |
| 纯 DOM 推断 | 从正文里猜数值 | 不可靠，禁止用于会参与判定的数值 |

## 2. 块形状

### 2.1 不变量

1. **一个块、一次输出、正文末尾**；不散落在正文中间。
2. **块用固定标签包裹，标签名全卡唯一，并且必须被一条规则消耗**。使用 `[status]…[/status]`。人设声明、解析脚本、消耗规则三处必须逐字一致。不消耗的后果：模型每轮吐的 JSON 原样显示在气泡里。
3. 新版骨架默认块内JSON；旧版native示例用KV，适合少量平面字段。两者必须配套解析器，不能仅因外壳相同而混读。
4. 键名要稳定，显示名在content.status.fields[].label配置。英文、描述性长键或中文均可；当前骨架支持字母/下划线起始，后接字母、数字、下划线或连字符，总长≤64，排除原型污染键。防漂移靠声明、样例和校验，不强制2–4字母。
5. **键集合由字段表决定**，不是固定几个。下面这些是**可选保留键**，用了就遵守其语义：

| 保留键 | 类型 | 语义 | 是否必需 |
|---|---|---|---|
| `opt` | string[] | 玩家可选的行动（2–4 条） | 有选项 UI 时 |
| `loc` | string | 当前地点，须为地图节点名 | 有地图时 |
| `time` | string | 时历/时间 | 有世界时钟时 |
| `act` | string | 本轮动作摘要 | 有纪事/回顾时 |

除此之外的键全部来自 `content.status.fields`，例如体力、金钱、好感、怀疑度、进度。

### 2.2 字段设计：从核心循环倒推

按顺序问（以下数量是小型卡的设计建议，不是平台字段上限）：

1. **每轮会变的量有几个？** 只保留每轮可能变的；不变的一次性写死进人设。
2. **哪些量会参与判定或分支？** 参与判定的必须有明确范围与阈值。
3. **玩家需要随时看到哪几个？** 这些进气泡卡；其余进舞台面板。

字段数量参考：

| 位置 | 建议数量 | 理由 |
|---|---|---|
| 气泡内状态卡 | 2–4 个 | 扫一眼能读完，多了等于没有 |
| 舞台完整面板 | 6–12 个 | 分组后一屏可读；超过 12 个考虑分页 |
| 每轮模型输出 | 小卡可先控制约8个核心键 | 输出越长，格式出错率越高 |

当前默认解析器支持以下类型；库内其他候选类型需转换或扩展，不能只写配置就假定生效：

| 类型 | 用途 | 裁剪规则 |
|---|---|---|
| `bar` | 有上限的数值 | `clamp(0, max)`，取整 |
| `num` | 无上限计数（金钱、天数） | 取整，限制绝对值上限 |
| `tag` | 状态标签数组 | 最多 4–6 条，每条限长 |
| `text` | 短文本（地点、时间、称谓） | 截断到固定长度 |

### 2.3 字段库索引

同义字段漂移是长线卡最常见的隐性故障：`生命 / 血量 / HP` 同时存在，模型这轮改一个、下轮改另一个，玩家看到两个数字各说各话。

为此维护一个**不断生长的字段库**：`references/fields/`。

| 文件 | 作用 |
|---|---|
| [fields.json](fields/fields.json) | 唯一真源（118 条起） |
| [index.md](fields/index.md) | 按分类的索引表（生成，勿手改） |
| [README.md](fields/README.md) | 命名、分类、冲突组、生长与淘汰规则 |

**两层命名**（库里所有字段都遵守）：

- 语义名：字段库常用2–4个汉字，用于检索与显示（`体力`、`信任`、`名望`）；
- 运行时键：字段库常用2–4个小写字母作为候选，不限制项目自定义键，写进状态块 JSON（`sta`、`tru`、`rep`）。
- 若长名更准确可保留；显示标签与运行时key分开，不为缩写制造歧义。

**用法**：

```bash
node scripts/field-add.mjs --find 体力        # 先查：有没有、近义是谁、属于哪个冲突组
node scripts/field-add.mjs --name 体力 --key sta --type bar --cat body --life 每轮      --range "0–100" --status core --alias 耐力,精力 --source luoli
```

先检索语义与冲突组，再决定复用或自定义；不把候选库当固定必填表。库内登记仍用简短命名规则；项目长键/中文键可直接定义并同步协议，无需先入库。登记时带类型、生命周期与来源。

**十三个分类**：身份 / 生理 / 心理 / 欲情 / 关系 / 社会 / 资源 / 进度 / 战斗 / 空间 / 时间 / 物品 / 元。分类单选，按「这个字段主要被谁读取」归。

**冲突组**：生命组（生命/气血）、耐力组（体力/精力）、名望组（声望/名望/名誉）、货币组（金钱/货币）、受孕组（受孕/子宫）。同组只留一个主字段，其余写成别名。

**status 是证据强度，不是质量**：`core` 多份素材出现且是主干；`common` 出现但不常用；`niche` 特定题材；`supplement` 素材里没有、按常见玩法补的，用前先确认题材真需要。

**什么时候不要用库**：纯文字卡（没有状态栏）、一次性数值（只出现一轮）、平台已提供的字段（如 `sdk.user.get()` 的昵称）。库是候选池，不是必须填满的表。

### 2.4 变化字段、轮次与重生成

值用当前绝对值，不把hp:-15当扣15。模型协议明确字段全集、类型与空值语义；未变的键可省略，清空数组必须写[]。opt只在作品有选项时输出，不是所有卡每轮必填。

```text
第1轮 [status]{"turn":1,"hp":100,"loc":"南渡口","flags":[],"opt":["问船期","等一会"]}[/status]
第2轮 [status]{"turn":2,"hp":85,"opt":["上药","求助"]}[/status]
第3轮 [status]{"turn":3,"flags":["已包扎"],"opt":[]}[/status]
```

当前status.js：旧turn不覆盖新turn；相同turn+相同内容幂等；同轮不同内容按重生成处理，恢复该轮before再合并替代块。默认保存最近40份回合快照；这不是自动删除或回溯宿主消息。缺turn有兼容递增兜底，但正式模型协议应要求turn，不能把缺turn当可靠重放。

检查点可按复杂度周期输出全量（如每10轮），用于降低模型遗忘；它是写作/协议策略，不是脚本已实现的历史扫描。若项目需要历史重建，须确认消息身份、完整性、排序、同轮替代规则，再从可靠快照重放。不能因只加载到较旧历史，就自动判定玩家回溯。DOM序号不是持久身份。



## 3. 一个块的实际样子（示例）

```text
[status]{"time":"第三日·酉时","loc":"南渡口","hp":62,"silver":18,"flags":["左臂受伤"],"opt":["去码头寻人","回客栈上药","留在原地观察"]}[/status]
```

这是某张江湖卡的字段集合；换一张经营卡，可能是 `{"day":12,"cash":320,"reputation":7,"stock":[...]}`。**形状不变，键可变。**

## 4. 解析：三级容错

```js
// 解析思路示例；正式实现以assets/skeleton/status.js为准。
function parseStatus(raw, fields) {
  var s = String(raw || '').trim();

  // 一级：剥代码块、取最外层花括号
  s = s.replace(/^```[a-z]*\s*/i, '').replace(/```$/g, '');
  var a = s.indexOf('{'), b = s.lastIndexOf('}');
  if (a < 0 || b <= a) return null;
  s = s.slice(a, b + 1);
  try { return JSON.parse(s); } catch (e) {}

  // 二级：常见手滑修复
  var fixed = s
    .replace(/[“”]/g, '"')
    .replace(/[‘’]/g, "'")
    .replace(/，/g, ',')
    .replace(/：/g, ':')
    .replace(/,\s*([}\]])/g, '$1')
    .replace(/([{\[,]\s*)([A-Za-z_]\w*)(\s*:)/g, '$1"$2"$3');
  try { return JSON.parse(fixed); } catch (e) {}

  // 三级：只救 text 类字段（地点、时间等），宁缺勿错
  var out = {};
  (fields || []).forEach(function (f) {
    if (f.type !== 'text') return;
    var m = new RegExp('"' + f.key + '"\\s*:\\s*"([^"]{0,40})"').exec(s);
    if (m) out[f.key] = m[1];
  });
  return Object.keys(out).length ? out : null;
}
```

三级只救 `text` 类字段：数值类靠正则抠容易抠错，错误数值比缺失数值更危险。三级结果同样要过 §5 的白名单裁剪。

## 5. 白名单裁剪

模型返回的是**不可信数据**，只允许白名单字段进运行时：

```js
// 思路示例，不替代正式模块的安全key、类型、长度检查。
function clip(obj, fields) {
  if (!obj || typeof obj !== 'object' || Array.isArray(obj)) return {};
  var out = {};
  fields.forEach(function (f) {
    if (!/^[\p{L}_][\p{L}\p{N}_-]{0,63}$/u.test(f.key) || ['__proto__','constructor','prototype'].includes(f.key)) return;
    var v = obj[f.key];
    if (v === undefined || v === null) return;
    if (f.type === 'bar' || f.type === 'num') {
      if ((typeof v !== 'number' && typeof v !== 'string') || String(v).trim() === '') return;
      var n = Number(v);
      if (!isFinite(n)) return;
      n = Math.round(n);
      var max = f.max == null ? (f.type === 'bar' ? 100 : 1000000000) : f.max;
      var min = f.min == null ? (f.type === 'bar' ? 0 : -1000000000) : f.min;
      out[f.key] = Math.max(min, Math.min(max, n));
    } else if (f.type === 'tag' || f.type === 'tags') {
      if (!Array.isArray(v)) return;
      out[f.key] = v.slice(0, 6).filter(function (x) { return typeof x === 'string'; }).map(function (x) { return x.slice(0, 40); });
    } else if (typeof v === 'string') {
      out[f.key] = v.slice(0, Number(f.maxLength) || 120);
    }
  });
  if (Array.isArray(obj.opt)) out.opt = obj.opt.slice(0, 4).map(function (x) { return String(x).slice(0, 20); });
  return out;
}
```

**不允许 `Object.assign(data, obj)`。** 模型多吐一个 `__proto__` 或 `save` 键就能污染运行时；只过白名单。

---

## 6. 继承：缺字段不清零

```js
REX.data.status = Object.assign({}, REX.data.status, clipped);
```

`Object.assign` 的语义正好是「新的覆盖旧的、缺的保留」。**不要**先 `= {}` 再赋——模型漏一个字段时血条归零，玩家会以为被打死了。

可扩展：为继承值加淡色角标。当前默认骨架保留旧值，并未逐字段绘制“继承”标记。

## 7. 可选渲染方案：两处读取同一份数据

下表是设计方案，默认骨架隐藏原始状态块并更新聊天页内面板，不自动生成每轮紧凑气泡卡；增量渲染接口也需按项目实现。

| 位置 | 形态 | 更新时机 |
|---|---|---|
| 气泡内 | 紧凑卡（≤3 行，2–4 个核心值） | `message:done` 解析后立即替换 |
| 舞台面板 | 完整面板（分组 / 标签 / 地图入口） | 解析成功后更新；面板打开时增量刷新 |

- **气泡卡不要塞满**：只放玩家每轮都要看的。
- **不要每次 `innerHTML = ''` 重建**：走 `update(root, data)`，否则滚动位置与 tooltip 状态会丢。
- 数值变化用 300ms 过渡即可；不要做无限循环动画。

## 8. 自修复

| 故障 | 表现 | 处理 |
|---|---|---|
| 解析彻底失败 | 三级都返回 null | 默认提示未读到并保留上一轮值；修正面板是扩展项 |
| 字段缺失 | 个别键没给 | 默认继承；角标需项目扩展 |
| 值越界 | `hp: 9999` | 默认裁剪；详细诊断日志按项目扩展 |

可扩展的修复面板：左右对照旧值与本轮值，允许玩家修改并保存。当前默认实现为保留旧值、提示错误和显式restoreTurn；尚未提供逐字段编辑面板。

**不做**：自动猜玩家想要多少血。模型给错就让人改。

## 9. 模型、内存与存档三层分开

| 层 | 谁产生 | 内容 |
|---|---|---|
| 模型输出 | 模型 | 一份[status]业务patch与turn；不用输出slots/history等存储结构 |
| 运行时 | status.js | 白名单合并值、当前turn、重生成前后快照 |
| 持久化 | store.js | v3信封、auto、命名slots、settings；详见33 |

新版需要跨刷新保留就用sdk.save；cache不承担长期进度。旧版由有可靠scope的Host/原生运行时持久化，隔离Frame不直接使用父localStorage。缺存储或保存失败明确提示，不静默切后端。

默认新版message:done完成有效更新后立即请求保存；persist(false)另有300ms防抖。串行队列防旧写后到覆盖新写，但不保证永远不会撞目标限频；长输出期间不要逐帧保存。项目高频交互需预算合并与重试，不能说“有防抖就无限制”。

## 10. 新版事件接线与最终一致性

- 顶层订阅message:done，正文从msg.content取；不要从message:mount的占位文本提数值。
- build的status-hide只消耗展示数据块，解析仍读原始消息；两端标签固定[status]…[/status]。
- 人设或世界书写模型协议；只做UI也应交付独立protocol.txt，不能因没有persona.txt漏掉模型接线。
- 玩家字段与模型字段分开；派生值选一个权威源。程序计算的值不要又要求模型独立生成另一份。
- render后的DOM文本需要转义。模型字符串不能直接当HTML/事件处理器执行。

## 11. 本地与项目验收

- [ ] 正式发布包连续两轮能更新，状态原文不露出
- [ ] 数值仍为number；0合法；缺失、null、空串和[]按契约区分
- [ ] 坏JSON保留旧值；超界裁剪；未知/危险key不进入运行时
- [ ] 同轮重复不重复结算，同轮重生成不会继承被替代版本的副作用
- [ ] 显式恢复快照说明“旧聊天仍在”；截断历史不触发自动回退
- [ ] 模型说明、配置、解析器、隐藏规则、preview使用同一协议
- [ ] 若扩展地图/任务/NPC私有字段，逐项测试数据实际被解析与渲染；默认status.js不支持任意嵌套结构

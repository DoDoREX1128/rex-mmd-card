# 30 · 模型状态协议

先判断是否需要状态；纯文字和纯换肤不自动添加。协议外壳统一 [status]…[/status]。新版默认 JSON；旧版 KV 是另一种编码，模型说明与解析器必须成对选择。

字段由题材决定，字段库只供候选。runtime key 可读且稳定，不强制2–4字母；显示名不必等于 key。定义类型、范围、空值、默认值与权威来源。bar/num 保持数值，tag/tags 为字符串数组，text 为限长文本。

默认状态 JSON 包含 turn 整数；新轮次递增。业务字段可只写变化的绝对值，清空列表写 []，缺失字段继承。opt 仅在需要选项时提供。长线可定期输出完整检查点，间隔由模型与预算决定，不固定每10轮。

status.js 读 message:done 原文，修复有限常见标点，失败时只救声明的 text；不从坏文本猜数值。白名单字段才进状态，已知 NPC 单独投影。状态记录含 turn、serverId与快照；重复同块不重复结算，当前轮重生成先恢复该轮 before 再应用，新收到的旧轮次不会覆盖当前进度。

restoreTurn 显式恢复最近可用快照并说明是否精确；不靠截断的 DOM 最后一条就自动断定平台回溯。没有 SDK 回溯事件时不假装实时同步宿主删除；用户回溯需通过明确游戏恢复或项目专用已验证适配器重建。

build 隐藏规则与模拟模型使用同一 [status]。规则隐藏不等于数据解析成功，合同测试必须投至少两轮原始消息并检查数值变化、缺字段、空列表、坏JSON与旧轮次。程序规则权威字段不得由模型再维护第二份。

# 33 · 存档与续档

> 30 文档管「模型 → 前端」的状态通道；本文管「前端 → 存档 → 下次进入」的持久化，以及读旧档之后怎么让模型接上。
> 适用：新版沙盒卡（`sdk.save`）与旧版同层卡（`localStorage`）。旧版原生卡只有单场景时可不做多槽。

## 1. 三种真值来源，先选一个

| 来源 | 放什么 | 与剧情的关系 | 现在能用吗 |
|---|---|---|---|
| 平台状态变量（`sdk.vars`） | 需要模型知道、且要跟楼层回溯的数值 | 本轮进提示词；快照随消息存；回溯按楼层恢复 | 存在，但契约未公布；不写依赖它的代码 |
| `sdk.save` | 小游戏进度、手动槽、玩家设置 | 不自动进上下文；不随剧情回溯 | ✅ |
| `sdk.cache` | 展开状态、临时高亮、当次页面数据 | 刷新即失 | ✅ |

**同一个剧情数值只能有一个真值来源。** 平台变量与 `sdk.save` 各存一份，回溯后必然出现两份真值。现阶段默认全部走 `sdk.save`，等 `sdk.vars` 契约公布再迁移。

## 2. 存档结构：一个键装下所有槽

平台对存档键数量有限制（由宿主动态下发，**不要写死 10 个**），所以不要一个槽一个键。整张卡只占一个键，内部再分槽。

```js
{
  v: 2,                       // 结构版本，改字段时迁移
  updatedAt: 1730000000000,
  auto: {                     // 自动档：每次有效回合覆盖
    turn: 23,
    cur: { hp: 70, loc: '渡口' },
    recent: [ /* 最近 3 条纪事 */ ]
  },
  slots: [                    // 手动档：玩家命名
    {
      id: 's1',
      name: '第二章·渡口',
      ts: 1729999999999,
      summary: '第 23 轮，渡口，体力 70，刚接下委托',
      snap: { turn: 23, cur: {...}, log: {...}, tasks: [...], clues: [...], npcs: [...] }
    }
  ],
  settings: { choiceBehavior: 'stageDraft', fontScale: 1 }
}
```

四条纪律：

1. **槽位索引与快照打包进同一个对象**，不要每个槽一个 `sdk.save` 键。
2. **槽位数自定上限**（建议 6–8），满了让玩家删，不要静默覆盖最旧的。
3. **每个槽带 `name` / `ts` / `summary`**，界面要能显示"什么时候、到哪了、关键数值"。
4. **`auto` 与 `slots` 分开**：自动档可以被覆盖，手动档只能由玩家显式覆盖或删除。

## 3. 什么时候写

| 时机 | 写什么 | 是否立即 |
|---|---|---|
| 每轮解析成功 | 更新 `auto.turn` / `cur` | 防抖 300ms |
| `turn % 10 === 0` | 往 `log` 追加完整快照 | 防抖 |
| 玩家确认关键操作（读档、战斗结算、离开面板） | 全量 | **立即**，不等防抖 |
| 玩家手动存档 | 新建/覆盖 `slots[i]` | **立即** |
| 切会话 | 先取消待执行定时器，再读新会话档 | — |

`save.set` 限频 20 次/60 秒。防抖不是可选项：流式输出期间每帧写一次会直接撞限频。

## 4. 读档：三档回退

```js
function readSlot(id) {
  const save = loadSave();
  if (!save) return { data: null, exact: false };
  if (id === 'auto') return { data: save.auto, exact: true };
  const slot = (save.slots || []).find((s) => s.id === id);
  return slot ? { data: slot.snap, exact: true } : { data: null, exact: false };
}
```

- 命中槽 → 直接恢复，界面标"已读取《名称》· 时间"。
- 槽损坏/版本迁移失败 → 给「新开」与「尽力读取」两个选择，**不要静默丢弃**。
- 读档后**绝不清零**：缺字段继承当前值，缺整份才回退到初始值。

## 5. 续档：让模型接上旧时间点

MMD 的存档只能恢复**游戏快照**，不能删改宿主聊天历史。读档之后，旧的后续消息仍然在上下文里，模型会拿"未来"当"现在"。所以读档必须附带一次续档上下文。

### 5.1 生成

读档时从快照与纪事生成一段裁剪文本，字段白名单：

```
[resume_context]
时间点：第 23 轮 · 渡口 · 酉时
玩家状态：体力 70，银钱 18，左臂受伤
进行中：把货送到南岸（还剩 2 天）
已知线索：船夫认得铜牌；仓库存货单缺了一页
关键人物：沈砚（信任 40，知道路线，不肯说前任死因）
最近纪事：第 21 轮接下委托；第 22 轮在码头遇见船夫；第 23 轮发现存货单缺页
忽略：以上时间点之后发生的剧情一律不作为当前事实
[/resume_context]
```

硬规则：

- **只放白名单字段**，不要把整个存档对象 `JSON.stringify` 进去。
- 长度设上限（建议 800–1500 字），超了按"任务 > 线索 > 人物 > 纪事"截断。
- 最后一句必须是"忽略该时间点之后的剧情"，否则模型会把旧后续当现在。

### 5.2 什么时候发

| 时机 | 做法 |
|---|---|
| 玩家点「读取」 | 只恢复界面与运行时状态，**不发消息** |
| 玩家下一次确认行动 | 把 `[resume_context]` 拼在行动前面，随这一条发送 |
| 发送成功 | 消费掉待发上下文，清标记 |
| 发送失败 | 恢复待发上下文，下次重试仍带同一段 |

界面必须提示：「恢复的是游戏快照，第 23 轮之后的聊天消息仍在。」不要写成"已回退聊天记录"。

### 5.3 人设侧配合

`<字段与输出>` 或 `<约束规则>` 里加一句：

```
[续档]收到 [resume_context] 时，以其中的时间点与状态为准；该时间点之后的旧剧情只当没发生过，
不引用、不总结、不据此推进。
```

## 6. 回溯与重生成

平台回溯会删掉该楼层及以下的消息，消息里的 `turn` 一定小于存档里的 `turn`。

```js
const save = loadSave();
const lastTurn = turnOf(lastMessage, messages.length);
if (save && lastTurn < save.auto.turn) restoreTo(lastTurn);  // 回溯
else replayFrom(lastTurn);                                   // 只补新增
```

`restoreTo` 从 `log` 里取 `<= turn` 的最近快照；没有精确命中就标"状态回退到第 N 轮，可能不精确"；一个都没有就保留当前值并提示"状态未能回退"。**绝不清零。**

## 7. 验收清单

- [ ] 两份内容不同的快照能分别保存、分别读取，互不影响
- [ ] 读档后正文、选项、至少两个状态字段、面板、设置都与所选快照一致
- [ ] 合法空数组保持为空，不被回填成新游戏默认值
- [ ] 槽名、槽数、其他槽内容不被覆盖操作影响
- [ ] 删除有二次确认，取消后槽还在
- [ ] `auto` 被覆盖时 `slots` 不变
- [ ] 版本迁移失败给两个选择，不静默丢档
- [ ] 回合结算后无需等防抖就能落盘
- [ ] 同一键并发写入按序落盘，刷新不改写 `updatedAt`
- [ ] 读档提示"旧消息仍在"，续档上下文只随下一次确认发送一次
- [ ] 发送失败后续档上下文能恢复
- [ ] 切会话时旧会话的待写定时器已取消

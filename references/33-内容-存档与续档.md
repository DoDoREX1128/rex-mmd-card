# 33 · 持久化与续档

需要跨刷新保存就用持久存储。新版默认 SDK save；cache 刷新即失。旧版同层用Host-only作用域本地存储；无可靠scope则停用保存并说明原因。禁止新版失败后静默改localStorage。

默认新版 store.js 使用v3单键包：updatedAt、auto、slots、settings。auto为当前快照，slots为带id/name/ts/summary/snap的手动槽；每槽快照带turn、业务数据与有限历史。v2数据可迁移；未知版本保留原档，禁止自动覆盖，界面提供确认新开和错误提示。

关键回合、手动存档/删除/覆盖立即排入同键串行队列；低优先级偏好可防抖。Promise拒绝进入可见错误与显式重试，不宣称已经保存。切会话取消尚未入队的定时器，丢弃旧代回调并重读SDK作用域存档；dispose停止写入与监听。真实宿主会话隔离仍需目标站验收。

sdk.save的键数/体积上限按宿主获取与错误处理，不写死10键。单键多槽节省键数，但快照数量/内容需按容量预算，满槽不静默删旧档。游客行为与save.remove历史故障按目标复验，不泛化永久结论。

读档只恢复游戏快照，不删除聊天。pendingResume使用白名单状态生成[resume_context]，提示旧消息仍在，仅在下一次玩家确认行动时随消息发送；失败保留，成功消费一次。默认选项填草稿，手动确认才发送；一点即发只在用户明确选择且有相应设置时启用。

同轮重生成恢复before后覆盖，不重复累加；旧轮done忽略；显式restoreTurn从保留快照恢复，较早或缺失时明确提示，不清零。不能仅凭可视DOM判定完整历史或宿主回溯。无宿主公开事件时，自动删除/分支同步属于项目扩展，不假装默认支持。

验收：不同快照分别存读、空数组不回填、覆盖不串槽、取消删除无副作用、失败不丢重试、切会话旧回调不污染新页、续档成功只发一次、失败可再次确认、未知版本不覆盖。

# 33 · 存档、命名槽、续档与回溯

30管模型到前端的数据通道；本文管进度跨刷新保留、读旧档与发送。新版默认store.js已实现的行为和项目扩展分别列明，旧版不调用sdk.save。

## 1. 先确定权威与作用域

| 数据 | 合适来源 | 边界 |
|---|---|---|
| 需要跨刷新保留的游戏进度 | 新版sdk.save；旧版可靠scope的本地实现 | SDK保存不自动进入模型上下文，也不改宿主聊天历史 |
| 当次页面展开/高亮 | state/cache | cache不能代替长期存档 |
| 平台剧情变量 | 已存在但公开参数契约未齐 | 不编造sdk.vars签名或导入字段 |
| 同一数值的派生显示 | 从唯一权威计算 | 不把模型值、本地值与平台值各存一套独立真值 |

SDK拥有其账号/角色/会话作用域，卡片不从DOM猜scope；旧版Host需要经验证的accountKey、roleId、conversationKey，并加作品命名空间。无scope就明确禁用持久化，不用固定main。隔离Frame不直接读父存储。

## 2. 当前新版信封（v3）

```js
{
  v: 3, updatedAt: 1730000000000,
  auto: {turn:23, data:{player:{},status:{hp:70},map:{},opt:[]}, nav:'world', key:null, history:[]},
  slots: [{id:'slot-…',name:'第二章·渡口',ts:1730000000000,summary:'第23轮·南渡口',
    snap:{turn:23,data:{status:{hp:70}},nav:'world',key:null,history:[]}}],
  settings:{choiceBehavior:'stageDraft'}
}
```

上例省略部分data字段，正式形状看snapshot()/cleanData()。

- storage.key由项目配置，默认rex:<meta.name>；一个键装auto与slots，避免一槽一键消耗键预算。
- 手动槽有稳定id、名称、时间和摘要；maxSlots默认8。槽满返回false，不静默淘汰最旧槽。
- saveSlot(name,id)可覆盖指定槽，UI层应先确认覆盖；deleteSlot(id,true)要求确认。auto变化不删除其他槽。
- applySave只恢复白名单结构，合法空数组保持为空，不能用“为空就补默认”覆盖玩家清空结果。

## 3. 当前API与调用时机

| 方法 | 当前作用 |
|---|---|
| saveGet() | 同步读、迁移与校验；返回auto或null，失败记录storageReadError |
| applySave(snapshot) | 恢复data/turn/history及有效导航，不自动发消息 |
| persist(true/false) | 立即进入串行队列 / 300ms防抖；不会因此绕过限频 |
| saveSlot(name,id?) | 新建或覆盖命名槽，立即持久化 |
| loadSlot(id或'auto') | 恢复游戏快照并生成pendingResume，提示旧聊天仍在 |
| deleteSlot(id,confirmed) | 已确认才删；随后持久化 |
| retrySave() / exportSave() | 重试捕获的失败载荷 / 导出信封文本 |
| reset(confirmed) | 确认后清进度与槽位并写新信封；调用前说明影响 |
| restoreTurn(turn) | 恢复最近≤目标轮的本地快照，非宿主回溯 |

message:done有效状态默认立即请求保存；手动存档/关键操作同样立即。高频UI变化可防抖。更新频率与容量由目标宿主限制，历史20次/60秒只作已记录预算，不能流式每帧写。

## 4. 串行、失败与版本迁移

1. 每次写入捕获载荷，串行排队，避免先发的旧快照晚落盘覆盖新快照。
2. 失败记录storageStatus与重试载荷，界面显示未保存；retrySave重试那份捕获值，不偷偷改成当前另一份值。
3. 读取失败/不兼容时禁止自动覆盖原档。当前迁移仅覆盖既有v2.data到v3；不支持任意历史格式。
4. 原档可先导出再人工迁移，或经明确确认新开。默认没有通用“尽力读取任意版本”按钮，不能声称已实现。
5. conversation:switch取消待写计时器、清续档与旧内存，重读新scope；dispose停旧运行时。已发往宿主且无法取消的请求仍依赖SDK自身作用域语义，目标站要测。
6. 新版保存不可用时不静默转localStorage；否则玩家会误以为跨设备已保存。

## 5. 读档后让模型接上

游戏快照与聊天历史是两回事。loadSlot不删除历史、不自动发送，只准备一次性上下文：

```text
[resume_context]
时间点：第23轮
状态：{"hp":70,"loc":"南渡口","flags":[]}
选项：["问船期"]
以此快照为准，忽略该时间点之后的旧剧情。
[/resume_context]
```

当前resumeContext只取声明状态字段、轮次与选项，主体裁到1200字符。任务、线索、人物与纪事摘要是**可扩展项**，添加后要同步白名单、预算和测试，不声称默认全部覆盖。

玩家下一次确认行动时confirmSend附加pendingResume；成功消费一次，失败保留，连点由发送锁保护。传输接受不等于回复完成或服务端完整保存，报告区分。模型侧要声明收到resume_context以该时间点为准，不能只把数据恢复在前端。

## 6. 重生成与回溯

同轮重生成先恢复该轮before再应用新patch；旧轮历史消息不回写当前状态。restoreTurn显式恢复最近≤turn快照，精确性不足会提示；无快照保留当前值。默认保留最近40份。

不要用最后可见消息turn小于存档turn就判定宿主已回溯：可能只加载到部分历史。若项目增加自动同步，先证明消息完整性与可靠的分支/回溯信号，再设计恢复规则。SDK没有公开删除/回溯接口，恢复游戏快照不能写成“聊天记录已回退”。

## 7. 验收清单

- [ ] 两份内容不同的快照能分别保存、分别读取，互不影响
- [ ] 读档后正文、选项、至少两个状态字段、面板、设置都与所选快照一致
- [ ] 合法空数组保持为空，不被回填成新游戏默认值
- [ ] 槽名、槽数、其他槽内容不被覆盖操作影响
- [ ] 删除有二次确认，取消后槽还在
- [ ] `auto` 被覆盖时 `slots` 不变
- [ ] 不兼容版本不自动覆盖；原档可导出并明确选择迁移或新开
- [ ] 回合结算后无需等防抖就能落盘
- [ ] 同一键并发写入按序落盘，刷新不改写 `updatedAt`
- [ ] 读档提示"旧消息仍在"，续档上下文只随下一次确认发送一次
- [ ] 发送失败后续档上下文能恢复
- [ ] 切会话时旧会话的待写定时器已取消

- [ ] 断网/拒写后显示未保存；刷新前后核对真实后端，而非只看内存
- [ ] 无SDK或无旧版scope时明确不可用，没有切换后端假成功
- [ ] 任务/线索等自定义扩展确实随快照恢复，未实现的标明范围
- [ ] 目标站跨会话、账号/角色隔离与设备恢复单独验；本地mock成功不能替代

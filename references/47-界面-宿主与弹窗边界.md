# 47 · 宿主换肤的三个通道

先确认目标域名、聊天版本、日期、文档来源和实际绘制document，再判断能力。

1. 直接CSS：角色iframe内的data-chat/data-slot与舞台可改；不能通过父class、提高优先级或parent.document穿透跨源。
2. 公开颜色桥：部分部署把白名单--chat-*映射到父层变量；父层没有同名--chat-*并不能单独证明桥没生效。
3. 受控宿主CSS：公开资料记录平台抽取、过滤并注入以精确data-host根开始的扁平规则。不是读取/点击/修改宿主数据的权限。

来源分层：历史meimoai15目标的负向探针、sexyai.ai的主题桥观察、2026-09-18官方ZIP中data-host规则、2026-10-01特定目标顺序对照属于不同证据，不能互相推广成所有站点永久结论。各根是否注入需在目标站逐项验证。

资料根：conversations、conv-delete/rename/limit、models、model-setting、persona/persona-confirm、extra、style、instructions、reset、background、assistant-intro、message-edit/delete/backtrack、share-role/records、summary。支付、登录、授权与系统安全页不在本角色换肤范围。

每条选择器从精确开放根开始，不写裸.model-setting-scope等；禁止:has()、url()、原生CSS嵌套。只按本次要求换肤，不伪造文案、价格、权限或业务状态；不猜postMessage协议。根内内部class是目标观察，不是永久API。

逐入口验收：实际打开→根命中→计算样式→选中/禁用/焦点→窄屏滚动→深浅色。记录支持/不支持/未验证，不一律写“父层可改”或“父层全不可改”。只通过静态检查也不能宣称真实注入。


## 1. 先画清实际document边界

```text
宿主页面：账号/模型/人设/总结等原生组件
└─ 角色沙盒iframe：data-chat、公开槽位、舞台和作者DOM
```

直接写iframe内.model-setting-scope无法穿透；同源规则与选择器优先级不是一回事。颜色桥/data-host是宿主主动接收的有限样式通道，不授予DOM读写或原生业务操作。

## 2. iframe内的检查表面（历史钩子，按目标复核）

| 靶点 | 钩子 | 吃哪些变量 | z-index |
|---|---|---|---|
| 「+」更多面板（11 项） | `[data-chat="more-panel"]`，每项 `button[data-action]` + 内层 `span` | 壳 `--chat-modal-bg`、文字 `--chat-modal-text`、图标底 `--chat-more-item-bg` | 无（composer 内展开） |
| 长按消息菜单 | `[data-chat="message-menu"]` | `--chat-modal-surface` / `--chat-modal-text` / `--chat-border` | 8200 + `backdrop-filter` |
| 居中 alert / toast | `[data-chat="alert"]` / `[data-chat="toast"]` / `[data-chat="alert-ok"]` | 确定钮 `--chat-accent` | 9000，`position:absolute` |
| composer 侧提示 | `[data-chat="snack"]` | 固定 `rgba(0,0,0,.72)` | 8100 |
| 分享条 / 选消息底栏 / 长图 loading | `[data-chat="share-bar"]` / `share-pick-*` / `share-shot-*` | `--chat-composer-bg` / `--chat-modal-surface` / `--chat-accent` | 0 / 0 / 8000 |
| 指令栏 | `[data-chat="instruction-bar"]` + `instruction-back` / `instruction-chip` | chip `--chat-shortcut-bg/-text`、返回钮 `--chat-modal-accent` | 无 |
| 总结提示气泡 | `[data-chat="summary-bubble"]` | 固定粉/蓝两套 | 无（在消息流里） |
| 帮聊 tip | `[data-chat="assistant-tip"]` | `--chat-modal-accent` | 10（点击后才插入） |
| 历史加载骨架 | `[data-probe="history-loading"]` | `--chat-text-muted` | 2 |
| 平台 snackbar | `[data-probe="snackbar"]` | 固定 | 10090（最高） |
| 槽位浮层 | `[data-slot="statusbar|header-extra|left|right|toolbar|message-extra"]` | 自定义 | 根据挂载点及真实层叠上下文验证 |

写法：`[data-chat="more-panel"] > button[data-action="reset"] { … }`。只改颜色、字体、边框、圆角、阴影、状态；不改定位、尺寸、滚动职责。

## 3. 宿主入口与通道矩阵

| 入口 | 资料中的受控根示例 | 如何验 |
|---|---|---|
| 会话列表及删除/重命名 | conversations、conv-delete/rename/limit | 打开对应状态，不只测列表首页 |
| 模型列表/设置 | models、model-setting | 检查壳、实际绘制层、选中与禁用 |
| 玩家人设/确认 | persona、persona-confirm | 样式变化不等于修改账号人设数据 |
| 补充设定/对话风格/指令 | extra、style、instructions | 分别打开，检查滚动和输入可读性 |
| 消息编辑/删除/回溯 | message-edit/delete/backtrack | 本任务只验外观时，不提交破坏性动作 |
| 分享/总结 | share-role、share-records、summary | 每个面板分别验证，不推定桥覆盖全部 |

公开颜色桥的变量映射需看目标绘制层计算样式；父层无同名--chat变量不能单独证明无桥。受控CSS必须精确开放根起始、扁平规则；校验脚本列出的根只是允许的静态语法范围，不代表目标部署已注入。

```css
[data-host="summary"].summary-sheet { color:#e8edf2; background:#10161c; }
```

这个例子只说明作用域写法；summary-sheet是目标观察类名，不能当永久API。每个逗号分隔选择器都要从精确根开始，不用裸父类名、:has()、url()或CSS嵌套。

## 4. 逐入口验收步骤

1. 记录目标域名、环境、时间、入口和所用通道。
2. 打开面板，保留修改前截图。
3. 确认实际绘制document、根是否存在、样式是否进入该document；如工具允许，可读计算样式。
4. 截图对照实际可见颜色/边框/字体，不只看CSS已被接收。
5. 检查选中、禁用、焦点、滚动、短高/窄屏与深浅主题。
6. 关闭重开、返回原生，确认样式未遮住业务按钮。
7. 每项写支持/不支持/未验证及原因，未测不算通过。

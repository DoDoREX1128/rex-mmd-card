# 47 · 宿主与弹窗边界

> 用户说"把模型设置、对话设置、用户人设、剧情总结这些弹窗也美化一下"时先读这一页。
> 一句话：**卡片跑在跨源 iframe 里；iframe 内的浮层能改，宿主页的弹窗改不动。**
> 2026-10-29 裁决：以洛璃 mmd-sandbox §6.3b 的实机结论为准，不承诺 `[data-host]` 可换肤。

## 1. 为什么有这条边界

沙盒卡跑在 `c<roleId>.sbx.<站点域>` 的跨源 iframe 里，宿主是站点主域。作者 CSS 只作用于 iframe 文档。

```
宿主页 www.<站点域>
├─ uni-app / uni-page-body
│  ├─ .sandbox-host
│  │  └─ <iframe src="c<roleId>.sbx.<站点域>">   ← 卡片在这里，作者 CSS 的作用域
│  └─ 模型设置 / 对话设置 / 用户人设 / 剧情总结 …  ← 宿主页原生组件，CSS 打不到
```

在 iframe 内写 `.model-setting-scope{…}` 不会命中宿主页；在 iframe 内改 `--chat-modal-bg` 也不会传导过去。

**探针证据（洛璃 2026-09-06）**：在卡片 iframe 内注入 `[data-chat=root]{--chat-modal-bg:#00ff00}`，再打开模型设置——弹窗仍是原色，卡片面仍是原色，且 `--chat-modal-bg` 在宿主页解析为**未定义**。同一次注入下，iframe 内的「+」更多面板立刻变绿。

## 2. iframe 内：这些能改

| 靶点 | 钩子 | 吃哪些变量 | z-index |
|---|---|---|---|
| 「+」更多面板（11 项） | `[data-chat="more-panel"]`，每项 `button[data-action]` + 内层 `span` | 壳 `--chat-modal-bg`、文字 `--chat-modal-text`、图标底 `--chat-more-item-bg` | 无（composer 内展开） |
| 长按消息菜单 | `[data-chat="message-menu"]` | `--chat-modal-surface` / `--chat-modal-text` / `--chat-border` | 8200 + `backdrop-filter` |
| 居中 alert / toast | `[data-chat="alert"]` / `[data-chat="toast"]` / `[data-chat="alert-ok"]` | 确定钮 `--chat-accent` | 9000，`position:absolute` |
| composer 侧提示 | `[data-chat="snack"]` | 固定 `rgba(0,0,0,.72)` | 8100 |
| 分享条 / 选消息底栏 / 长图 loading | `[data-chat="share-bar"]` / `share-pick-*` / `share-shot-*` | `--chat-composer-bg` / `--chat-modal-surface` / `--chat-accent` | 0 / 0 / 8000 |
| 指令栏 | `[data-chat="instruction-bar"]` + `instruction-back` / `instruction-chip` | chip `--chat-shortcut-bg/-text`、返回钮 `--chat-modal-accent` | 无 |
| 总结提示气泡 | `[data-chat="summary-bubble"]` | 固定粉/蓝两套 | 无（在消息流里） |
| 帮聊 tip | `[data-chat="assistant-tip"]` | `--chat-modal-accent` | 10（点击后才插入） |
| 历史加载骨架 | `[data-probe="history-loading"]` | `--chat-text-muted` | 2 |
| 平台 snackbar | `[data-probe="snackbar"]` | 固定 | 10090（最高） |
| 槽位浮层 | `[data-slot="statusbar|header-extra|left|right|toolbar|message-extra"]` | 自定义 | 1–999 装饰 / 3500–7999 页面级 |

写法：`[data-chat="more-panel"] > button[data-action="reset"] { … }`。只改颜色、字体、边框、圆角、阴影、状态；不改定位、尺寸、滚动职责。

## 3. 宿主页：这些改不动

| 入口 | 真机 scope | 备注 |
|---|---|---|
| 模型设置 | `.model-setting-scope` | z-index 9000 |
| 模型切换 | `.model-switch-scope` | 9000 |
| 对话设置 | `.conv-style-modal` | 10075 |
| 用户人设 | `.role-profile-modal` + `.role-setting` | 用宿主 `--lo*` 变量族 |
| 剧情总结 | `.summary-sheet` | z-index 1000000000，作者组件永远盖不过 |
| 新聊天 / 会话列表 | `.conversation-list-scope` | 9000 |
| 分享角色 | `.share-popup` | 9000 |
| AI 帮聊介绍 / alert | `.alert-scope` | 9000 |
| 消息编辑面 | `.msg-edit-scope` | 9999；内部 `.edit-surface` / `.option-item` / `.save-btn` |
| 二层说明（文风/总结提示词） | `.alert-scope` / `.summary-prompt-intro` | 与父同层或更高 |

这些都渲染在宿主页的 uni-app 里，用宿主 `body` 上的 `--background-color` / `--lo*` 变量族，**一个 `--chat-*` 都没有**。

正确做法：

1. **不做假入口**。不要写"点这里美化模型设置"，然后点开没变化。
2. **如实说明**：这些面板属于平台原生界面，卡内改不了；能改的是聊天层、舞台、iframe 内浮层。
3. **不要写裸父页面选择器**（`.sandbox-host` / `.model-setting-scope` / `.role-profile-modal`），会被校验判为禁止项。
4. **不要用 `window.parent.document`、`document.domain` 或猜的 `postMessage` 绕过跨源**。

## 4. 关于 `[data-host]`

官方资料提到另一条通道：平台抽取作者 CSS、过滤后注入宿主页，作者可从 `[data-host="…"]` 精确根写扁平 CSS。该资料来自压缩包说明，**未在目标站实测注入**。

本 skill 的处理：

- 不把它当作默认能力，不据此承诺"能换肤"。
- 用户明确要求尝试时：必须在目标站实际打开面板，确认根存在、规则进入宿主、绘制节点计算样式改变，才算通过。
- 静态检查只证明选择器写法合规，不证明已注入。

## 5. 全局美化清单

用户要"整套美化"时，按表面逐项盘点，标注"能改 / 改不动 / 未验证"：

| 表面 | 归属 | 状态 |
|---|---|---|
| 顶栏、消息列表、气泡、输入栏、发送钮 | iframe | 能改 |
| 功能栏（statusbar）、槽位浮层 | iframe | 能改 |
| 舞台（content / full） | iframe | 能改 |
| 「+」更多面板、长按菜单、alert、toast、snack、分享条、指令栏 | iframe | 能改 |
| 模型设置、模型切换、对话设置、用户人设、剧情总结、会话列表、消息编辑 | 宿主页 | 改不动，如实说明 |
| 平台 snackbar、历史加载骨架 | iframe，平台所有 | 只读/谨慎 |

**"能改"要有证据**：实际打开、点开状态、看计算样式。只写 CSS 没打开过，不算完成。

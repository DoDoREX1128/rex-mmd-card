# 创作字段库

本库提供可选语义和设计维度，帮助写人物、世界、玩法与状态协议。题材、章节、主角身份、角色数量和字段集合由本次作品决定，不要求填满，也不要求沿用示例缩写。

## 1. 先选要解决的问题，再选字段

| 资料 | 作用 | 何时读 |
|---|---|---|
| [创作与运行时蓝图](blueprints.md) | 前提、世界秩序、欲求、行为、语言、认知、关系、能力、记忆、开局、地理、创建、文风等22个设计维度；完整同层的实际字段路径 | 起稿、字段设计与换题材前 |
| [语义索引](index.md) | 130个字段候选，按13类检索近义、类型、生命周期和来源 | 确定概念、查重与选显示标签 |
| [fields.json](fields.json) | 语义候选真源 | 登记与更新语义 |
| [blueprints.json](blueprints.json) | 创作维度与完整运行时映射真源 | 更新路径、形状、合并/清空与实现差异 |

索引和蓝图MD均由 `node scripts/gen-fields.mjs` 生成；不要手改生成文件。原始制作记录与变更审计不打包进字段库。

## 2. 三条路线分别映射

| 路线 | 接入方式 | 不能混用的部分 |
|---|---|---|
| 新版沙盒卡 | 默认配置型骨架用 `content.status.fields`，配套默认JSON解析器；其他类型先映射/扩展 | 候选enum/bool/list不是配置后自动获得支持；以实际骨架为准 |
| 旧版同层卡 | 完整骨架用嵌套 `me/npcs/sys` 与世界字段，按蓝图逐项映射 `applyRexStatus/mergeCast` 和UI | 不把平面语义池的 `body/rel/lv/act` 原封当成同一含义 |
| 旧版原生卡 | 轻量示例为 `[status]` 内KV；复杂自定义解析按该工程契约 | JSON与KV虽同外壳，仍不是相同编码 |

字段设计至少记录：完整路径、含义、类型/范围、权威源、更新频率、缺省、清空方式、未知值、界面落点与信息可读边界。同一数值只选一个结算者；纯界面偏好不进入模型状态。

完整骨架蓝图包含14组顶层字段、17组人物子字段和5组系统子字段。它记录实际实现，并列出设计约束与代码裁剪的差异。能力、部位装备、身体档案、随身系统与经济都可不选；换成修仙、科幻、现代等题材时重新定义显示与玩法映射，原生动作层沿用。

## 3. 创作写法

人物用触发条件、行动、关系与认知边界来写；稳定档案、此刻心声、当前处境和动态身体/穿搭分开。世界规则写生效条件、执行者、代价、例外与实际用法。开场提供可感知场景与可回应事件，选项写尚未发生的行动意图。

文风自由由作者决定。去套话先补具体信息和人物差异，不机械禁用因果、修辞、性格词或固定标点。详细方法见[人设与文风](../32-内容-人设与文风.md)和[世界书](../31-内容-世界书.md)。

地理的地区ID、地区名、视图标题分开，`loc/where/near`共享地名注册表。实体以稳定ID识别，名称允许变化。未知与0、缺键与清空分开；不能让演示数据补成事实。详见错题 [E-036](../errors/cases.md#e-036)、[E-037](../errors/cases.md#e-037)、[E-054](../errors/cases.md#e-054)。

## 4. 命名与冲突

语义池沿用2–4个汉字与2–4个小写字母，便于库内查重；这是现有登记工具的约定。项目可以使用准确长名、中文键、大小写或嵌套路径，只需目标解析器支持。`Intel`大小写和`sys.look`路径不能为凑缩写改掉，也不宣称中文键天然不可靠。

近义先查含义：生命/气血、体力/精力、声望/名望/名誉、金钱/货币。相同含义合并为主字段和别名；确有两种资源则明确定义消耗、恢复与读取者。相关但不同概念可以并存，例如称谓与好感、受孕状态与器官档案；不要用“同组只能留一个”抹掉差异。

`body`在旧语义池是体态，在完整骨架是部位字典；`rel`在完整骨架为称谓文本，`fav`为好感；`lv`是等级称号文本；完整骨架的`act`为幕号标题。按路径与类型判断，不只看短键。

## 5. 分类与候选属性

十三类：身份、生理、心理、欲情、关系、社会、资源、进度、战斗、空间、时间、物品、元。单个语义候选按主要读取者归类，分类不决定所有卡必须出现这个维度。

- `type`：bar/num/tag/text/enum/bool/list，语义池描述的是候选形状；蓝图另记对象和元组等实际结构。
- `life`：每轮/阶段/一次性，表示典型更新时机；“每轮”不意味着未变化的所有字段都必须重复输出。
- `range`：候选范围或格式；只有实际解析/校验实现了才可声称强制执行。
- `status`：core多份素材主干、common素材内常用、niche特定题材、supplement无直接素材的补充。它不代表写作质量或运行时支持。
- `sources/note`：来源与语义、映射注意项；生成索引保留说明，避免查到键却看不到边界。

## 6. 检索与维护

```text
node scripts/field-add.mjs --find 认知
node scripts/field-add.mjs --find Intel
node scripts/field-add.mjs --find sys.bag
node scripts/field-add.mjs --profile planning
node scripts/field-add.mjs --profile complete-status-v3
node scripts/gen-fields.mjs --check
```

先检索同义与现有路径，再复用或自定义。语义池新增仍用 `field-add --name ... --key ... --type ... --cat ... --life ... --source ... --note ...`，更新加`--update`。创作维度与运行时蓝图改对应JSON，重生成并回归。批量整理先做查重与逐条语义复核，不用“只能一次加一个”代替真实检查。

合并保留旧名/旧键的迁移映射；废弃先写替代项与兼容读取，拆分要改解析与UI，不能只改显示标签。现有语义池status枚举无deprecated，不写一个工具不支持的状态。加入库不代表已加入某张卡；本次采用的字段才同步到模型说明、开场、解析器和UI。

语义池来源：persona通用模拟器、yuji无羁、yinyu因缘、luoli状态/创建参考、common通用补充、complete-template完整同层模板。创作蓝图结合人设/世界书方法，运行时蓝图以当前完整骨架实际源码为准；参考题材不成为必选设定。

## 创作设计维度

| 维度 | 要解决的问题 | 写法与边界 | 落点 |
|---|---|---|---|
| 叙事前提 | 叙事者是谁、能写到哪里、玩家能决定什么 | 明确{{user}}的行动/心理由谁决定，避免强塞来历和人格 | persona前提 |
| 题材与基调 | 时代、超常规则、叙事节奏和感官重点 | 按作者选择，不用禁词表替代具体表达 | persona主题 |
| 核心循环 | 玩家反复做什么、得到什么反馈、承担什么代价 | 从一次可执行行动推演后果，纯故事不强加游戏系统 | 方案/玩法规则 |
| 世界秩序 | 资源、权力、日常制度和可见代价 | 规则写触发条件、可做/不可做、代价与例外 | 世界书常驻/触发 |
| 身份与处境 | 角色职责、所处关系、可用资源 | 写能支配谁/受谁约束，避免很重要/深不可测 | persona/人物条 |
| 外貌识别 | 固定特征、衣物、动作习惯与场景痕迹 | 保留可辨识细节，不堆清冷绝美等空评价 | 人物条/外貌候选 |
| 欲求与压力 | 想取得什么、怕失去什么、当前阻力 | 让它能改变具体选择，不固定全卡欲望数量 | persona角色 |
| 行为与例外 | 遇到某事先做什么、何时改变惯例 | 以触发→动作→后果写可演行为，不只贴性格标签 | persona角色/习性 |
| 说话方式 | 对不同对象的称呼、句式、回避与透露 | 给短语境例子，避免人人同一种金句腔 | persona角色 |
| 认知与信息边界 | 已知、误信、未知、秘密与信息来源 | 角色不能因为世界书写了就全知；心声可读性另定 | persona约束/人物条 |
| 关系与称谓 | 关系事实、利益/旧事、称呼变化条件 | rel/fav/信任分义；玩家关系不代替玩家意愿 | 人物/关系条 |
| 能力与限制 | 适用范围、资源消耗、失败与反制 | 等级不等于效果；稳定ID与可改名称分开 | 能力条/运行时映射 |
| 长线记忆 | 跨多轮仍须生效的事实与承诺 | 静态约束进人设/世界书，剧情变化进状态与可靠存档 | persona/世界书/存档 |
| 开局场景 | 时间地点、在场者、眼前压力与可行动处 | 给真实初值，不把选项结果提前写成事实 | 开场白/初始status |
| 地理注册 | 地区ID、地区名、视图标题、地点别名与房间 | loc/where/near共享注册表；未知保留，不编距离 | 世界书/地图数据 |
| 创建参考 | 可选出身/相貌/能力/身份等候选与介绍 | 按题材选维度，名称或ID用于触发；UI偏好分流 | 创建数据/触发世界书 |
| 行动意图 | 下一轮可采取的行动与侧重 | 动词起头、只写意图，不预设成功，随玩家回复习惯调整 | opt/可改草稿 |
| 档案与状态 | 固定事实、当前状态、部位/装备、心声 | 不要把这些都塞备注；不同更新频率分层 | 字段目录/人物页 |
| 条目设计 | 分类、启用、常驻/关键词、优先级、单层包裹 | 稳定UID；正文规则与资料/创建参考分组；实际文本回放 | worldbook/审阅稿 |
| 文风与事实密度 | 动作、物件、声音、距离、代价和可用信息 | 抽象结论改成能表演的事实，保留作者修辞和章节自由 | persona/世界书 |
| 纯界面偏好 | 主题/头像形态/字号/动效/阅读位置 | 仅本地UI则不喂模型；所选项仍须真实落到HUD与持久化 | 偏好存储/创建桥接 |
| 资源与结算 | 余额、物资、取得/消耗条件与唯一结算者 | 交易未闭环就不假扣款；物品数量0与空库分别定义 | 可选玩法/资源协议 |

## 旧版同层完整骨架的实际字段

新版沙盒默认平面字段配置、旧版原生KV与本表不是同一schema；跨路线必须显式映射。

实现依据：assets/samelayer-complete/frame/frame-main.js:applyRexStatus/mergeCast；frame-features.js:optsOf。

| 路径 | 形状 | 更新时机 | 合并/清空 | 写法与映射 | 界面 |
|---|---|---|---|---|---|
| `turn`（轮次） | integer | 每轮 | 覆盖；缺失保留/历史兼容可补偿 | 不拿turn当消息ID | 世界/编年 |
| `y`（年份） | integer | 跨年变化 | 有效非0值覆盖，0不写入 | 按题材历法，可不选 | 顶栏 |
| `t`（日期时辰） | string | 时刻变化 | 非空覆盖，按·拆日期与时段 | 不重复维护另一time真源 | 顶栏 |
| `loc`（具体地点） | string ≤20 | 移动 | 非空覆盖，未知原文保留 | 只用注册名与合法房间后缀 | 地图/顶栏/玩家where |
| `region`（地区名） | string ≤12 | 跨区 | 非空合法名更新，非法保留regionRaw | 与地区ID/地图标题分开 | 地图 |
| `act`（幕号标题） | string | 转折 | 解析幕号与标题，空串不清空 | 完整骨架指幕，不是新版示例行动摘要 | 世界/编年 |
| `threat`（威胁） | integer 0–5 | 变化 | 覆盖且夹取，0有效 | 定义风险事实，不擅加玩家感受 | 世界内部/动荡 |
| `env`（环境） | string | 变化 | 非空按·分段提取环境/温度 | 具体光声气味与限制，温度未知不编 | 世界 |

| `me.lv / npcs.*.lv`（等级称号） | string ≤20 | 成长 | 字符串覆盖 | 境界/职位可重命名，但UI旧题材标签也要映射 | 人物列表/详情 |

## 实现差异与换卡前检查

- 气泡opt直接读原消息最多4条，WORLD.opt最多3条且每条20字；目标3条10–30字需要先统一实现，见E-080。
- me/npcs/Intel/body/outfit/bones/sys按键合并；空对象和空字符串多数不能清除旧值。
- tags/opt/near/sys.bag/sys.shop整组替换且[]可清；wuhun/outer是增量集合，[]不会清空。
- 字段目录常用的mind40/Intel30或40/sys.look80/sys.say40为生成约束；代码裁剪不同，不能宣称已强制校验。
- 早期四维/独立双块/独立货币/固定每十轮全量属于历史方案或可选策略；新卡须按本次玩法决定。

历史兼容入口仅用于旧档读取，新稿不继续要求生成：[cast]历史档案块；present/tier/flags/map/note；sys.alias/sys.coins/sys.mood/sys.trait/sys.note；Intel别名intel/surface、数字rel历史好感。

参见错题 [E-036](../errors/cases.md#e-036)、[E-075](../errors/cases.md#e-075)、[E-080](../errors/cases.md#e-080)、[E-081](../errors/cases.md#e-081)、[E-086](../errors/cases.md#e-086)。

## 接入验收

- 选择本次题材/核心循环和所需字段，允许自由章节与自定义键；不用的维度不建。
- 逐项写路径、类型、权威源、更新频率、缺省、清空、UI落点、可读信息边界。
- 沿用完整骨架时保持现有原生动作层；变更模型schema只改对应映射，别重新逐项适配原生功能。
- 世界书字段目录为模型说明真源，人设留指针；开场与每个示例必须真实解析。
- 对所选解析器做缺键/空集合/0/未知/改名/重复快照/回溯验证；不把生成上限当已实现校验。

# 54 · 目标站与实体设备测试

E4 在真实 MMD 部署上跑，E5 在实体 Android 设备上跑。两条链路都只测用户指定的那一张卡，脚本不会自己找卡。

## 1. 测试入口由用户提供

开测前必须向用户索取聊天页 URL，不给就停。

```text
https://<MMD域名>/#/pages/chat/chat?roleId=<角色卡ID>&prePath=1
```

已记录可用域名：`sexyai.ai`、`meimoai15.com`。示例：

```text
https://meimoai15.com/#/pages/chat/chat?roleId=114739&prePath=1
```

以下都不算目标，收到就退回重问：

- `#/pages/role/create?id=…` 创卡页
- 站点首页、发现页、他人主页
- 「大概叫这个名字」的卡，或看起来相似的卡

域名不在清单里不等于不能测。先问用户这个域名是不是本轮目标，确认后加 `--assume-host` 执行，报告里记下这次放行。

拿不到 URL 时，E4 与 E5 都写 NOT RUN，并保留可直接执行的命令，不要用本地预览或相似卡凑一个结论。

入口校验由脚本完成，不依赖人工肉眼核对：非 https、路径不是 `#/pages/chat/chat`、缺 `roleId`、域名未知，四种情况分别给出拒收原因和正确格式。

## 2. PC 目标站（E4）

```text
node scripts/live.mjs --url "<聊天页URL>" [--act "<动作JSON>"] [--strict] [--shot-full] [--use-open] [--selectors "a,b"]
```

执行内容：

1. 建立浏览器会话，新建标签并导航到入口 URL。
2. 轮询 `[data-chat="root"]` 是否挂载，最多 30 秒。
3. 首屏截图，跑只读探针，读控制台与请求记录。
4. 落 `work/live/pc-<时间>/`：`report.json`、`report.md`、`shots/`。

标签默认新建。加 `--use-open` 才借用用户已打开的同域名标签，脚本结束时归还，不关用户的页面。

`--send "<文本>"` 是唯一的写操作入口，且只填不发；不加就不碰输入框。

退出码：`0` 通过或有待查项，`1` 失败，`2` 入口被拒，`3` 未执行。

驱动是 bsk（browser-skill 的 CLI 与浏览器扩展），复用用户已登录的 Chromium。未安装时脚本写 NOT RUN，不拿无头渲染结果冒充目标站。

链路覆盖范围：已连接的那一个浏览器、当前登录态、当前网络。跨内核、干净首访、权限授予、弱网限速不在覆盖内，报告里不要写成「平台全量通过」。

### 动作序列

用例可以写成 JSON，两条链路语义一致：

```text
node scripts/live.mjs --url "<入口>" --act '[{"click":"[data-chat=\"more-panel\"]"},{"wait":500},{"shot":"02-more"},{"eval":"document.querySelectorAll('[data-chat=\"message\"]').length"}]'
```

可用步骤，每步只能带一个动作键：

| 键 | 值 | 说明 |
|---|---|---|
| `click` | 选择器 | 手机上走真实触摸点 |
| `fill` | 选择器，或 `{selector,text}` | 先聚焦再输入，不自动提交 |
| `press` | 按键名，或 `{key,selector}` | Enter / Backspace / Tab / Escape |
| `wait` | 毫秒，0–60000 | 等界面稳定，不等网络 |
| `shot` | 文件名，只含字母数字点线 | 落进 `shots/`，同时记进报告 |
| `eval` | 表达式 | 只读取值，结果写进报告 |
| `scrollTo` | 选择器 | 滚动到可见，再判断 |

`click`、`fill`、`press` 会真的作用到页面。只在有授权的测试卡上做，涉及发送、删除、提交的动作单独确认。序列中断即停，后面的步骤不再执行，报告里写明断在第几步。

动作跑完会再取一次读数，报告里的 `probeAfter` 是动作后的状态；判定以它为准，没有动作时用初始读数。

## 3. 实体设备（E5）

```text
node scripts/live-mobile.mjs --url "<聊天页URL>" [--act "<动作JSON>"] [--rotate] [--serial <设备序列号>]
```

桌面浏览器把宽度设成 390px 不是 E5。内核、字体、触摸手势、软键盘顶起、移动端性能都不同，这些只有实体设备能测。

链路：

1. `adb devices` 找处于 `device` 状态的设备。
2. 在设备上拉起 Chrome 打开入口 URL。
3. `adb forward tcp:<端口> localabstract:chrome_devtools_remote`。
4. 直连 CDP，等聊天页挂载，首屏截图，跑同一套只读探针。
5. 真实触摸点输入框，读 `dumpsys input_method` 判断软键盘是否弹出。
6. `--rotate` 时切横屏再拍一张，测完恢复原方向。
7. 带 `--act` 时，触摸检查之后按序列执行，跑完再取一次读数。
8. 落 `work/live/mobile-<时间>/`，结构同上。

设备侧前提：

- 开 USB 调试并在手机上点允许；`unauthorized` 时脚本会说明去点授权。
- 设备上装 Chrome，且已登录 MMD。未登录时脚本停下并提示去设备上登录，不代填凭据。
- 设备保持解锁、Chrome 在前台。

无设备、无 Chrome、DevTools 连不上，都写 NOT RUN 并退出 3。不降级成桌面视口模拟补一个「通过」。

iOS Safari 走不了 adb，需要云真机或实体 iPhone 手动执行，报告中如实标未覆盖。

## 4. 只读探针

两条链路共用 `scripts/lib/live-probes.mjs`，全部只读：不写 DOM、不改存储、不发消息。

| 读数 | 判据 | 说明 |
|---|---|---|
| 平台根 | 存在 `[data-chat="root"]` | 不存在说明没渲染新版聊天页，先查 URL 与登录态 |
| 横向溢出 | `documentElement.scrollWidth > innerWidth + 1` | 真溢出，不是「看起来有点宽」 |
| 状态栏 | 存在、字数、`scrollWidth > clientWidth` | 空槽不计问题；被裁才是问题 |
| 气泡 | 条数、最宽宽度、正文溢出数 | 溢出数大于 0 要定位到具体气泡 |
| 固定层 | `position` 为 fixed/absolute/sticky 且 `z-index ≥ 100` | 按 facts 的作者安全带判越界与空档 |
| 遮挡 | 目标元素中心点 `elementFromPoint` | 由当前观察取得的定位，不复用旧选择器 |
| iframe | 数量、同源、是否含平台根 | 顶层没有平台根时自动落进同源 iframe 再测 |
| 媒体查询 | 断点与朝向命中情况 | 判断当前是否真在窄屏布局 |

测到读数不等于测通过。溢出、遮挡、z-index 越界属于要查的现象，能不能接受由这张卡自己的设计约定判断。

## 5. 用例库：按实现范围取用

旧版同层常见动作如下，**不是自带基座已实现清单**。新版只测公开能力和作品 UI；旧版原生只测声明的 KV / 气泡 / 主题 / 轻量 Host。删除、回溯、会话与人设提交只在实现且有授权的测试数据上执行；纯外观任务不顺手提交真实数据。未实现写 N/A 加原因，有能力但没测写 NOT RUN，都不算 PASS。

| # | 用例 | 操作 | 预期（可见） |
|---|---|---|---|
| 1 | 首屏 | 打开链接 | 封面或主界面出现，不是白屏、不是平台默认页 |
| 2 | 导航 | 点每一个导航项 | 每个分区都有内容，标题对应 |
| 3 | 面板开 | 点终端/设置/人设等入口 | 面板打开，内容非空 |
| 4 | 面板关 | 点关闭/返回/遮罩/ESC | 回到上一级，不白屏 |
| 5 | 消息编辑 | 选一条 → 编辑 → 改字 → 提交 | 该条消息文字真的变了 |
| 6 | 消息删除 | 选一条 → 删除 → 确认 | 该条从列表消失；取消则不消失 |
| 7 | 回溯 | 选一条 → 回溯/分支 | 出现新分支或回到该楼层（按平台行为） |
| 8 | 会话 | 新建 → 切换 → 重命名 → 删除 | 列表与标题同步变化 |
| 9 | 人设 | 打开 → 改一项 → 提交 → 重开 | 值被保存，重开仍在 |
| 10 | 补充设定 | 打开 → 写入 → 提交 → 重开 | 内容被保存 |
| 11 | 指令 | 打开指令 → 选一条 → 应用 | 输入框出现对应指令文本（不自动发送） |
| 12 | 设置 | 打开 → 改一项 → 提交 | 设置生效，重开仍在 |
| 13 | 分享/收藏/评论 | 点入口 | 对应原生弹层出现，或明确提示不可用 |
| 14 | 输入 | 填入文本 → 发送 | 消息出现在列表；发送后输入框清空 |
| 15 | 二次进入 | 刷新/重进 | 不叠实例、不双份界面、状态不丢 |
| 16 | 窄屏 | 手机链自动执行 | 不横向滚动，底栏不遮输入，能点 |
| 17 | 控制台 | 全流程 | 0 异常；警告逐条记录 |

## 6. 状态、创建与存档专项

| 专项 | 操作与预期 |
|---|---|
| 两轮状态 | 实际模型输出与 UI 一致，缺字段不清零，原始数据块不露出 |
| 坏输出 | 在本地注入坏 JSON；目标站自然出现时记录，保留旧值，不用改内部变量假通过 |
| 创建 | 必填与可选、返回、默认值、草稿可改、失败不退出；选项不会自动变成已发生剧情 |
| 命名槽 | 保存两份不同值 → 读各自槽 → 核对至少两个值、空列表及其他槽 |
| 真保存 | 刷新或重开后恢复；拒写时可见；重试后再刷新确认 |
| 续档 | 读取只恢复快照不发消息，下一次确认带一次上下文，失败仍可重试 |
| 会话与重入 | A/B 会话不串数据，退出回来不叠实例；切宽窄不丢关键草稿 |
| 主题/外链 | 深浅切换、真实宿主表面、图片与字体失败、减少动态 |

## 7. 证据格式

脚本会自动写 `report.json` 与 `report.md`。人工补测的部分按下面写：

```text
用例：存档读取A
前置：目标卡/构建、已有两个槽、当前值
动作：点存档→选A→确认读取
预期：状态回到A；提示旧消息仍在；尚未发送续档
前截图：shots/save-before.png
后截图：shots/save-after.png
可见结果：hp与地点分别变为…；其他槽仍在
控制台与等待：…
结论：PASS / FAIL / NOT RUN / N/A（原因）
```

「已点击」「handler 返回 ok」「没有报错」都不足以判 PASS。发送至少区分：点击已触发、消息出现、回复完成、服务端回读。超时显示结果未确认，不自动重发。

## 8. 故障与收尾

| 现象 | 排查 |
|---|---|
| 入口被拒 | 按脚本给出的正确格式重问用户；不要自己去站点上翻一张卡 |
| bsk 不可用 | 装 CLI 与扩展后重跑；期间 E4 写 NOT RUN |
| 聊天页未挂载 | 确认登录态、卡是否公开、URL 里的 roleId 是否存在 |
| 元素定位过期 | 重新观察取新定位；不要重放旧引用盲点 |
| 截图空白或交互不到 | 核对 iframe、Canvas 与当前活动标签页 |
| 窄屏仍溢出 | 查内层 scrollWidth、flex min-height、固定高度与软键盘 |
| 软键盘未弹出 | 先确认焦点是否落在输入框，再看是否被平台拦截 |
| 原生面板被 Frame 盖住 | 检查 Host 让位、返回按钮、当前 capabilities |
| 保存 toast 成功但刷新丢失 | 查真实 scope、SDK 响应、后续旧写覆盖、读档失败；不要新开覆盖原档 |
| 设备 unauthorized | 让用户在手机上点允许 USB 调试，再重跑 |

收尾：脚本默认结束会话并归还借用的标签，手机链默认移除端口转发。加 `--keep` 或 `--keep-forward` 才保留现场。

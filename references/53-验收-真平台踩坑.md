# 53 · 排障与错题本

> 排障不是背结论，是**按层缩小范围**。
> 具体条目在 [references/errors](errors/index.md)，本页给顺序、方法和最常撞的几条。

---

## 0. 先分版本，再动手

| 版本 | 典型故障 | 先看 |
|---|---|---|
| **旧版 0** | 点火不触发、字符被改写、分片断了、旧实例抢跑 | 本文 §2 + [24](24-平台-旧版事实.md) |
| **新版 1** | `chatVersion` 没生效、标记没接上、SDK 名拼错、读到占位、层级被压 | [21](21-平台-新页事实.md) §6 / §11 |

同一个症状（例如「按钮全哑」）在两版的原因不同，**不要跨版本套结论**。错题本里每条都标了 `v0` / `v1`。

## 1. 症状 → 先查哪一层

不要从「哪里看起来有问题」开始查，从「这一类症状归哪一层」开始。

| 你看到的现象 | 先查 | 库里编号 |
|---|---|---|
| 规则装上了，页面毫无变化，控制台干净 | 点火 | E-001 / E-002 / E-004 |
| 本地代码对，贴进去变形 | 字符集 | E-003 |
| 规则数量对、标记在，但一条不命中 | 正则 | E-020 / E-021 |
| 某一条规则不生效，其余正常 | 数据（限额） | E-022 |
| 调了 `sdk.*` 没效果，或报 `NOT_SUPPORTED` | 能力 | E-014 / E-015 / E-016 |

## 2. 最常撞的五条

### E-002 · `onerror` 载体用了合法图片

**症状**：规则一条都不跑。
**根因**：引用的 base64 是合法 1×1 透明 GIF，加载成功，`onerror` 永不触发。看着像坏图，实际是有效资源。
**动作**：载体固定写 `src="data:,"`。不要拿"看起来像坏图"的 base64 赌它坏。

真站对照：合法 gif → `slp:null, badge:null`；`data:,` → `slp:60, booted:true`。

### E-001 · 链式标记在独立拓扑下断在第二条

**症状**：一百多条分片只有第一条跑。
**根因**：平台可能对每条规则各自作用于原文，上一条的输出传不下去。
**动作**：默认独立拓扑——所有标记一次性进 `beginning`，每条规则只认自己那一个。要复刻链式成品才用链式，并做双语义重放。

### E-009 · 版本字段被校验器「建议」改掉

**症状**：旧版卡导入后页面正常，按钮全哑，零报错。
**根因**：用沙盒校验器验旧版卡，它提示「chatVersion 必须是 1」，照改后旧版卡被当成新页处理。
**动作**：校验器按版本专用；交付前单独断言 `chatVersion`，不信构建脚本默认值。

### E-017 · 层级落在平台舞台层下面

**症状**：自绘 HUD 本地正常，真站被立绘/舞台盖住，点击穿透。
**根因**：平台舞台内容约 `2000`、全屏层约 `3000`，作者层用 `1000–1999` 正好被压在下面。
**动作**：页面级浮层用 `3500–7999`；气泡内元素才用 `1–999`。

### E-014 · 在流式占位时解析消息

**症状**：状态偶尔被解析成空，旧状态被清零，重新生成又好了。
**根因**：流式阶段消息体里先是「消息生成中」占位，此时读 DOM 拿到的是占位文案。
**动作**：在 `message:done` 里解析，或 mount 时先校验文本里确实有协议块；解析失败保留上一份有效状态。

其余 25 条见 [错题本索引](errors/index.md)。

## 3. 什么不算验证

真站故障最贵的成本不是修，是**以为已经修好了**。

| 不算验证 | 为什么 |
|---|---|
| 在 Node 假 DOM 里手动调 handler | 只是执行了自己写的函数，没验证平台是否会触发它（E-013） |
| 看控制台没有报错 | 静默失败是这类故障的默认形态（E-005） |
| 只看"规则数量对不对" | 装上 ≠ 命中（E-020 / E-021） |
| 只在一版上验 | 两版机制不同（§0） |

算验证的三条：**真浏览器 + 真实页面 + 截图**；判定看页面上的可见结果（徽标、iframe、文字），不看日志；每次改注入链，先跑双语义重放，再上真浏览器。

## 4. 旧版真站注入的三个现实约束

写在这里是因为它决定"能不能注入"，不是代码风格问题。

- CSP `script-src` 允许 `'unsafe-inline' 'unsafe-eval' blob:`，但**外链 `<script src>` 被拦**；
- `fetch('http://127.0.0.1:…')` 被 mixed content 拦；
- 可行路径是 base64 分片（每片约 18KB）累加到全局对象 → `atob` → `TextDecoder` → `Blob` → `blob:` script。整包 589KB 用 46 片能传完。

新版沙盒有官方 `<script>` 通道，不走这条路（见 [21](21-平台-新页事实.md) §2）。

## 5. 错题本怎么用

位置：[`references/errors/`](errors/README.md)，真源 `errors.json`，索引 `index.md`（生成，勿手改）。

```bash
node scripts/error-log.mjs --find 点火 --ver v0      # 查：先版本，再层
node scripts/error-log.mjs --show E-002              # 看：症状/根因/处置/出处
node scripts/error-log.mjs --hit E-002               # 命中：累加次数与日期
node scripts/error-log.mjs --add ...                 # 记：查不到才新增
```

三条使用纪律：

1. **只有「已复现」能直接照做。** 「待复现」是线索，「失效区」里的条目不要再按它排查。
2. **命中就 `--hit`，不要新开一条。** 同一条被反复命中，说明它值得提到本文 §2。
3. **发现归因错了，改判决而不是删掉。** 标成 `false-positive` 并写清真错因，才能阻止下一个人重走这条路。

判决、证据、分层的完整规则见 [errors/README](errors/README.md)。

## 6. 一页检查表

- [ ] 版本先定：`chatVersion` 是 0 还是 1；没有跨版本套结论
- [ ] 点火拓扑：独立优先；双语义重放都过（E-001）
- [ ] 字符集：无裸 `_ * < >`；打包器 guard 通过（E-003）
- [ ] 载体：`onerror` 用 `data:,`；点火器自给自足（E-002）
- [ ] 失败可见：徽标 + 兜底 + 错误上屏（E-005）
- [ ] 旧实例：先 destroy 再测（E-004）
- [ ] 真浏览器：截图 + 无控制台错误（E-013）
- [ ] 没有为了"能跑"去换掉用户成品（E-026）
- [ ] 新结论已进错题本，且标了版本与判决

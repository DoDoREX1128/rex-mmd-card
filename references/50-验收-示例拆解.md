## 2. 示例 A · HUD 接管型

### 2.1 规则结构（100 条怎么分）

| 段 | 条数 | 作用 |
|---|---|---|
| 初始化 | 1 | 建 `globalThis.__MMD_HUD_INLINE_STATE__` |
| `h` 分片 | 8 | 累积 **Host** 源码（约 14 万字符） |
| `f` 分片 | 90 | 累积 **Frame** 源码（约 166 万字符） |
| launcher | 1 | 校验两段 → 注入 Host → 配 `theme` 与 `frameScriptSource` |

每条分片的形状（一字不差）：

```html
<script>(()=>{const s=globalThis.__MMD_HUD_INLINE_STATE__;
s.h=(s.h??'')+"<本片内容，已转义>";})()</script>【MMD HUD 内嵌注入 00N】
```

- `h` 与 `f` 分两段累积，launcher 才拼起来用。
- 片长卡在 19000，预留 wrapper。
- 最后一条没有尾部标记——它是链的终点。
- 转义：`<` → `\u003c`、`$` → `\x24`、换行 → `\n`。少一个就断链。

### 2.2 Host 做了什么

- **146 个选择器**，覆盖：消息列表/气泡、输入框、发送代理、快捷键栏、指令栏、聊天设置弹窗、总结面板、更多菜单、返回。
- 16 个 `case` 的动作分发 + 若干 `open*/submit*` 方法。
- 只做"翻译"：Frame 说"删第 3 条"，Host 找 DOM、点按钮、填表单、提交。
- 找不到元素就降级，不抛异常（否则 Frame 一片红）。

### 2.3 Frame 做了什么

- 1.66MB 的完整前端应用（Vue 运行时 + 组件 + 样式）。
- 自带封面、捏人、地图沙盘、人物图鉴、场景设置、境界、地点。
- **数据在本地**：玩家在 HUD 里捏人、走地图、解锁立绘，HUD 自己存。
- AI 只负责写正文；`example` 里下了硬约束：**每次 ≥1500 汉字 + 固定尾部结构**。
- "历史状态栏出现她的姓名后显现"——它读的是**历史消息文本**，不是结构化协议。

### 2.4 界面结构（从标签统计看出）

`地图工具 / 场景设置 / 天下地图 / 放大缩小沙盘 / 境界（凝神·化劲·合道）/ 前往此处 / 药材铺·木作铺·茶肆·货栈`

→ 一个"可走动的世界"：地图是主界面，人物与地点是地图上的节点。

### 2.5 视觉

| 项 | 取值 |
|---|---|
| 主色 | 朱砂 `#913c2c`（29 次） |
| 暗部 | 墨绿 `#243e35` / `#294e3d` / `#36594b` |
| 纸面 | 米黄 `#efe6d3` / `#fff3d9` |
| 字 | 文楷系 4 族（开篇/正文/选项/界面各一） |
| 质感 | 纸纹 + 墨线 + 印章式点缀 |

**可迁移的点**：三色体系（纸 / 墨 / 朱），强调色只做印章与标题；字体按用途分族，而不是一个字体打天下。

## 3. 示例 B · 原生增强型

### 3.1 规则结构（68 条怎么分）

| 类 | 条数 | 例子 |
|---|---|---|
| 原生换肤 CSS | 8 | 聊天页、弹窗、设置、对话框 |
| 自建层 CSS | 18 | 挂载层、场景、百科、地图、音乐、气泡、修复 |
| JS 模块 | 38 | boot、screens、forge、wiki、music、status、desktop、repair |
| 资源/其它 | 4 | 开场动画、底纹、诗篇、预载 |

`beginning` 是一串标签：

```html
<zml-native><zml-native2>…<zml-mod-forge>…<zml-status-core>…<zml-repair-ui>
<div hidden>【仅供 AI 阅读：开局与角色创建】…</div>
```

每条规则 `findRegex: /<zml-xxx>/` → 替换成 `<style>` 或 `<script>`。**标签就是点火器，顺序就是依赖顺序。**

### 3.2 运行时

```js
var OWNER='__ZML_MOUNT__', VERSION=128;
if (prev && prev.version >= VERSION) { prev.reenter(); return; }
rt.register('status-data', fn);   // 注册制：模块只关心自己的 ctx
```

- 单例 + 版本守卫 + `reenter()`。
- 模块通过 `register(name, fn)` 挂载，互不直接依赖。
- 有 `repair-*` 模块：状态栏冲突分析、版本选择、修复交互——**自诊断**。

### 3.3 字段设计（最值得抄的部分）

AI 每轮输出一个 `<zml-status>` 严格 JSON，字段自带填写规则：

| 字段 | 设计要点 |
|---|---|
| 时间 | 格式写死：`神陨历1347年3月1日·午后` |
| 大区域 | **枚举**：帝都/金穗城/渊城/翡翠联盟/炼狱魔域/深渊/未知 |
| 小区域 | 具体街道/建筑/房间 |
| 归属势力 | 枚举 + "无法判断填未知" |
| 轮次 | 数字，自增 |
| 玩家 | 姓名/社会身份/欲望/倾向/战力/持有物 |
| 本地流言 | 固定 3 条，且"来路不明、真假难辨" |
| 已激活角色 | **永久不增删**，未激活的不存在 |
| 在场角色 | 数组，每人：姓名/身份/想法（≤30 字）/状态；**严禁泄露未探查的隐私** |
| 吟游诗人传唱 | ≤200 字，后世口吻总结点评 |
| 选项 A/B/C | 概括（按钮）+ 详情（≥70 字，涵盖动机/目的/动作/心态/话语，**只填输入框不执行**） |

**四条可复用规则**：

1. **每个字段都写"填什么、怎么填、不能填什么"**，不写"自由发挥"。
2. **枚举优先于自由文本**，能让前端稳定渲染。
3. **长度写死**（30 字/70 字/200 字），否则模型一定写飞。
4. **协议里包含"示例对象"**，但标注"仅作格式示意，正式回复不带示例标记"。

### 3.4 视觉

| 项 | 取值 |
|---|---|
| 主色 | 暗金 `#d4b371`（108 次）/ `#c9a962` |
| 底 | 近黑褐 `#1c1714` / `#251e19` |
| 字 | 米白 `#e8dfd4` |
| 字体 | 衬线（Isenheim + Noto Serif SC），远程 woff2 + 本地回退 |
| 质感 | 暗金描边 + 羊皮纸暗纹，克制，不外发光 |

**可迁移的点**：暗色卡不要用纯黑 + 纯金，用"褐黑 + 旧金 + 米白"三档，才有旧物质感。

## 4. 两卡的核心差异（选型时先回答这个）

| 问题 | 示例 A | 示例 B |
|---|---|---|
| 数据谁产生？ | 玩家在 HUD 里操作 | AI 每轮输出 JSON |
| HUD 是什么？ | 可玩的界面（地图/图鉴/捏人） | 状态的镜子（渲染 AI 数据） |
| AI 提示词重点 | 文风 + 字数 + 固定尾部 | 严格 JSON 协议 |
| 前端复杂度 | 极高（完整应用） | 中（换肤 + 模块） |
| 崩了怎么恢复 | 本地存档 + 重进 | 修复模块 + 保留上次数据 |

**没有优劣**。要"玩法"选 A，要"叙事状态可视化"选 B。

## 5. 复现清单（做到这些才算"复现了方法"）

> 封面与捏人单独拆在 [43-界面-封面与捏人](43-界面-封面与捏人.md)；骨架与皮肉的分界见 [45-界面-骨架与皮肉](45-界面-骨架与皮肉.md)。**复刻模式下：工程骨架 1:1，创作皮肉必须原创。原创卡不适用这条，只受交付下限约束。**

### 结构

- [ ] `chatVersion` = 0
- [ ] 旧版导入 JSON **4 键必填**（`personality` 可携带但不读）
- [ ] 规则 `id` 唯一负整数，按执行顺序递增（`-1,-2,…`）
- [ ] 每条规则恰好 4 键
- [ ] 规则名 ≤20 字，且能一眼看出模块职责
- [ ] 总规则数 ≤130，单条 ≤20000

### 分片链（A 型）

- [ ] h / f 分段累积，launcher 校验后注入
- [ ] 片长 ≤19000（转义后）
- [ ] 切片没落在转义序列中间
- [ ] `<` `$` `\` `"` 换行 全部转义
- [ ] 标记零填充 3 位，逐条递增，链尾无残留
- [ ] launcher 失败时有可见错误，不白屏

### 模块（B 型）

- [ ] `beginning` 标签顺序 = 依赖顺序
- [ ] 单例 + 版本守卫 + `reenter`
- [ ] 每个模块 `register` 幂等
- [ ] `destroy` 清计时器/监听/节点

### 字段

- [ ] 每轮字段 ≤8 个顶层键（嵌套不算）
- [ ] 枚举字段给了完整取值
- [ ] 每个文本字段有长度上限
- [ ] 有"未知/无"的兜底取值
- [ ] 选项只写输入框，不自动发送

### 视觉

- [ ] 三色体系（底/面/强调），强调色面积 ≤5%
- [ ] 字体 ≤2 族，按用途分
- [ ] 有 1 种质感（纸/金属/噪点），不是纯色块
- [ ] 暗色不用纯黑，亮色不用纯白

### 动作（A 型）

- [ ] 每个功能至少 2 个候选选择器
- [ ] 找不到降级，不抛异常
- [ ] 删除/提交类不自动重试
- [ ] 没有接口的功能不做假入口

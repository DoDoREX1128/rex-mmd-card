# 20 · 两种环境与三条制作路线

chatVersion 表示执行环境，不是视觉开关；同层/原生描述呈现方式。先核对目标页与已有卡，再按能力和维护需求选择。纯文字可以先写内容。

## 1. 路线对照

| 项 | 新版沙盒卡 | 旧版原生卡 | 旧版同层卡 |
|---|---|---|---|
| 执行 | 公开 SDK 与受控沙盒 | 旧页正则、原生气泡或场景层 | Host 适配旧页，Frame 提供独立 UI |
| 长期界面 | sdk.stage；轻量元素可用槽位 | 文档级自建层，或逐消息组件 | 隔离 iframe 与 MessagePort |
| 原生动作 | 仅 SDK 已公开能力；edit 不代表删除/回溯 | 可按需求加经验证的 DOM 适配 | 同样需要真实 DOM 适配，不自带全部61项 |
| 持久化 | sdk.save；cache 是临时数据 | 有作品/账号/角色/会话作用域的本地实现 | Host-only 有作用域存储，Frame 不读父存储 |
| 初始化 | init --route sandbox | init --route native | init --route same |
| 构建 | build --route sandbox | build --route native | pack-samelayer |
| 静态校验 | --platform sandbox | --platform legacy | --platform legacy（same 为别名） |
| 详细文档 | 21、25、40 | 24、assets/native | 22、assets/samelayer |

旧版原生与轻量同层可组合：原生聊天保留，浮动 Frame 只做少量功能。新版全屏舞台在形态上可像独立界面，但不等于获得旧版 Host 或原生动作。

## 2. 怎么判断

1. 用户已确定新旧页时沿用，先检查要求的能力能否实现，缺口如实说明。
2. 用户只要人设、世界书、开场白时先做内容，不为架构阻塞创作。
3. 保留旧页聊天，只加气泡/KV/换肤时选旧版原生；需要独立网页信息架构时考虑旧版同层。
4. 需要新版公开 SDK、舞台或 SDK 存档时选新版沙盒，不混入旧版点火与 DOM 选择器。
5. “背包”“小游戏”“沉浸”都不足以判路线；看目标页、数据权威、需要哪些动作、是否愿意维护 Host。

找不到环境信息且会改变脚本产物时，给具体选项补问。不能为了通过某个单版本校验器，把用户旧卡直接改成新版。

## 3. 独立正则包与整卡分开

| 格式 | 顶层规则 |
|---|---|
| 新版独立正则 | 五个必填键 chatVersion=1/pageDepth/statusbar/beginning/regex_scripts；personality 可选，导入正则不写入人设栏 |
| 旧版独立正则 | 恰好四键 pageDepth/statusbar/beginning/regex_scripts，不带 chatVersion/personality |
| 每条规则 | 恰好 id/scriptName/findRegex/replaceString；新版 id 为负整数，旧版固定 -1 |
| v2 整卡 | data 下人设、开场、character_book 与 extensions.regex_scripts；不是独立正则包 |

statusbar 可以为空；纯换肤、纯人设不必造 HUD。独立世界书根 entries 对象与 v2 character_book.entries 数组必须显式转换。

## 4. 各路线最小操作

从零制作整卡时，优先用[02项目工作区](02-项目工作区与审阅交付.md)的 `project.mjs init/build`。它在同一目录规范下选择对应底层工具；下面的独立命令保留给已有工程、调试与最小机制验证，不代替用户审阅同步流程。

命令在本 skill 根目录执行；项目和输出目录可改为用户指定位置。init 默认保留已有文件；只有 --with-persona 才复制示例人设，不用 --force 覆盖用户工程。

```bash
node scripts/init.mjs --route sandbox --out work/sandbox-src
node scripts/build.mjs --route sandbox --src work/sandbox-src --out work/sandbox-out --name demo
node scripts/validate.mjs work/sandbox-out/demo-regex.json --platform sandbox

node scripts/init.mjs --route native --out work/native-src
node scripts/build.mjs --route native --src work/native-src --out work/native-out --name demo
node scripts/validate.mjs work/native-out/demo-regex.json --platform legacy

node scripts/init.mjs --route same --out work/same-src
node scripts/pack-samelayer.mjs --host work/same-src/host.js --frame work/same-src/frame.html --out work/same-out --name demo
node scripts/validate.mjs work/same-out/demo-regex.json --platform legacy
node scripts/replay.mjs work/same-out/demo-regex.json --from auto
```

新版本地壳用 preview/e2e；旧版同层用 preview-samelayer；旧版原生需针对生成 HTML 的可见交互做项目测试，不套新版 SDK mock 当兼容性证明。

## 5. 版本迁移与导入

新版交付要说明：新建卡，首次保存前选“使用新版聊天页”；给旧卡导入正则不能升级运行环境。已有卡迁移应另建目标环境，迁移内容、协议和存档，不能只改 JSON 数字。

整卡优先 PNG；v2 JSON 用于备份和封装，目标入口能否直导需验证。分离式人设另贴、世界书另导。详情见55。

## 6. 判错症状与处理

| 症状 | 排查 |
|---|---|
| SDK、data-chat、舞台都不存在 | 核对是否真的进入新版；不要只看文件的 chatVersion |
| 旧版同层被要求 chatVersion=1 | 校验器可能只支持新版，改用 legacy；旧版包也不要填0凑数 |
| Frame 正常但原生按钮没反应 | 查 Host 能力、DOM、草稿保护与让位，不假设参考动作已实现 |
| 同层包被自家校验拒绝 | 回读四键与 id=-1，不靠说明文字掩盖产物矛盾 |
| statusbar 首轮出现后不更新 | 新版静态载体不自动跟模型变，动态更新需脚本接线 |

交付前按实际路线 validate、重放注入、读取最终包结构，再报告本地/目标站/实机分别达到什么程度。

# 20 · 平台分流（动手前第一件事）

> 一句话：**`chatVersion` 决定执行模型，不是样式开关。写错不报错，功能全哑。**
> 本文只写"怎么判、判错什么样、两套路线怎么分工"。具体 API/上限以 `21-平台-新页事实.md` 与 `references/platforms/*` 为准。

---

## 1. 两条路线，互不通用

| | **旧版同层卡** | **新版沙盒卡** |
|---|---|---|
| `chatVersion` | **0**（或缺省） | **1** |
| 平台叫法 | 旧页 / `/mmd` | 新页 / 新聊天页 / 沙盒模式 |
| 运行方式 | 平台页内注入规则 + 自建 **iframe**，靠原生 DOM 桥接操作宿主 | 平台页内 `<script>` + **官方 SDK** |
| 能碰原生 DOM | ✅ 能（消息列表、输入框、弹窗都能点） | ❌ 不能（只有 `[data-chat]` 稳定钩子） |
| 原生动作 | **61 项**（编辑/删除/回溯/会话/人设/补充设定/指令/设置/分享/更多菜单） | 只能做 SDK 给的：`message.edit` / `input.set` / `stage` 等；删除、回溯、会话、人设写入都**没有** |
| 存档 | 自己 `localStorage`（单机，跨设备靠导出） | `sdk.save`（服务端，跨设备） |
| 注入载体 | 正则链（`statusbar` / `beginning` 点火） | 正则链（装卡即抽 `<script>`，不必被匹配） |
| 导入 JSON | **4 键必填**（带 `personality` 时 5 键，仍不读） | **6 键**（含 `personality`，仍不读，要另贴） |
| 上限 | 规则 ≤130 / 名称 ≤20 / 正则 ≤1000 / 替换 ≤20000 / statusbar ≤200 / beginning ≤4000 | 同上 |
| 校验器 | `node scripts/validate.mjs <json> --platform legacy` | `node scripts/validate.mjs <json> --platform sandbox` |
| 判错症状 | 被当新页 → 页面正常、按钮全哑、无报错 | 被当旧页 → `sdk` 不存在、白屏或全哑、无报错 |

本 skill 的 `validate.mjs` 用 `--platform` 区分两版，同一份代码不会给出相反建议。外部校验器（官方版、洛璃版）可作交叉复核，但它们是**单版本专用**：官方版只认新版，对旧版产物必然报错；洛璃版对 `sdk.stage` 这类命名空间写法可能误报。交叉复核的结论要按证据等级处理，不能直接照改。

## 2. 判平台的三问（按顺序问，问到就停）

```
Q1 用户说的是「同层卡 / 网页 UI / 独立页面 / 接管界面」吗？
   ├─ 是 → Q2
   └─ 否 → Q3

Q2 要不要「删消息 / 回溯 / 切会话 / 改人设 / 原生设置面板」这些原生动作？
   ├─ 要 → 旧版同层卡（chatVersion:0）
   └─ 不要，只要好看的界面 + 跨设备存档 → 新版沙盒卡（chatVersion:1）

Q3 是「状态栏 / 美化 / 纯文字卡」吗？
   ├─ 纯文字 → 平台无关，先写内容
   └─ 带脚本 → 回到 Q1，不要猜
```

判不出来就问一句，并把答案写进 `main.md`。**猜平台的代价是整卡重做。**

## 3. 旧版同层卡的两个流派（选型见 `22-平台-同层卡架构.md`）

| | **A · HUD 接管型** | **B · 原生增强型** |
|---|---|---|
| 做法 | 自建 iframe 全屏界面 + Host 适配层 + NativeBridge | 只换肤 + 自建"场景层"插在原生页上，不碰原生动作 |
| 代表 | 示例 A（100 条规则 / 1.87MB） | 示例 B（68 条规则 / 633KB） |
| 适合 | 要全套原生动作、要重做信息架构 | 想保留原生聊天手感、只做视觉与场景包装 |
| 风险 | 平台 class 改版 → 适配层全废 | 原生 DOM 一变 → 场景层错位 |
| 工作量 | 高（Host + Frame 两套） | 中（CSS + 模块注册） |

两条都不是"低级/高级"，是**不同的产品形态**。先选形态，再写代码。

## 3.5 新页（chatVersion:1）能不能做同层卡 / 原生增强？

这是最常被问、也最容易被"看起来能做"骗过去的问题。

| 想做 | 新页能不能 | 证据/原因 |
|---|---|---|
| **同层卡**（iframe 全屏 HUD + NativeBridge + 61 动作） | ❌ **不能** | 平台白名单直接删 `iframe`；没有 NativeBridge；删除/回溯/会话/人设写入都没有 SDK 接口 |
| **原生增强**（换肤 + 气泡增强 + 自建层） | ✅ **可以，但有限** | 29 个 `--chat-*` 变量、`[data-chat]` 稳定钩子、`message:mount`、`sdk.stage`。只能走官方表面，不能点原生弹窗内部 |
| **形态上的"类同层卡"**（全屏面板） | ✅ 可以 | `sdk.stage.open('full')` 能放长期全屏面板；但能力上限是 30 项 SDK，不是 61 项 |
| **让玩家删消息/回溯/切会话** | ❌ 不能 | SDK 只有 `message.edit`；没有删除、回滚、会话管理 |

**四句话结论**：

1. **同层卡在新页不是"难"，是物理上不存在**——iframe 被删，桥没有，动作没有。
2. **原生增强可以做**：换皮、气泡挂件、封面/捏人/百科这类"自建层"都可以，只要不碰原生弹窗内部。
3. **想要全屏 HUD 形态**可以用 `sdk.stage`，但要接受"没有原生动作"这个上限。
4. **必须要 61 项动作 → 只能旧版 0**。这是架构分叉，不是实现细节。

> 判断口诀：**"要动原生按钮/弹窗" → 旧版 0；"只要长得像、能存档" → 新版 1。**

## 4. 交付物差异

### 旧版同层卡

```
<短名>-regex.json     4 键必填：pageDepth / statusbar / beginning / regex_scripts（可带 chatVersion:0）
<短名>-persona.txt    人设（手贴创卡页）
<短名>-worldbook.json 世界书（根对象只留 entries，单独导入）
<短名>-manifest.json  规则数 / 最大条 / payload sha / 证据等级
```

- 导入 JSON **不要**放 `personality`（旧版导出就是这么干的，见示例 A / B）。
- 界面触发串必须在 `beginning` 或 `statusbar` 里，否则规则永远不点火。
- 分片链的最后一条必须是 launcher，把累积载荷注入 `<script>`；**链尾不能残留 marker**。

### 新版沙盒卡

```
<短名>-regex.json     6 键：chatVersion=1 / pageDepth / statusbar / beginning / personality / regex_scripts
<短名>-persona.txt    人设（必须另贴）
<短名>-worldbook.json 世界书
```

- 可见 UI 的触发串必须在 `beginning` / `statusbar` / AI 输出里。
- 全屏 HUD 用 `sdk.stage`，不要 iframe + 宿主桥（跨源，那套在新页失效）。

## 5. 事故模式：用错校验器把正确值改错

**触发条件**：旧版同层卡用新页校验器复验。校验器报「chatVersion 必须是 1」，照改。

**后果**：导入后被当成新页处理，同层 iframe、原生桥接与 61 项动作全部失效，页面不报错。

**同类模式**：

1. 校验器是单版本专用的，选错等于把正确值改成错误值；
2. 平台版本字段要在交付前单独断言一次，不能只信构建脚本；
3. 文档写 0、产物写 1 这类矛盾，交付前必须回读产物，不能只看 `main.md`。

**处置**：改回正确版本值，用本 skill 的 `validate.mjs --platform` 复验，重跑 manifest 与 `replay`。

---

## 6. 迁移与限制

- **同层卡不能升级成新页**，新页也不能降级成同层卡。`chatVersion` 只在**新建卡导入**时被读取，导入到已有卡会被忽略。
- 想换路线 = 新建一张卡，重新导入。
- 同一张卡里**不要混两套点火器**（`img onerror` 与 SDK 生命周期），净化规则不同，必有一边失效。

## 7. 交付前自检（30 秒）

```bash
node scripts/validate.mjs card-regex.json --platform auto
```

- 旧版：`chatVersion === 0`、4 键必填、`beginning` 里有起点标记、链尾无残留
- 新版：`chatVersion === 1`、6 键、`personality` 另附

任一不符，停下来改，不要"先导入看看"。

# 41 · 界面基线

> 这是一把**分基线的尺子**，不是唯一版式。
> 先声明这张卡用哪条基线，再按该基线量；**通用下限**对三条基线都成立。
> 术语见 [45](45-界面-骨架与皮肉.md)：结构属于工程骨架，观感属于皮肉，下限是另一层。

---

## 0. 先选基线

| 基线 | 形态 | 适用 | 典型核心循环 |
|---|---|---|---|
| **A · 列表型** | 世界条 + 列表/详情 + 人物档案 | 人物多、地点多、需要"翻名册" | 探索、对话、关系推进 |
| **B · 仪表盘型** | 多面板同屏（资源 / 地图 / 任务 / 日志） | 同时盯多个数值 | 经营、养成、策略 |
| **C · 单页流** | 一列滚动叙事，状态折叠在页首或浮层 | 线性剧情、单场景、短篇 | 悬疑、视觉小说、一次性体验 |

选错基线的代价：A 的卡硬套 C 会失去人物密度；C 的卡硬套 A 会出现大量空列表。

**通用下限（三条基线都要过）**

1. 首屏可读：不白屏，第一眼知道"我在哪、我是谁、下一步做什么"。
2. 主操作可达：手机上拇指能碰到，不被底栏或浮层挡住。
3. 三态齐备：空 / 加载 / 错误都有明确文案，不出现"空白 + 无提示"。

低于这三条，不论哪条基线都不合格；高于这三条属于创作空间，本文不设上限。

---

这些字号是可读性起点，不代表默认骨架每处已达到；按实际字体、缩放与设备验收。

## 1. 基线 A · 列表型

### 1.1 三段式

```
顶部世界条     3–5 个短值，一屏能看到"什么时候、在哪、什么状况"
      ↓
列表 + 详情    左侧简要（名字 + 两三个标签），右侧全部
      ↓
人物档案       基础（键值行）→ 心里（一句）→ 印象（一两句）
```

三层各有读者：扫一眼看世界条，坐下来看键值行，看人看心里那层。

**这是 A 的结构，不是所有卡的结构。** 用 B 或 C 时，这一节整段跳过。

### 1.2 世界条：短值不占宽

```
时 · 地 · 区 · 天 · 势          （示例：5 格单字标签）
```

- **宽度跟内容走，不做等分**：`flex: 0 1 auto` + `gap`，短值自然窄。
- 单字标签是 A 的惯例（余光扫的，不是读的）；换成两字标签也成立，只要总格数 ≤5。
- `loc` 与 `region` 建议分两个字段：一级地名 + 二级区域，比塞一个长字符串有用。

这条属于**内容设计建议**（怎么切字段），不是视觉规范。

### 1.3 键值行

```css
.rowline{
  display: grid;
  grid-template-columns: 4.2em minmax(0,1fr);   /* 标签定宽，值吃满 */
  gap: 8px; padding: 5px 9px; margin: 2px 0;
  background: rgba(255,255,255,.022);
  border-left: 2px solid var(--line3);
}
```

三个细节值钱：

1. **标签定宽**（中文 2–4 字用 4.2em 刚好）：值永远左对齐，不跳。
2. **左竖线代替 bullet**：比圆点安静，比缩进明确。
3. **极淡底纹**（2% 白）：几乎看不出，但行与行有块感。

**不要两端对齐**：标签在左、值在右、中间一大片空白，读起来像账单。

### 1.4 心里那层

每个 NPC 允许一句 `thought`：没说出口的那句话。

- 只写一句，写不成一句就不写；
- 它是档案里唯一"不客观"的内容，不要拿它写设定；
- 单独渲染成一块，与键值行对齐，用次要色。

数据（资源、关系）让人知道"她是什么状态"，心里那句话让人知道"她怎么想的"。后者才是戏。

## 2. 基线 B · 仪表盘型

```
┌─ 顶栏：资源 3 项 + 时间 ──────────────┐
├─ 左：地图 / 场景      ├─ 右：任务 / 日志 ┤
├─ 中：主面板（当前操作）                  │
└─ 底：行动条（2–4 个主操作）────────────┘
```

- **验收要点**：同时可见的信息不超过 3 组；每组有明确标题；主面板永远只做一件事。
- **风险**：面板越多越像后台系统；用"一屏一决策"约束自己。
- **不适合**：人物关系为主的卡（人会变成表格行）。

## 3. 基线 C · 单页流

```
页首：状态折叠条（点开才是完整状态）
正文：叙事流（一次一屏或连续滚动）
页尾：选项 / 输入
```

- **验收要点**：滚动中状态不丢；选项出现时不被键盘遮挡；回到顶部能看到当前处境。
- **风险**：状态不可见导致玩家忘了数值；用页首折叠条或每 N 轮插入状态卡解决。
- **不适合**：需要频繁对比多个对象（人物/物品）的卡。

## 4. 配色：哑色策略

### 4.1 彩度是参数

| 题材 | 主色起点 | 文字起点 |
|---|---|---|
| 古风 / 末世 / 民国 | `#c9a962` 哑金 | `#e8dfd4` 暖白 |
| 赛博 / 科幻 | `#6fe3c4` 高彩青 | `#f4fbff` 冷白 |
| 校园 / 日常 | `#7fb2c9` 中彩蓝 | `#2a2a2a` 深灰（浅底） |

**这些是起点值，不是唯一解。** 推色两条规则：

1. 彩度随"时代与材质"走：旧时代/旧材质降彩度，新科技提彩度；
2. 明度随"场景光线"走：夜戏压暗底、日戏提亮底，但正文对比度不低于 4.5:1。

### 4.2 描边：默认策略 + 两个可选

```css
/* 默认：主色 + 透明度，三级 */
--line:  color-mix(in srgb, var(--accent) 20%, transparent);
--line2: color-mix(in srgb, var(--accent) 32%, transparent);
--line3: color-mix(in srgb, var(--accent) 52%, transparent);
```

| 策略 | 适用 | 注意 |
|---|---|---|
| 主色 + 透明度（默认） | 暗底、器物感、古风/废土 | 三级够用，不要超过三级 |
| 实色细线 | 浅底、极简、纸张感 | 线与底对比 ≥1.5:1，否则看不见 |
| 无描边，用间距分组 | 现代扁平、信息密集 | 依赖留白与字重，排版要更克制 |

**验收口径改为"同一套内保持一致"**，而不是"必须主色 + 透明度"。

## 5. 名字块（可选）

```css
background: linear-gradient(110deg, rgba(37,27,20,.9), rgba(59,43,29,.55));
border-bottom: 1px solid var(--line3);
width: max-content;
padding: 5px 12px 6px;
```

`width: max-content` + 斜渐变 + 下沿亮线 = 一块铭牌；撑满宽度就变成标题栏。

这是 A 的一种做法；B/C 可用纯文字标题、标签条或角标，不必照搬。

## 6. 字号与密度

参考区间（按基线调）：

| 项 | A 列表型 | B 仪表盘 | C 单页流 |
|---|---|---|---|
| 标签 | 12–14px | 12–14px | 12–14px |
| 值/正文 | 14–16px | 14–16px | 14–18px |
| 名字/标题 | clamp(17px, 2vw, 24px) | 16–20px | clamp(20px, 3vw, 28px) |
| 行高 | 1.75–1.85 | 1.5–1.7 | 1.8–2.0 |

原则：**字号、行高与密度应共同服务阅读**。具体数值按字体与屏宽调，不必卡死。

---

## 7. 白名单 vs 开放字段

| 做法 | 收益 | 代价 |
|---|---|---|
| 白名单（`content.status.fields` 决定） | 顺序与视觉可控；未知字段不伪造 UI | 模型多给的字段被丢 |
| 开放字段 | 灵活 | 侧栏变流水账；未知字段成为伪造 UI 的入口 |

**默认白名单**；确有"玩家自定义字段"需求时，走单独的自定义区，并做类型白名单，不要放开全局。

---

## 8. 一分钟版

**通用**

1. 首屏可读、主操作可达、三态齐备。
2. 同一套内描边/字号/间距保持一致。
3. 手机不是桌面缩小：主操作与阅读区按移动任务重排。

**基线 A 追加**

4. 世界条短值不占宽，不做等分。
5. 键值行标签定宽、值左对齐、左竖线。
6. 名字块宽度跟内容走，不撑满。

# 40 · 新版骨架、模块与扩展

适用新版沙盒卡。旧版原生读24，旧版同层读22。下面区分默认实现与设计建议，不能把这里的REX接口当作平台SDK。

## 1. 分层与职责

```text
宿主：消息、输入、公开槽位与舞台
内核：window.__REX__，版本/事件/槽位/场景
进度：store.js与status.js，保存/白名单/快照/恢复
视图：导航、简要、详情、移动抽屉、可选封面捏人
内容：content.json，题材、主题、字段、地图、NPC、文案
```

state是运行态（当前nav/key、宽窄模式、抽屉与场景），data是游戏进度。模块通过REX对象约定接口，不从另一个规则的局部变量取数据。题材变更优先改内容和项目模块，不把NPC名写进通用内核。

## 2. 当前模块与依赖

项目modules.json存在时覆盖build默认表，顺序就是执行顺序。以下是当前默认起点，不是所有作品必须有的数量：

| 源文件 | 作用与依赖 |
|---|---|
| core.js | 创建REX、SDK适配、事件、槽位、场景、destroy；先加载 |
| store.js | 保存、槽位、恢复、发送锁；依赖core |
| ui.js | HTML转义后的行/卡/标签等UI原子与图标 |
| view.js | 导航/列表/详情/抽屉装配；定义boot，延后读取内容 |
| content.json | 挂window.__REX_CONTENT__；必须在boot实际运行前可读 |
| base.css / skin.css | 布局与组件皮肤；作用域不能套给旧版 |
| sections.js | 用REX.section注册世界/人物/地图等默认栏目 |
| status.js | 解析[status]、裁剪、同轮替代、快照与事件接线 |
| scenes.js | 可选封面/捏人；features控制是否进入 |
| saves.js | 存档栏目和对应用户操作 |
| ping.js | build额外生成重入点火，放statusbar，不必写进modules.json |

构建器另加status-hide与主题规则。不要继续按旧文档写死“13条”或默认加载figdata/figure/dossier；这些现在属于可选kit。

## 3. 当前REX接口

| 接口 | 含义 |
|---|---|
| R.content() | 读取项目content；初始化后有缓存，不能假设改全局对象就会热更新 |
| R.section(id,{title,icon,brief,detail,after?}) | 注册栏目；brief返回key/head/meta等行，detail返回HTML，after接收到已挂载详情 |
| R.scene(id,{render,after?}) / R.go(id) | 注册和进入舞台场景，render返回DOM节点 |
| R.nav(id) / R.pick(key) / R.back() | 导航与详情返回；不需要时不调用未定义的旧definePanel/defineScene |
| R.fillInput(text) | 填原生草稿与聚焦，返回是否成功；默认不自动发 |
| R.writeDraft(text) | 等待SDK输入写入结果；创建提交流程使用，失败不退出创建页 |
| R.confirmSend(text) | 玩家确认后的发送锁与一次性续档处理，store提供 |
| R.on / R.listen / R.timer | SDK订阅、DOM监听、受跟踪计时器；清理见destroy |
| R.stageOpen / stageEl / stageClose | 包装公开舞台接口，缺能力明确降级，不伪造父层能力 |

旧文档的definePanel/goScene/register示意并非当前骨架方法，扩展时以上表与源码为准。SDK名称和签名只查25。

## 4. 新增一个栏目：完整最小例子

在项目新增quests.js，把它以js模块放在ui/content之后、boot执行之前：

```js
(function () {
  var R = window.__REX__;
  if (!R) return;
  R.section('quests', {
    title: '委托', icon: 'world', empty: '暂无委托',
    brief: function (r) {
      return ((r.content().quests || [])).map(function (q) {
        return {key:q.id,head:q.title,meta:q.note || ''};
      });
    },
    detail: function (r, key) {
      var q = (r.content().quests || []).find(function (x) { return x.id === key; });
      return q ? '<p>' + r.esc(q.note) + '</p>' : r.ui.empty('未找到委托');
    }
  });
})();
```

modules.json追加{name:"rex-quests",file:"quests.js",kind:"js"}，content.json增加quests:[{id:"q1",title:"一封信",note:"找到信的收件人"}]。然后build→validate→preview点击该栏目。这里是静态资料示例；若要模型动态更新任务，还必须扩展状态白名单和cleanData存档字段，不能只加UI就宣称任务进度可保存。

## 5. content主要契约

```json
{
  "meta":{"name":"river","title":"河畔来信","version":"1.0","opening":"守船人递来一封信。"},
  "features":{"cover":false,"forge":false,"bodyDossier":false},
  "storage":{"key":"rex:river","maxSlots":8},
  "theme":{"dark":{"bg":"#10161c","text":"#e8edf2"},"light":{"bg":"#f5f7f6","text":"#182b25"}},
  "world":{"era":"河畔小镇","rule":"人物只知道自己接触到的信息"},
  "player":{"fields":[{"key":"name","label":"姓名","type":"text","maxLength":20}]},
  "status":{"fields":[{"key":"hp","label":"体力","type":"bar","max":100},{"key":"loc","label":"地点","type":"text"}]},
  "map":{"nodes":[{"id":"dock","name":"渡口","x":18,"y":62,"links":[]}]},
  "npcs":[],"codex":[],"bag":[]
}
```

- player.fields用于捏人，不等同status.fields。创建选择到状态初值的映射需项目定义，选“好手”不会自动改变任意能力字段。
- status支持bar/num/tag(tags兼容)/text；字段名、范围、maxLength同步模型协议。数组不是随意嵌套对象的通行证。
- 地图x/y按0–100百分比设计；links应指向存在id。模型loc与地图地点映射需一致。
- NPC的key稳定；当前模型更新只允许已声明NPC及status.js支持的字段，详情看30和源码。
- bodyDossier仅是项目意图标识，不能单靠true自动安装kit；要复制模块并修改modules.json。
- theme.dark/light用于构建器颜色映射；theme.cover用于封面背景，其余布局/字体可按作品CSS定制，不能把配置键写出来就假设代码读取。

## 6. 场景与开局组合

| cover | forge | 无存档启动 |
|---|---|---|
| false | false | 直接主界面 |
| true | false | 封面→开始→主界面 |
| false | true | 直接捏人→草稿提交→主界面 |
| true | true | 封面→捏人→草稿提交→主界面 |

有有效自动档时恢复主界面；捏人返回保留选择，无封面时返回主界面。封面和捏人只在选用时进入sdk.stage.full；默认主界面是聊天页内导航/抽屉，不是原文描述的“所有main都在content舞台”。需要长期游戏画布可设计为舞台，由项目选择。

## 7. 双端布局与滚动

当前宽屏≥1024为导航/简要与详情区域，窄屏为底部导航+抽屉；断点和宽度可按作品调整，不是平台限制。目标是保留原生聊天、输入可达，手机不能只是桌面等比缩小。

```css
.rex-panel { display:flex; flex-direction:column; min-height:0; }
.rex-panelBody { flex:1; min-height:0; overflow-y:auto; }
```

min-height:0让flex子项允许收缩，否则滚动区可能被内容撑开。测长列表、短视口、键盘弹出、横屏与底部安全区；不要写死宿主顶栏/输入栏高度。框架metrics从真实节点测量顶部、底部与抽屉位置。

## 8. 更新、焦点与生命周期

重复点火不叠实例，旧版本destroy后再装；气泡用mount/unmount，长期订阅顶层建立，切会话重读进度。destroy需释放监听、定时器、observer、画布/纹理与注入节点；不把函数名存在等同已完整清理。

设计目标是相同视图更新保留滚动/焦点，切到新对象再按需求复位。当前默认detail/抽屉主要通过HTML刷新，**并非全量实现逐字段增量渲染**；复杂编辑器应给模块自己的稳定DOM、更新函数与清理。不要在after每次往常驻节点叠监听；输入未提交内容要单独保存，不让模型更新吞掉草稿。

## 9. 构建、预算与交付

build按modules.json把文件包成style/script，规则顺序与依赖一致；beginning放注入标记+开场，ping在statusbar。超20000字时先按关注点拆文件；自动拆分仅尝试特定缩进下的REX.register/section/scene边界，每块须语法有效，失败就报错，不对任意JS硬切。

用自定义模块表时保留实际依赖；build仍需content.json和ping.js，不能把它当任意网页打包器。生成protocol.txt与常驻输出条目时核对模型侧内容；人设文件按需，不自动合成模板。worldbook到v2显式转换，PNG仅是封装。

验证模块依赖、第一次/二次进入、窄宽切换、两轮状态与坏数据、手动存档、草稿发送和销毁。专用组件与新扩展要增加实际行为用例，不能只凭默认e2e通过宣布自定义功能完整。

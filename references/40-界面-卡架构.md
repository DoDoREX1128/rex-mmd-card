# 40 · 卡架构（新页）

## 0. 五层，从上到下不得越层

```
┌ 宿主层  平台聊天页：消息流、输入框、原生弹窗、主题变量
├ 内核层  window.__REX__：版本守卫 / 模块注册表 / 场景栈 / 存档 / 事件总线
├ 场景层  封面 → 捏人 → 主界面（互斥，同一时刻只有一个场景可见）
├ 面板层  状态 · 地图 · 百科 · 背包 · 设置（主界面内切换，不重建 DOM）
└ 内容层  content.json：题材、配色、字段、节点、NPC、文案
```

**越层即返工。** 内容层永远不写逻辑；面板层永远不碰存档；内核层永远不知道"江湖"还是"赛博"。

## 1. 内核：`window.__REX__`

```js
var OWNER = '__REX__', VERSION = 1;
var prev = window[OWNER];
if (prev && prev.version >= VERSION) { prev.reenter(); return; }
if (prev && prev.destroy) prev.destroy();

var REX = window[OWNER] = {
  version: VERSION,
  ready: false,
  modules: Object.create(null),
  scenes: Object.create(null),
  current: null,
  state: Object.create(null),   // 运行态：当前场景、面板、滚动位置
  data: Object.create(null),    // 玩家进度：从 sdk.save 读出来的快照
  register: function (name, fn) { if (!this.modules[name]) this.modules[name] = fn; },
  boot: function () { /* 按依赖顺序调 modules */ },
  defineScene: function (id, def) { this.scenes[id] = def; },
  goScene: function (id, arg) { /* 淡出旧场景 → 挂新场景 → 淡入 */ },
  get: function (k) { return this.data[k]; },
  set: function (k, v) { this.data[k] = v; this.persist(); },
  persist: function () { /* 防抖写 sdk.save，失败 .catch 记 debug.log */ },
  reenter: function () { /* 二次进入：重建舞台挂载，不重跑 bootstrap */ },
  destroy: function () { /* 解绑全部监听、清计时器、关舞台 */ }
};
```

**四条纪律**

1. **版本守卫必须第一句**。用户二次进入、切会话回来、分享页打开，都会重跑脚本，没有守卫就叠实例（症状：按钮点一次触发两次、存档被旧副本覆盖）。
2. **一条规则一个模块**，靠 `REX.register('panel-status', fn)` 挂进来。规则之间**不直接引用彼此的函数名**——只通过注册表。
3. **运行态（`state`）与进度（`data`）分开**。`state` 刷新即失，`data` 才进 `sdk.save`。
4. **`destroy` 必须真的拆干净**：`sdk.on` 的返回值是解绑函数，存进数组，destroy 时逐个调。

## 2. 场景栈

三个场景，互斥。`goScene` 只做三件事：淡出旧场景 → 清旧 DOM → 挂新场景。

| 场景 | 何时进入 | 承载 |
|---|---|---|
| `cover` 封面 | 首次进入、无存档 | 主视觉、标题、开始/继续/设置 |
| `forge` 捏人 | 点「开始」且无存档 | 姓名/性别/种族/倾向/战力/背景，选项即初值 |
| `main` 主界面 | 捏人完成、读到存档 | HUD + 面板容器 + 选项区 |

**舞台策略**：`sdk.stage.open('full')` 承载 cover 与 forge（沉浸、无干扰）；`main` 用 `'content'`（保留顶栏与输入框，玩家还能看聊天）。这条是刻意的——捏人是"一次性仪式"，主界面是"长期战场"，混用会两头不讨好。

**返回键**：`sdk.on('back')` → 在主界面则退回上一个面板，在面板则回主界面，在封面则什么都不做（交给平台关舞台）。

## 3. 面板注册表

```js
REX.register('panel-status', function (REX) {
  REX.definePanel('status', {                 // 注意是 definePanel(id, def)，不是直接塞 REX.panels
    title: '状态',
    render: function (REX, node) { /* 建 DOM，只读 REX.data，不写 */ },
    update: function (REX, node) { /* 增量改 textContent / style.width，不重建 */ }
  });
});
```

| panel id | 职责 | 数据来源 |
|---|---|---|
| `status` | 属性 / 资源条 / 关系 / 状态标签 | `data.status`（AI 输出块） |
| `map` | 节点图 + 当前所在地 + 可去地点 | `data.map` + `content.map` |
| `codex` | 已解锁的百科条目 | `data.codex` |
| `bag` | 道具 / 装备 / 消耗 | `data.bag` |
| `set` | 字号、动效、存档管理 | `data.settings` |

**`render` 只在首次挂载时调，`update` 负责后续。** 每次切面板都 `innerHTML = ''` 重建，会让滚动位置和动画状态全部丢失，这是最容易被吐槽的体验缺陷。

**点当前已开的 tab 是空操作**（`if (REX.state.panel === id) return;`）。别做成 toggle——关掉之后中央一片空白，用户会以为卡坏了。关面板交给返回键 `back` 与 `closePanel()`。

### 3.1 可选行动条（`data.opt`）

AI 每回合在状态块里给 `opt: [最多 3 条]`，主场景渲染成底部行动条（`REX.renderOpts()`，由 `renderHud` 每帧驱动）。

```js
REX.pickOpt = function (v, el) {
  REX.sdk.input.set(v);        // 只写进输入框
  REX.sdk.input.focus();
  REX.toast('已填入输入框，确认后发送');
};
```

**只写不代发。** 平台的 `message.send` 在多数版本会 `NOT_SUPPORTED`，更关键的是代发等于替玩家做了决定——玩家想改一个字都没机会。行动条的价值是"不用打字"，不是"不用思考"。

## 4. 双端布局（应用外壳，不是"长页面"）

主场景是一个**固定高度的应用外壳**：HUD 钉顶、面板区独立滚动、可选行动条 + 标签栏钉底。桌面端把同一套东西横过来变成三区。**不是整页往下滚**——整页滚的卡在手机上会把标签栏滚出屏幕。

| 断点 | 布局 | 导航 |
|---|---|---|
| < 1024 | 单列外壳：HUD / 可滚面板 / 行动条 / 底部 5 格 tab | 底部 tab，`order:2` |
| ≥ 1024（`data-layout="wide"`） | 三区栅格 `196px / 1fr / 272px` | 左栏竖排 tab（`grid-auto-flow:row`），中区面板，右栏常驻状态 |

实现要点（改之前先看 `base.css` 的骨架段）：

```css
.rex-scene[data-rex-scene="main"]{height:100vh;overflow:hidden}
.rex-scene[data-rex-scene="main"] .rex-body{flex:1;min-height:0;overflow:hidden;padding:0}
.rex-scene[data-rex-scene="main"] [data-rex-panelhost]{flex:1;min-height:0;overflow-y:auto}
```

- **`min-height:0` 不能省**，否则 flex 子项按内容撑高，`overflow-y:auto` 永远不触发。
- **右栏不是装饰**：桌面端把 `体力/存水/所在/时历/相关人物` 常驻在右栏，用户不用点开"状态"就能看见——这才是"同层 HUD"。手机端右栏 `display:none`，同样信息在底部"状态"面板里。
- **左右留白只在 `.rex-body` 上，主场景要 `padding:0`**：主场景的留白由面板/行动条/标签栏各自带；封面和捏人靠 `.rex-body` 的 `padding:0 var(--rex-pad)`，别为了主场景把这条删掉。
- **封面** `.rex-coverMark` 是纯 CSS 大字水印（标题首字，`opacity:.05`），不依赖任何图片；顶部 `.rex-eyebrow` 用 `margin-bottom:auto` 顶上去，和底部标题形成上下对角构图。没有 `theme.cover` 图时也立得住。
- **捏人页必须自己滚**：`.rex-scene[data-rex-scene="forge"]{height:100vh;overflow-y:auto}`。维度有 7 组，390×844 放不下，靠宿主的 `overflow:hidden` 会把"战力/初始所在地/背景补充"永远藏在屏幕外（这是骨架实际遇到的问题，`e2e.mjs` 有断言专门覆盖）。

**只用 CSS 栅格，不用 UA 判断。** 手机横屏（`orientation:landscape` 且高度 < 500）单独收一版：HUD 压成 44px 横带。

**PC 专属增强**：`@media (hover:hover)` 才给悬停态；`pointer:coarse` 隐藏 `⌘/Ctrl` 快捷键提示。触屏设备不该看到"按 E 打开背包"。

## 5. 规则拆分（当前骨架的 13 条）

**先讲原则，再看这份清单**：不是所有卡都必须 13 条，也不是每条都必须叫这个名字。

| 原则 | 说明 |
|---|---|
| 按关注点切 | 几何 / 数据 / 档案 / 视图 / UI 原子 / 状态 / 场景，各自独立，改一处只动一条 |
| 每片 8–15K 为目标 | 上限是 `replaceString` 20000 字；超了先按关注点拆，不要按字数硬切 |
| 一文件一规则 | 便于 `build.mjs` 自动打包与定位错误 |
| 顺序即依赖 | `<script>` 被抽出后按出现顺序执行，被依赖的模块放前面 |

下面是**当前骨架**的拆分结果（`build.mjs` 顶部的 `MODULES` 表是唯一真相）：

| # | scriptName | 源文件 | 内容 | 入口 |
|---|---|---|---|---|
| 1 | `rex-boot` | `core.js` | 状态 / 宿主适配 / 槽位 / 实测 / 舞台 | beginning |
| 2 | `rex-ui` | `ui.js` | UI 原子（行/卡/标签/正文）+ 内联图标 | beginning |
| 3 | `rex-view` | `view.js` | 四区装配 / 渲染 / 事件 / 存档 / boot | beginning |
| 4 | `rex-content` | `content.json` | `window.__REX_CONTENT__` 题材数据 | beginning |
| 5 | `rex-css` | `base.css` | token / 四区 / 窄屏抽屉 | beginning |
| 6 | `rex-skin` | `skin.css` | 档案 / 舞台 / 封面 / 捏人 / 行动条 | beginning |
| 7 | `rex-sections` | `sections.js` | 世界 · 人物 · 地图 · 见闻 · 行囊 · 设置 | beginning |
| 8 | `rex-figdata` | `figdata.js` | 整身图 / 部位特写图 / 逐行轮廓 / 热区标定 | beginning |
| 9 | `rex-figure` | `figure.js` | 人形渲染 · 兜底剪影 · 部位热区 | beginning |
| 10 | `rex-dossier` | `dossier.js` | 人物档案（表层 / 里层）HTML 与交互 | beginning |
| 11 | `status` | `status.js` | 状态解析 / 裁剪 / 接线 / 修复提示 | beginning |
| 12 | `rex-scene` | `scenes.js` | 封面 · 捏人（`REX.scene`） | beginning |
| 13 | `rex-ping` | `ping.js` | 重入点火（轮询等内核） | **statusbar** |

**为什么是 13 条**：因为「内核 + 视图」放一起 24K、「几何 + 档案」放一起 21K，都过不了 20000 字上限；按关注点拆完后每条落在 8–15K。换一套骨架、换一种模块划分，条数会变——**原则不变，数字可变**。

**`beginning` 里的标记串顺序 = 依赖顺序**（`<script>` 被抽出后按出现顺序执行）：

```
【rex-boot】【rex-ui】【rex-view】【rex-content】【rex-css】【rex-skin】
【rex-sections】【rex-figdata】【rex-figure】【rex-dossier】【status】【rex-scene】
```

标记用中文方括号、不带尖括号：方括号不是 HTML 标签，可避开创卡页对 `findRegex` 的标签文案禁令，也不受正则转义影响。`[status]` 是内容协议标记（方括号），只出现在模型正文与解析脚本里，不在这个串中；它必须由一条替换规则消耗，见 [30](30-内容-状态与字段.md) §2.1。

`rex-figdata` 必须在 `rex-figure` 前（后者读 `window.__REX_FIG__`），`rex-figure` 必须在 `rex-dossier` 前（后者调 `REX.figHTML`）。

`beginning` 正文（玩家看见的第一句话）放在标签串**之后**，两者用空行隔开——标签串被替换成 DOM 或空，玩家看不到。

要点：

- **`meta.adult` 只是个标记**，不要围绕它写开关逻辑；内容由作者定，不设档。
- **`status` 里直接放 `desire` / `intimacy`**，不要另开独立区块。少一层结构就少一处对不上。
- **`npcs[].sex` 决定里层画哪套部位**：`f` → 口腔/乳房/子宫/阴部/后庭；`m` → 阴茎/阴囊。
- **`npcs[].priv` 的键必须和性别对应**（f：口腔/乳房/子宫/阴部/后庭；m：阴茎/阴囊），否则热区点了没卡。
- `st` 是部位特写图的选图键，**每个部位支持的档位不同**：

  | 部位 | 可选档位 |
  |---|---|
  | 口腔 · 乳房 | `干净` / `沾染精液` |
  | 阴部 · 后庭 | `干净` / `被外射` / `被内射` / `被同时内外射` |
  | 子宫 | 不按档位，走 0/33/66/100 四张 |
  | 阴茎 · 阴囊 | 只有 `干净`，且**不出图**，界面只显示文字 |

  写了不支持的档位会被裁到 `干净`。档位表在 `figure.js` 的 `STLEVELS`，改档位只改那一处。
- **`fixed` 换场景还成立，`rt` 只有此刻成立。** 判据只有这一条；`fixed` 写具体到能画出来的细节，不写形容词。
- `ml` 是 0–20 的残留量，界面按 `ml/20` 画条；只有 `子宫` 用 `spec` 存量表。
- **`surface` 是表层能看的**，3–6 条，全是一句话；`hooks` 是印象，不是设定。
- **`thought` 是没说出口的那句话**，只写一句。它是档案里唯一"不客观"的内容，别拿它写设定。
- **`loc` 与 `region` 是两级地名**：`loc`=渡口，`region`=南岸。分开写比塞一个长字符串有用——世界条上两个格子，一长一短，密度才立得住。
- 旧的 `panels` / `r18` 字段已删除——栏目顺序在 `sections.js` 里定死。`

**硬规则**

- `status.fields` ≤ 8 个。超过的拆成 `panels` 里的子页，不要堆 HUD。
- 每个 `status` 字段必须有 `key/label/type`；`type` 只允许 `bar | text | tag`。前端按白名单裁剪，模型多吐的键直接丢。
- `map.nodes[].x/y` 是 **0–100 百分比**，双端自适应；`links` 必须是存在的 id。
- `npcs[].key` 与 `status` 里关系字段的键同名，一处定义两处用。
- `theme.cover` 用远程图必须 HTTPS 且域名在平台白名单内；本地图只能 base64 且总量 ≤ 200KB。

## 7. 原生动作适配（不重造轮子）

| 原生动作 | 怎么做 | 不做 |
|---|---|---|
| 消息编辑 / 删除 / 回溯 | 引导用宿主原生面板；需要页内触发时用 `sdk.message.edit` | 自己实现历史管理器 |
| 会话切换 | `conversation:switch` → 清 cache、重读 save、重挂场景 | 自己存会话列表 |
| 输入框 | 选项按钮只 `sdk.input.set` 进草稿并聚焦，**不 send** | 点了就替玩家发送 |
| 模型/设置等宿主弹窗 | **跳原生**。宿主页面板在跨源 iframe 外，卡片 CSS 打不到，如实说明做不到；详见 [47](47-界面-宿主与弹窗边界.md) | 重画一套设置页；写 `.model-setting-scope` 之类裸选择器 |
| 返回 | `sdk.on('back')` 逐层退 | 拦截并吞掉返回 |
| 存档 | `sdk.save` 单对象装 `auto` + `slots`；宿主上限由平台下发，不写死 10。多槽与续档见 [33](33-内容-存档与续档.md) | 一槽一键；自己拼 localStorage |
| 舞台 | 长期面板挂 `sdk.stage.el()` | 挂气泡里 |

**「一点即发」默认关闭。** 玩家点选项 → 文字进舞台内输入框 → 玩家可改 → 点确认才 `message.send`。这条写进 `settings.choiceBehavior`，默认 `stageDraft`。

## 8. 分块策略（超 20000 字自动触发，已实测）

**触发条件**：某个 JS 模块包上 `<script>` 后超过 20000 字。

**做法**：`build.mjs` 的 `splitModule()` 在这些位置切开——**顶层 `REX.register(` 的缩进边界（两个空格）**，然后每块补回原 IIFE 的头部（`var REX = window.__REX__; var C = ...; var esc = ...`），重新包成一个完整 IIFE：

```js
// 原文件
(function () { var REX = window.__REX__; var C = ..., esc = ...;
  REX.register('scene-cover', ...);
  REX.register('scene-forge', ...);
  REX.register('scene-main', ...);
})();

// 拆成 3 条规则：rex-scene-1 / -2 / -3，各自
(function () { var REX = window.__REX__; var C = ..., esc = ...;
  REX.register('scene-cover', ...);
})();
```

**为什么不用「累加器 + eval 装配」**：那需要运行时 `eval`，平台 CSP 与净化器都可能拦，中途失败还会留下半截状态。现在这条路上**没有运行时组装**——三块各自是合法 IIFE，先后执行，`register` 天然幂等（`if (this.modules[n]) return;`）。

**三道安全网，缺一不可**：

1. 拆点必须落在 `^  REX.register(` 上；找不到就放弃自动拆分，退回硬报错；
2. 每块必须过 `new Function(code)` 语法检查，任一块不过就整块放弃；
3. 拆完再跑一遍点火重放，残留 `【rex-scene-1】` 这类未点火标记直接 ERROR。

**实测**：把 `scenes.js` 灌到 26369 字 → 自动拆成 3 块 → 9 条规则 / 92KB → `validate` 0 ERROR 0 WARN → `e2e` 34/34 全过。

**但不要主动走这条路。** 先拆功能模块（一个文件一个关注点），拆不动再让分块兜底。7 个模块正常总量 50–120KB，达不到需要拆的规模。CSS / JSON 模块不支持自动拆分——真超了请拆文件。

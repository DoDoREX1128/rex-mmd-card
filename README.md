**说清楚要什么，剩下的它做。**

## 这是什么

装进 AI 助手（WorkBuddy / Codex / Claude Code）的技能包，不是模板库。

**它做的**：把你脑子里的卡，变成能导入的文件——方案、界面、状态栏、人设、世界书、校验报告、整卡包。  
**它不做的**：替你想内容。题材、世界观、人物、视觉调性，方向得你给。

为什么值得装：MMD 卡的坑几乎都不报错。`chatVersion` 写错，规则照装但 SDK 全不存在；界面标记没接进 `beginning`，HTML 从未进入 DOM；`findRegex` 语法错，整条规则静默丢弃。打开控制台，一片干净。这类记录在 `references/errors/` 里有 30 条，每条带症状、根因、处置和证据等级。

## 装

### 一、让 Agent 自己装（最省事）

> 帮我安装这个skill并命名为Rex版MMD角色卡制作 <https://github.com/DoDoREX1128/rex-mmd-card>

把这句话丢给你正在用的助手。它会克隆仓库、放进对应的 skills 目录、确认能不能被加载。

**中文名在 WorkBuddy 下可用。** Codex / Claude Code 请把「并命名为…」半句删掉——这两个宿主按规范校验「目录名必须等于 SKILL.md 里的 `name`」，中文名会被静默跳过，正好是这类工具最擅长的那种失败。

### 二、命令行

```bash
git clone https://github.com/DoDoREX1128/rex-mmd-card.git
cd rex-mmd-card
node scripts/install.mjs --target workbuddy
```

| 参数          | 取值                               | 说明                             |
| ----------- | -------------------------------- | ------------------------------ |
| `--target`  | `workbuddy` / `codex` / `claude` | 装给哪个宿主，必填                      |
| `--scope`   | `user`（默认）/ `project`            | 装给当前用户，或装进某个项目                 |
| `--dir`     | 路径                               | `--scope project` 时的项目根，默认当前目录 |
| `--name`    | 目录名                              | 改显示名，如 `--name "Rex版MMD角色卡制作"` |
| `--force`   | —                                | 覆盖旧版（旧目录改名保留，不删除）              |
| `--dry-run` | —                                | 只打印目标路径，不写盘                    |

装完**重开一个会话**，技能列表才会刷新。

### 三、手动放目录

技能就是一个文件夹，`SKILL.md` 必须在目录根部。别用「下载 ZIP 解压」——多出来的一层 `rex-mmd-card-main/` 会让宿主扫不到。

| 宿主              | 用户级                                                        | 项目级                       |
| --------------- | ---------------------------------------------------------- | ------------------------- |
| **WorkBuddy**   | `~/.workbuddy/skills/rex-mmd-card/`                        | `<项目>/.workbuddy/skills/` |
| **Codex**       | `~/.agents/skills/rex-mmd-card/`<br />或 `~/.codex/skills/` | `<仓库>/.agents/skills/`    |
| **Claude Code** | `~/.claude/skills/rex-mmd-card/`                           | `<项目>/.claude/skills/`    |

Windows 下 `~` 是 `C:\Users\<用户名>`。**不想装也能跑**：`git clone` 之后 `node scripts/test.mjs`，60 项自测直接在本地验证。

## 用

打开对话，正常说话：

> 帮我做一张修仙题材的卡，要有状态栏和捏人，风格偏水墨。

> 复刻某张卡的手感，但世界观换成赛博朋克。

> 我这个卡导入后界面不出来，帮我看看。

### 它会先问你四件事

| 问什么       | 你在答什么                                                       |
| --------- | ----------------------------------------------------------- |
| **版本与路线** | 你用的是新版聊天页还是旧版？要保留原界面只换皮（A）、整页重做并保留原生功能（B），还是用官方 SDK 全屏接管（C） |
| **交付形态**  | 整卡 PNG / 整卡 JSON / 分离式（卡 + 正则 + 人设 + 世界书）                   |
| **托管档位**  | 你想自己管多少：全托管（只答定位，结果说话）/ 半托管（默认，只问关键分歧）/ 全精修（每一步都过你）         |
| **目标**    | 什么题材、给谁玩、想要什么调性                                             |

**这四项必须问，不能替你猜。** 三条路线能力完全不通用，选错不报错、功能全哑；交付形态决定你怎么发布；档位决定它多久来找你一次。答完这四项，它会写一段书面结论，你确认了才动工。

想省事就说「你看着办」，它按默认走；想掌控就每一处都指定。

### 六个阶段

| 阶段              | 做什么                 | 出口判据              |
| --------------- | ------------------- | ----------------- |
| **S0 定位**       | 版本 / 路线 / 形态 / 档位   | 你确认那段结论           |
| **S1 方案**       | 一页方案 + 首屏线框         | 过「评审 7 问」         |
| **S2 原型**       | 只做首屏与一次完整交互，假数据     | 你确认视觉方向           |
| **S3 模拟**       | 接骨架 + 协议 + mock SDK | 校验 0 error，关键路径可点 |
| **S4 真站**       | 浏览器内逐项取证            | 首屏/导航/面板/输入/窄屏均过  |
| **S5 实机（本人实操）** | 需本人真机导入测试并游玩        | 由本人实测             |

**不跳阶段，但可回退。** S3 发现方案有缺陷就退回 S1 改方案，不允许在代码里打补丁掩盖设计问题。唯一例外是单点改动——只改文案、换图、调间距，且不碰信息架构和协议时，直接改完跑校验。

中途改主意直接说：「状态栏去掉体力」「封面换成冷色调」「这个按钮点了没反应」。

## 三条路线

|               | **A · 旧版原生增强**   | **B · 旧版同层卡**                   | **C · 新版沙盒卡**             |
| ------------- | ---------------- | ------------------------------- | ------------------------- |
| `chatVersion` | `0` 或缺省          | `0` 或缺省                         | **`1`**                   |
| 导入顶层键         | 4 键              | 4 键                             | **恰好 6 键**                |
| 做法            | 换肤 + 自建场景层       | iframe 全屏接管 + 原生桥接              | 官方 SDK：CSS 变量 + 稳定钩子 + 舞台 |
| 能力上限          | 换肤、气泡增强、封面/捏人/百科 | A 全部 + 61 项原生动作（删消息/回溯/会话/人设等等） | 30 项 SDK、跨设备存档、全屏舞台       |
| 主要代价          | 跟随平台 class 改名    | 维护上百个选择器，改版风险最高                 | 受 SDK 边界限制，宿主面板改不动        |
| 适合            | 保留原生手感、体积敏感      | 必须重做信息架构且要原生动作                  | 长期维护、要跨设备存档               |
| **不适合**       | -                | 第一次做卡                           | -                         |

**三条路线不可混用。** 新版卡里写 `iframe`、旧版卡里调 `sdk.save`、同层卡用 6 键导入包——这三种写法都不报错，只会什么都不发生。

## 能做出来的

|               | 内容                                         |
| ------------- | ------------------------------------------ |
| **状态栏 / HUD** | 血量、体力、好感、时间、地点、Buff、任务…… 118 条现成字段可选，也能自定义 |
| **封面与捏人**     | 开局选性别、出身、天赋，选项直接写进角色数据                     |
| **世界书**       | 地点、组织、NPC，按需触发，不占上下文                       |
| **人设与文风**     | 按「笔记体」写，不写成 AI 腔                           |
| **成品形态**      | 整卡 PNG、整卡 JSON、分离式三种                       |

交付时附一张清单，逐项标 **已验证 / 未验证 / 风险**。没跑过的一律写 `NOT RUN`——它不会把「静态校验通过」写成「可以交付」。

**需要你亲手做的一步**：在创卡页第一次保存前，选择「使用新版」/「使用旧版」。漏掉它，卡会装上但界面不出来，且没有任何报错。

## 目录

```
Rex-MMD角色卡/
├── SKILL.md                 入口：版本分流、六态心流、门禁、硬约束
├── facts.json               平台事实唯一真源（限额/能力/事件/选择器/变量/层级/错误码）
├── README.md  LICENSE
├── references/              28 篇方法论，编号即类别
│   ├── 00 / 01              总览与阅读路径；心流与状态机
│   ├── 10 / 11              流程：三问与方案、一句话补全
│   ├── 20~25                平台：分流、新版事实、同层卡、事实表、旧版事实、SDK 速查
│   ├── 30~33                内容：状态与字段、世界书、人设与文风、存档与续档
│   ├── 40~47                界面：卡架构、基线、视觉、封面捏人、捏人协议、骨架皮肉、外链 CSP、宿主边界
│   ├── 50~55                验收：示例拆解、复刻、静态冒烟、真平台踩坑、真站测试、发布前检查
│   ├── fields/              字段库：118 条。fields.json 真源，index.md 生成
│   └── errors/              错题本：30 条。errors.json 真源，index.md 生成
├── examples/                三个可跑的最小示例
│   ├── 01-sandbox-hud/      最小可跑的沙盒卡（3 条规则）
│   ├── 02-samelayer/        旧版同层卡最小包（脚本生成）
│   └── 03-remix/            复刻对照：骨架不变、皮肉全换
├── assets/
│   ├── skeleton/            沙盒卡骨架（改内容，不改机制）
│   ├── samelayer/           同层卡最小骨架（host.js + frame.html）
│   └── skin/                tokens 模板与示例配色（原创性检查用）
└── scripts/                 22 个工具
```

三处值得单独说：

- **`facts.json`** 是平台事实的唯一来源，文档表由脚本生成，改了真源忘了文档，`--check` 会报。
- **字段库只增不删**——「为什么不用这个字段」本身是知识。
- **错题本必须可证伪**——判 `confirmed` 不许配猜测级证据；判 `false-positive` 必须写清真错因是什么。

## 不做的

- 酒馆（SillyTavern）和其他平台的角色卡
- 画立绘（Codex可选）。它给结构、占位、提示词，图你自己配
- 绕过平台审核、鉴权，或伪造平台数据
- 把本地测试结论说成线上结论
